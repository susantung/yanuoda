# HTML 原型页面样式清单 V3.4

> 本文档只维护页面样式、视觉状态和响应式验收，不重复业务规则。业务以《场景活动预约管理功能 PRD》为准；全局 Token、主题、字号和安全区以《预约小程序 Figma 与主题规范 V3.4》为准。

## 1. 维护规则

- 使用 A/C/V/O 页面编号与 PRD、HTML 页面清单和原型一一对应。
- 本文档只记录用户已确认的样式。未确认页面只标记状态，不预设视觉结论。
- 样式变更同步本文档和 HTML 原型；如影响字段、操作、状态或数据口径，再同步 PRD。
- 所有手机页检查 320、360、375、390、414px；核心信息不被图标、状态或官方胶囊遮挡。

## 3. A02 预约活动管理

- 默认为绿色主题，移动端单列卡片。
- 活动名称 15px，最多两行，超出省略；状态和操作不得遮挡名称。
- 无 LOGO 时使用主题色浅底和活动名首字，文字居中。
- 总参与、今日预约与操作区信息密度平衡；数字超过千位仍保持卡片稳定。
- 创建时间、创建人与其他辅助文字同层级，不加粗、不放大。
- 已确认的原型入口：`outputs/product-preview/scenic-reservation-admin/preview/index.html`。

## 4. O00 运营活动选择

- 页面默认高亮“已发布”标签，不在标签后显示数量；数量另作摘要显示。
- 卡片左侧显示 LOGO 或首字占位，中间显示活动信息，右上角显示状态，右侧使用轻量进入箭头。
- 状态不放在活动名后。活动名最多两行，长名称不得被右上角状态遮挡。
- 更新信息为辅助层级；总参与指标使用人物图标，今日预约使用日历图标。
- 总参与和今日预约之间不使用竖分隔线。两组指标使用固定组间距，不因上一个数字长度改变；同一列表内每张卡片使用同一规则。
- 样例覆盖总参与 `128600`、今日预约 `10000`、长活动名、有图和无图卡片。
- 360—414px 组间距为 16px；320px 为避免五位今日人数溢出，组间距缩小为 6px，但同屏所有卡片仍必须一致。

## 5. O01 活动运营首页

- 活动摘要和统计、操作分卡展示。
- 总参与和今日预约合并在一张统计卡中，左右两组通过留白区分，不使用竖线。
- 人物使用品牌色图标，日历使用橙色图标；数字单行展示，至少兼容六位数。
- “全部预约”“场次名单”“数据导出”为三张等宽等高的横向列表卡，纵向排列。
- 三个入口分别使用绿色单据、蓝色日历和橙色下载图标；说明保持单行，窄屏超长时省略。
- 页面不出现三点更多菜单、编辑配置、复制或删除的视觉入口。

## 6. C01 基础信息

- 管理端沿用现有管理小程序表单与卡片风格，不套用游客端预约卡片样式。
- 活动 LOGO 使用正方形上传区；封面图片使用横向上传区。LOGO 空态仅居中显示上传图标和上传文案，首字占位规则说明置于上传区外。
- 封面标签和封面副标题各占一行；字段清空后不得保留底色、胶囊或空白占位。
- 字段名使用 14px，必填/选填、字数和尺寸提示使用 12px；分组标题使用 16px。
- 底部主要操作按钮使用 14px；顶部步骤、游客端效果、上传/更换/删除和富文本工具使用 13px；状态提示使用 11—12px。
- 页头“编辑预约活动”使用 12px，活动名称使用 16px 中等字重。
- 富文本工具栏可横向滚动或自适应换行，320—414px 不截断核心操作。
- 详情图片缩略图不超过内容卡片宽度；大图在可视区域内等比展示，支持遮罩与关闭按钮退出，关闭后保留原滚动位置。
- 320—414px 下字段名、必填/选填、字数、尺寸提示和按钮层级清晰一致，不出现 9—10px 的核心操作文字。
- 配置页头的活动名称不得被保存状态或游客端效果按钮挤压；LOGO 空态图标、上传文案和外部说明保持正确对齐。

## 7. C03 项目配置

- 项目名称与简介在列表中保持稳定信息密度；名称、简介过长时按当前原型单行省略，不挤压状态与操作。
- 项目 LOGO 编辑区、预览、更换、删除及无图首字占位复用 C01 活动 LOGO 的视觉规则。
- 未上传图片时游客端使用纯文字项目样式且不保留图片空位；上传图片后使用图文项目样式。
- 文本框、下拉选择和图片上传保持统一字段标题、说明、44px 操作高度、圆角与聚焦状态。
- 分类名称下的项目文字不使用微型字号，与同页辅助正文层级一致。

## 8. C04 日期与场次

- 历史日期使用独立只读样式，与未选择日期有明确差异。
- 日期模式、日期选择、各日期场次分卡展示；场次条目保持紧凑，时间为首要视觉信息。
- 模板管理与“各日期场次”标题区域横向对齐，不显示数量角标。
- 场次项目和库存设置通过弹层按需展开，不在日期列表中铺开全部项目明细。

## 9. C05 展示设置

- 单条“选择规则”使用轻量提示条，不使用上下分割线，也不单独占用大说明卡。

## 10. 其他已有页面的样式来源

- C01—C07：当前已确认原型是页面特有样式基线；后续再变更时，按页面编号补入本文档，不回写 PRD 的业务章节。
- V01—V10：游客端现有原型和《预约小程序 Figma 与主题规范 V3.4》共同构成当前样式基线；分类标签单行横向滚动，点击热区不低于 44px。
- O02、O03、O04、O08 已完成逐页确认并作为定稿规则；O05—O07 仍待逐页确认。

## 11. O02 全部预约列表（已确认）

- 页面字体层级与 C01—C07 已确认管理端规范一致：模块标题 16px，卡片主信息 14—15px，字段值 13px，辅助标签、状态标签和紧凑操作文字统一为 12px；核心信息不使用低于 12px 的微型文字。
- 当前活动与今日预约人数在顶部摘要中分区展示，人数保持单行。
- 标签不显示数量；搜索、筛选入口和简要/详情切换保持同一操作行且小屏不互相遮挡。
- 筛选条件展开后单行横向滚动，整条区域（包括从日期、下拉控件区域起手）均支持手指滑动和电脑端横向拖动；短按仍正常打开控件，横向位移超过阈值后只执行滚动且不误触控件。每个条件保留完整标题和值。预约日期使用“指定单日／全部日期”选择控件；指定单日显示不低于 44px 高的手机日期控件，全部日期隐藏日期控件，未填写关键词时列表区显示查询引导空态。
- 详情卡片中“场次名称及时间”和“分类/项目”各压缩为一行，标签和值横向排列，超长值省略，不使用大块卡片和三行结构。
- 游客字段采用两列栅格；单选、多选、单行文本和多行文本占整行，多选及多行文本允许自然换行。
- 身份证号码保持单行展示，不出现末尾单个字符换行。
- “查看预约详情”与上方内容之间不额外增加重复分割线。
- 320px 下搜索、筛选、视图切换和排序仍可操作，卡片及字段不产生横向溢出。

## 12. O04 管理端预约详情（已确认）

- 字体层级沿用 O02：模块标题 16px，字段值及时间线标题 13px，字段名、辅助信息、状态、复制操作和时间线说明不低于 12px，底部操作按钮 14px。
- 预约号作为页面核心识别信息突出展示；活动名称、状态和复制预约号操作不得互相遮挡。
- 预约信息与游客填写资料使用统一详情行：左侧字段名 12px，右侧字段值 13px；长文本允许自然换行，不缩小字号解决拥挤。
- 详情行使用固定 92px 字段名列与自适应内容列。字段名约 7 个中文字符以内保持一行，超过后自然换行；字段值在 320—375px 页面中约 13—16 个中文字符后按可用宽度自然换行，不截断完整内容。
- 每条详情行最小高度 44px，字段名、字段值和复制操作均相对该行垂直居中；换行后整组文字仍与上下分隔线保持相等内边距，不能顶住横线。
- 操作记录的时间、来源和说明均保持 12px，不能使用 10px、11px 微型文字。
- 320—414px 下详情字段、长身份证号和多选长文本不产生横向溢出，底部操作栏不遮挡最后一条记录。
