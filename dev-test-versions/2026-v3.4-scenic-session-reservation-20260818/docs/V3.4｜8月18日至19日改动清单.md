# V3.4｜景区场次预约 8 月 18—19 日改动清单

> 用途：供产品、设计、开发、测试统一确认本轮最终改动。本文只描述当前 V3.4 应实现的最终逻辑，不保留已废弃的中间方案。

## 一、版本与交付结构

1. 版本统一调整为 **V3.4**。
2. 活动配置步骤统一为：
   - C01 基础信息
   - C02 必读须知
   - C03 项目配置
   - C04 日期与场次
   - C05 展示设置
   - C06 游客预约配置
   - C07 活动发布
3. 项目配置提前到日期与场次之前，C04 根据 C03 的项目模块状态加载项目关联和库存配置。
4. 管理端增加完整运营管理入口与 O00—O08 页面；活动上下架统一收口到 C07。
5. 最终交付目录只保留 V3.4，不再使用 V1 或临时补传包作为开发依据。

## 二、活动状态与发布逻辑

### 2.1 活动状态

活动只保留两种业务状态：

- **已上架**：游客端正式页面可进入，并继续按日期、场次、截止时间和库存判断能否预约。
- **已下架**：停止新预约；历史预约仍可查看、修改和取消；管理员可继续编辑并重新发布上架。

新建活动首次发布前按“已下架”处理。不设置活动草稿、暂停、恢复和结束状态。日期或场次暂停属于局部运营状态，不改变活动整体状态。

### 2.2 C07 操作

- 已上架：主操作为“发布更新”，同时提供“下架活动”。
- 已下架：提供“保存”和“发布上架”两个独立操作。
- 保存只更新待发布配置和游客端效果，不改变线上正式版本及活动状态。
- 发布上架、发布更新前执行完整发布检查；未通过时不发布，提示未通过数量并定位首个问题。
- 发布成功后，A02 活动列表的状态和所属标签立即同步。
- A02 已发布活动卡片可直接发起二次确认下架；发布、发布更新和重新上架仍统一进入 C07，运营首页不直接处理活动状态。

### 2.3 本轮缺陷修复

- 修复下架活动“发布上架”按钮因原生禁用导致点击无反应的问题。
- 按钮即使检查未通过也可点击查看失败原因，但不会执行发布。
- 修复活动管理“新建”因新活动尚无 ID、读取独立缓存时报错而无法进入配置页的问题；新活动进入配置时生成活动 ID，首次保存后进入“已下架”列表。

## 三、活动与项目数据关系

### 3.1 最终结构

- 一个活动可以配置多个项目。
- 一个项目只属于一个活动。
- 活动先配置开放日期，每个日期下配置场次。
- 场次可以不关联项目，也可以关联一个或多个总体启用项目。
- 场次不关联项目时，游客选择场次后直接填写资料，库存核算在场次维度。
- 场次关联项目时，游客按“日期 → 场次 → 分类（如启用）→ 项目”完成选择。

### 3.2 项目模块总开关

- 项目模块关闭：C04 不显示项目关联区域，游客端不展示项目模块，所有场次只使用场次库存。
- 项目模块开启：C04 可以给每个场次关联项目，并选择共用场次库存或分别设置项目名额。
- 活动不存在任何预约记录时，允许切换项目模块总开关。
- 活动一旦产生预约记录，总开关永久锁定，不能在启用和禁用之间切换。
- C03 页面需要直接说明：“活动产生预约后，项目模块状态将锁定，不能再切换。”

### 3.3 项目启用、禁用与删除

- 项目总体状态为“展示中/已隐藏”，列表直接启用或禁用。
- 总体禁用后，游客新预约不再看到该项目，历史预约保留项目快照，不受影响。
- 禁用项目时，从今天及以后尚未产生相关预约占用的场次关联中移除该项目；历史日期不改写。
- 共用库存场次移除项目后，场次库存不变。
- 单独项目名额场次移除项目后，删除该项目名额，场次总名额按剩余项目名额重新求和。
- 项目存在预约记录时不可删除；无预约时允许删除。
- 分类名称不可重复；分类下存在项目时不可删除。

## 四、C03 项目配置页面

1. 页面只负责：项目模块总开关、游客端模块名称、项目资料、项目排序、项目总体启用状态、分类和分类排序。
2. 本页不再配置具体日期、场次和库存。
3. 项目字段包括：名称、项目 LOGO、简介、所属分类。
4. 项目 LOGO 未上传时，使用“主题底色 + 项目名首字”的占位图；名称变化时首字同步变化。
5. 项目和分类均使用三横线拖动排序。
6. 项目列表优化长名称与简介展示，避免按钮、状态和内容因换行错位。
7. 项目分类关闭时，游客端项目直接平铺；开启时只展示实际存在且有展示中项目的分类，不生成“未分类”假数据。
8. 添加项目使用弹层；编辑项目复用相同结构并加载原数据。

## 五、C04 日期与场次页面

### 5.1 日期选择

- 第一期只实现“自选可约日期”。
- “每周规律循环”置灰并显示“敬请期待”，不提供功能。
- 月历支持上月、下月切换。
- 单点点击未选日期可加入，点击已选日期可移除；已有预约的受保护日期需要先处理预约。
- 支持“添加连续日期”和“删除连续日期”两个范围操作。
- 删除范围时，仅删除范围内无有效预约的已选日期；有预约日期保留并明确提示。
- 历史日期只供查看，不限制未来日期配置。
- 已有预约只代表日期受保护，只有本次操作实际影响该日期时才触发校验。

### 5.2 各日期场次列表

- 按月份展示已选日期摘要，支持前后月份切换。
- 每个日期显示：日期、场次数、配置状态、时间范围、预约摘要。
- 未配置场次显示“待配置”，不能保存成 0 场次的有效配置。
- 每日场次和游客端场次统一按开始时间升序。
- 仅配置开始时间时，摘要只显示开始时间，不显示残缺的“开始时间—”。
- “模板管理”与各日期场次标题横向对齐，不显示模板数量角标。

### 5.3 当天场次弹层

- 支持添加单个场次、批量添加场次、保存为模板、应用模板、复制当天配置到其他日期。
- 取消：撤销本次打开弹层后发生的全部调整，返回日期列表。
- 确认：当天至少保留 1 个场次；确认后仅形成当前步骤未保存修改，仍需点击 C04 底部保存。
- 新增、编辑弹层的时间使用移动端时间选择器，不要求手输时间数字。
- 场次名称选填，最多 10 个字；开始时间必填；结束时间选填。
- 无预约场次可修改时间、名称、库存、项目关联、库存模式并可删除。
- 有预约场次锁定时间、删除、关联项目集合和库存模式；允许在原库存模式下调整名额，但不得低于已预约实际参与人数。
- 修改时间导致排序变化时，场次唯一 ID 不变，历史预约和项目名额继续绑定原场次。

### 5.4 批量添加场次

- 输入开始时间、结束时间和场次间隔。
- 场次间隔按 5 分钟递增，最大 180 分钟。
- `(结束时间－开始时间) ÷ 间隔` 必须整除；不能整除时阻止生成并提示重新选择。
- 显示预计生成的场次数。
- 项目模块开启时，批量添加与单个添加采用相同的项目关联与库存模式，生成的所有场次共用本次设置。

## 六、场次与项目库存最终规则

### 6.1 未关联项目

- 场次库存支持“不限额”或“限额”。
- 限额时维护一份场次名额；预约按实际参与人数扣减。

### 6.2 已选项目共用场次库存

- “已选项目共用场次库存”放在关联项目区域顶部，默认勾选。
- 关联项目默认选中全部总体启用项目，列表只加载总体启用项目。
- 共用库存仍支持“不限额”和“限额”。
- 不限额时不进行库存拦截。
- 限额时维护一份场次名额，预约选择任一关联项目均扣减同一场次库存。
- 共用库存时不显示逐项目名额输入。

### 6.3 单独项目名额

- 取消勾选“已选项目共用场次库存”后，进入单独项目名额模式。
- 每个已选项目必须填写大于 0 的整数名额，不允许留空或不限额。
- 场次总名额由已选项目名额实时求和并明确展示，不允许手工输入场次总名额。
- 预约只扣减所选项目库存，不再额外扣减第二套场次库存。
- 场次已预约人数等于各关联项目已预约实际参与人数之和。
- 有预约后不能在共用库存和单独项目名额之间切换，也不能改变关联项目集合。
- 已预约样例数据必须前后一致，不能出现“场次已预约 12 人、项目均暂无预约”。

### 6.4 复制与模板

复制当天配置和场次模板均包含：

- 场次名称、开始/结束时间、排序；
- 场次不限额/限额及名额；
- 关联项目；
- 共用库存/单独项目名额模式；
- 单独项目名额明细。

不复制预约单、已预约人数、特殊提示日期参数和历史运营状态。复制完成后各目标日期独立维护。

## 七、C05 展示设置

1. 游客端固定选择顺序为：日期 → 场次 → 分类（如启用）→ 项目（如启用）。
2. 每次预约只能选择 1 个场次，该规则只读展示，不提供管理端配置。
3. 场次不存在“未开放”状态：未配置或不希望展示的场次不进入游客端；已有预约但需停止新预约时使用“暂停”。
4. 支持配置是否向游客展示剩余名额。
5. 支持配置当天结束场次是否隐藏；当天全部场次结束后可隐藏该日期。
6. 暂不展示已预约人员名单。

## 八、C06 游客预约配置

### 8.1 填写项

- 默认常用字段：姓名、手机号、身份证号。
- 自定义字段：单行文本、多行文本、数字、单选、多选、日期。
- 添加填写项统一使用弹层；字段列表支持三横线拖动排序。
- 姓名、手机号、身份证号类型固定，仅允许修改显示名称及其有效配置。
- 手机号支持填写时加载微信授权手机号，但管理端不展示“微信授权”配置项。
- 数字字段仅允许整数。
- 单选使用下拉框和纯文字选项；多选必填时默认至少选择 2 项。
- 日期字段支持“年月日”和“年月日 + 时间”。
- 多人/团队控件最少人数改为 1 人；添加该控件即按填写人数统计并扣库存，不添加时每笔预约固定统计 1 人。
- 所有游客填写项均允许删除；发布检查时必须至少保留 1 个填写项，否则阻止发布并定位到本页。
- 多人/团队控件在一个活动中最多保留 1 个；存在该控件即为多人统计模式，不存在即为单人统计模式。
- 游客填写页不展示“我已阅读并同意本活动预约规则”勾选项，提交预约不校验该项。
- 游客填写项的详细字段配置页仍需后续根据补充截图继续细化。

### 8.2 开放与截止

- 开放规则第一期固定为“立即开放”，不可修改。
- 预约截止支持：不限制、到场次开始时间截止、场次开始前 N 分钟截止。
- 默认“到场次开始时间截止”，不提供小时单位。

### 8.3 游客取消

- 是否允许游客取消默认开启。
- 游客取消截止支持：不限制、到场次开始时间截止、场次开始前 N 分钟截止。
- 达到取消截止时间后，游客预约详情不再显示取消入口。
- 管理员取消不受游客取消截止限制。
- 取消成功后按原库存模式返还场次库存或项目库存。

## 九、游客端与配置联动

0. HTML 原型在场次预约页之前增加“活动效果浏览”辅助页，用于集中查看全部已上架活动并逐个核对发布结果；该页只用于原型验收，本期真实游客端不开发。
1. 后台每个配置步骤点击保存后，更新“游客端效果”；未保存内容不进入预览。
2. 只有 C07 发布上架或发布更新后，配置才进入正式游客端。
3. 游客端效果只展示，不提交真实预约；正式游客端才写入预约数据。
4. 游客端日期、场次、项目、分类、库存、截止状态必须读取当前活动已保存配置，不能使用独立假数据。
5. 分类只展示实际配置且存在可展示项目的分类，不自动出现“未分类”。
6. 关联项目只展示该场次关联且总体启用的项目；长项目名称允许合理换行，不挤压勾选框或库存控件。
7. 活动下架后游客仍可查看历史预约，但不能新建预约。
8. 日期暂停时历史预约不变，该日期停止新预约；游客端显示暂停状态或不可预约状态。
9. 场次状态仅包括业务实际存在的状态，如剩余名额、已满员、已截止、暂停；不使用“未开放”。

## 十、运营管理页面

本轮将已有运营端原型与 PRD 合并，页面为：

- O00 运营活动选择
- O01 活动管理首页
- O02 预约订单列表
- O03 详情卡片字段设置
- O04 管理端预约详情
- O05 日期/场次名单
- O06 场次名单详情
- O07 数据导出
- O08 管理端修改与取消

主要规则：

- 从工作台“运营管理”独立入口进入。
- 订单搜索支持游客预约号、姓名、手机号。
- 订单状态第一期为已预约、已取消。
- 管理员可修改除日期、场次、分类、项目以外的游客资料；选错日期或场次需取消后重新预约。
- 修改实际参与人数时重新校验库存。
- 名单按预约日期、场次状态等筛选；无预约显示“暂无人选择”。
- 导出沿用竞品的导出类型和时间范围选择逻辑。
- 活动上下架不在运营首页操作，统一进入 C07。
