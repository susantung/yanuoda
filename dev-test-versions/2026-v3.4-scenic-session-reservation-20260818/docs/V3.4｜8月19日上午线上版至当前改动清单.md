# V3.4｜8 月 19 日上午线上版至当前改动清单

> 对比基准：2026-08-19 上午已上传至 GitHub Pages 的 V3.4 版本。本文只记录该线上版本之后发生的增量修改，不重复描述此前已经上传的日期、场次、项目库存等既有方案。

## 1. 新建活动初始化修复

- 修复新建活动错误继承示例活动全部配置的问题。
- 新活动只加载规定的初始默认项，不继承其他活动的名称、图片、详情、项目、分类、日期、场次、库存和发布数据。
- 新活动默认项目模块关闭，项目、分类、日期和场次为空；保留默认姓名、手机号、身份证号三个游客字段，不默认添加多人/团队字段。

## 2. C03 项目分类状态修正

- 分类增加独立的“启用中/已禁用”状态，并可在分类列表直接启用或禁用。
- 关闭项目分类展示功能时，分类数据仍保留；新增、编辑项目仍展示所属分类，但分类控件标识当前分类状态。
- 禁用分类下的项目不进入游客端，也不进入 C04 新的场次关联项目列表。
- 分类全部禁用时，不生成“未分类”假分类，游客端不展示项目分类内容。
- 禁用分类前校验未来有预约的关联场次；存在受影响预约时禁止禁用。
- 分类名称修改时，同步更新所属项目；分类名称继续禁止重复。

## 3. C03/C04 项目读取一致性

- C04 关联项目统一读取“项目总体启用且所属分类有效”的项目。
- 项目保存、分类状态变化后，管理端关联项目、游客端效果和正式发布快照使用同一数据来源。
- 修复项目和活动图片在主原型、交付包相对目录不同导致的资源路径失效问题。
- 恢复历史带图片活动及项目图片，不再因活动切换或目录变化丢失。

## 4. C05 游客端展示联动修正

- “向游客展示剩余名额”关闭时，日期和场次统一显示“可预约”，不再残留剩余人数。
- 日期状态继续按已截止、暂停预约、已满额、不限额及剩余名额计算，不新增“未开放”状态。

## 5. C06 游客填写项规则调整

- 所有游客填写项均允许删除，包括姓名、手机号、身份证号和多人/团队字段。
- 发布检查只保留一条底线：至少存在 1 个游客填写项；全部删除后可以暂存，但不能发布。
- 存在多人/团队字段即为多人统计模式；不存在则为单人统计模式。
- 游客填写预约信息页移除“我已阅读并同意本活动预约规则”勾选项，提交预约不再校验该项。

## 6. 发布数据按活动独立联动

- 新增按活动 ID 保存的正式发布快照目录，多个活动不再共用一份正式游客端数据。
- 保存配置只更新当前活动的待发布配置和游客端效果。
- 发布上架或发布更新后，才更新当前活动的正式快照及活动浏览数据。
- 下架或删除活动时，同步移除该活动的正式发布快照，不影响其他活动。

## 7. 原型辅助“活动效果浏览”页

- 在 HTML 游客端原型的场次预约页之前新增独立的“活动效果浏览”页。
- 页面集中展示所有已上架活动，点击活动进入该活动对应的场次预约效果。
- 页面只读取成功发布的活动快照；后台仅保存但未发布时不更新。
- 该页面仅用于产品、业务和开发核对多活动发布效果，本期真实游客端不开发。

## 8. A02 活动下架

- 已发布活动卡片新增“下架”入口。
- 下架前二次确认：下架后停止新预约；已有预约仍可查看、修改和取消；活动之后允许重新发布。
- 下架成功后活动进入“已下架”标签，清除正式发布快照，但保留后台配置和历史预约。

## 9. A02 活动删除

- 删除入口只在已下架活动卡片展示。
- 只有已下架且从未产生任何预约数据的活动允许物理删除。
- 有效预约和已取消预约都属于历史预约数据；只要存在任一预约单，活动永久禁止物理删除，只能保持下架。
- 无预约的已下架活动删除前二次确认，确认后删除活动、待发布配置和正式快照。
- 原型增加“测试活动｜已下架且无预约可删除”样例，用于验证删除成功链路。
