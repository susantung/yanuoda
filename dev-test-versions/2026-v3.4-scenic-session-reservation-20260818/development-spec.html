1. 文档维护规则

1.1 内容准入

正式 PRD 采用两级确认状态：

  1. 业务规则已确认：字段、状态、计算方式、操作边界和跨页面影响已经确认，可以进入本 PRD 的业务规则章节。
  2. 页面已定稿：页面结构、展示字段、交互、状态样例和多尺寸原型均已逐页确认，可以进入本 PRD 的页面详细设计章节并作为开发依据。

尚未确认的产品建议、竞品能力和视觉尝试不写成正式实施规则。确需保留的缺口，只记录“待确认事项名称和影响范围”，不预设处理方案。

1.2 信息优先级

内容冲突时，按照以下顺序处理：

  1. 用户最新明确确认的结论。
  2. 已完成逐页复核的页面记录。
  3. 《景区场次预约方案确认清单》中标记为“已确认”的业务规则。
  4. HTML 原型当前实现。
  5. 竞品截图和分析，仅作为参考证据，不直接成为本产品规则。

1.3 单页更新流程

每个页面依次完成：

  1. 确认页面目标、入口和返回路径。
  2. 确认页面模块顺序、字段、状态、操作和默认值。
  3. 确认与其他页面、库存、统计及历史数据的关系。
  4. 制作或调整可交互 HTML 原型。
  5. 检查 320、360、375、390、414px 五档手机宽度。
  6. 用户明确确认页面后，将该页写入本 PRD，并更新页面关系矩阵和验收标准。

2. 项目背景

2.1 业务背景

景区部分游玩项目需要控制每日接待日期、具体场次、线路或项目名额。游客通常已经通过景区线下窗口、官网小程序或 OTA 完成购票，但购票后仍需要另外选择游玩日期和时间段。

现行业务存在以下入口：

  • 线下购票后扫描二维码进入预约页。
  • 官网小程序购票后，从首页再次进入外部预约页面。
  • 购票成功短信携带预约链接。
  • 携程、美团等 OTA 下单后，通过短信进入预约页。

当前流程中，购票和预约彼此割裂，景区还需要依靠外部竞品完成场次预约。为了形成景区自有、可配置、可持续扩展的 SaaS 能力，需要建设一套独立的场次预约功能，并在后续逐步关联官网订单和 OTA 订单。

2.2 产品定位

本产品是一套面向多景区 SaaS 场景的“预约活动”配置与运营能力。

  • 景区管理员在当前景区账号下创建多套预约活动。
  • 管理员配置日期、场次、分类、项目、库存、游客填写项及预约规则。
  • 游客按照配置完成日期、场次、项目和资料填写并获得预约资格。
  • 管理员查看预约订单、场次名单并执行资料修改、取消和导出。
  • 同一套功能可在不同景区主题下运行，业务结构保持一致。

2.3 竞品参考原则

第一版参考“快预约”小程序的成熟配置逻辑，重点吸收日期场次、项目库存、项目启停、动态填写项和名单管理等通用能力；不复制竞品品牌视觉，也不照搬与本期无关的支付、审核、核销、候补或营销能力。

3. 产品目标

3.1 第一期目标

  1. 支持景区独立创建、发布和维护多套预约活动。
  2. 支持游客按照“日期 → 场次 → 分类（启用时）→ 项目（配置时）”完成预约。
  3. 支持场次库存与项目库存按照实际参与人数准确扣减、追加和返还。
  4. 支持单人预约和多人/团队预约两种人数统计模式。
  5. 支持游客查看、修改和取消本人预约。
  6. 支持管理员查看预约订单、日期/场次名单和导出数据。
  7. 建立可适配不同景区主题的小程序页面与组件规范。

3.2 第一期业务边界

第一期采用“独立预约模式”：

  • 游客原则上已经购票，但预约系统不读取、不校验、不绑定门票订单。
  • 任何人均可进入预约页面并填写资料预约。
  • 预约成功只表示获得预约资格，不代表已经购买门票。
  • 可从官网小程序、线下二维码和短信链接进入。

3.3 第一期不建设

  • 购票订单校验和订单绑定。
  • 购票与预约同一流程。
  • OTA 订单及场次接口。
  • 预约审核、候补、排队、黑白名单和爽约限制。
  • 核销码、二维码核销、扫码核销和核销状态。
  • 微信订阅消息、短信通知和管理员通知。
  • 独立访问详情、访客明细、转化率和高级统计报表。
  • 周期内预约次数限制和身份证号去重。
  • 管理员代客新增预约。

3.4 后续演进方向

  • 官网小程序购票后直接进入预约并带入订单。
  • 官网购票和预约在同一流程完成。
  • 对接携程、美团等 OTA 订单及场次。
  • 根据订单票型自动匹配项目/线路。
  • 增加通知、核销、限制、审核、候补和高级统计能力。

4. 用户、入口与景区上下文

4.1 管理员

  • 管理员扫码进入全域景区管理后台。
  • 先选择要管理的景区账号，再进入该景区工作台。
  • 进入工作台后景区上下文已经确定，预约活动自动归属当前景区，不在预约活动内重复选择景区。

4.2 游客

  • 游客通过当前景区小程序入口、二维码或短信链接进入预约活动。
  • “我的预约”按照当前微信小程序用户身份查询其在当前景区提交的预约记录。
  • 手机号是预约资料，不作为进入“我的预约”的登录凭据。

4.3 工作台入口

工作台新增“活动/场次预约管理”分组，第一期包含：

  • 活动管理。
  • 运营管理。
  • 特殊提示日期管理。

“特殊提示日期管理”当前只确认入口，内页权限、批量日期设置和历史日期规则待业务后续确认。

5. 核心概念与数据对象

5.1 预约活动

景区可同时维护多套预约活动。每套活动独立保存基础资料、日期、场次、项目、库存、游客表单、须知及预约记录。

活动只有两种状态：

  • 已发布：对游客开放，具体是否可预约继续按照日期、场次、截止时间和库存判断。
  • 已下架：不接受新预约；历史预约仍可查看、修改和取消，管理员可编辑后重新发布。

活动层级不设置草稿、暂停、恢复和结束状态。新建活动首次发布前按“已下架”管理。

C03 的“暂停某日预约”属于日期级运营状态，不是活动状态：活动仍保持“已发布”，仅暂停指定日期的新预约；其他开放日期继续正常预约，历史预约保持可查看、修改和取消。

5.2 日期与场次

  • 日期是游客预约游玩日期。
  • 场次是日期下独立的可预约时间段。
  • 每笔预约必须且只能选择一个日期和一个场次。
  • 场次名称、结束时间选填，开始时间必填。
  • 场次可以不限名额或限制人数。

5.3 分类与项目

  • 一个活动可配置多个项目，一个项目只能归属于一个活动。
  • 项目模块关闭时，场次不关联项目，游客选择场次后直接填写资料，库存只在场次维度核算。
  • 项目模块开启时，每个场次可不关联项目，也可关联一个或多个总体启用项目；未关联项目的场次仍只核算场次库存。
  • 场次关联项目后，每笔预约必须且只能选择一个该场次可预约的项目。
  • 分类是项目的可选分组能力；不启用分类时直接展示项目。
  • 项目可代表线路、体验项目或未来对应的票型。

5.4 预约单与实际参与人数

  • 一次提交产生一张预约单。
  • 单人模式下一张有效预约单固定统计 1 人。
  • 多人/团队模式下，游客填写的团队人数就是实际参与人数。
  • 联系人和实际参与人是两个概念，联系人不额外计入人数。
  • 场次库存、项目库存和参与人数统计均使用实际参与人数。

5.5 游客预约号

  • 系统内部生成全局唯一 ID，用于数据关联和技术排查，不向游客展示。
  • 另生成游客预约号，用于游客现场报号和管理员查询。
  • 游客预约号按照“预约活动＋预约游玩日期”独立递增，每个日期从 001 开始。
  • 同日不同场次共用序列；次日重新从 001 开始。
  • 取消后号码不回收；修改资料和人数不改变号码。

5.6 配置与预约快照

预约提交时保存以下快照：

  • 活动、日期、场次、分类和项目信息；未选择项目时项目快照为空。
  • 场次关联项目集合及该场次使用的项目库存模式。
  • 游客表单结构、字段名称、顺序和填写数据。
  • 必读须知内容及确认时间。
  • 实际参与人数和库存占用。

后续项目禁用、字段名称或顺序调整、须知更新均不改变历史预约快照。

5.7 日期、场次、复制与模板的数据关系

日期、场次、复制和模板必须按照“目标日期独立持有场次数据”的原则设计，不能把复制关系做成运行时依赖。

日期数据

每个活动的每个开放日期保存一条独立日期记录，至少包含：

  • 活动 ID。
  • 预约游玩日期。
  • 日期是否开放、是否暂停新预约。
  • 当前场次数。
  • 当前有效预约单数和实际参与人数汇总。
  • 配置版本、最后更新人和最后更新时间。

日期列表中的场次数、时间范围、名额和预约人数均由该日期当前拥有的场次记录实时汇总，不保存“复制自某日”或“模板某某”作为业务展示状态。

场次数据

每个场次必须归属于一个具体活动日期，至少包含：

  • 场次 ID、活动日期 ID。
  • 场次名称，选填，最多 10 个字。
  • 开始时间，必填。
  • 结束时间，选填。
  • 名额模式：不限额或限额。
  • 限额人数；不限额时为空。
  • 当前有效预约实际参与人数。
  • 关联项目 ID 集合；未关联项目时为空。
  • 项目库存模式：共用场次库存或单独项目名额；未关联项目时为空。
  • 单独项目名额明细；仅在单独项目名额模式下保存。
  • 排序值、有效状态、创建人、更新人和时间。

预约单通过场次 ID 占用库存。已有有效预约的场次保留原场次 ID，禁止通过复制、模板或重新生成方式覆盖。

复制日期场次

复制只是一次性批量创建或替换操作：

  1. 管理员选择一个来源日期和目标范围。
  2. 系统读取来源日期当前全部场次的名称、开始时间、结束时间、名额模式、名额数量、排序、关联项目、项目库存模式和单独项目名额。
  3. 对允许覆盖的每个目标日期创建全新的场次记录和全新的场次 ID；不复制预约人数、预约单或特殊提示日期参数。
  4. 目标日期保存后独立维护，后续修改来源日期不会同步修改目标日期。
  5. 目标日期只要存在任一有效预约场次，就整日跳过，不执行整体覆盖；结果反馈成功日期和跳过日期。

复制完成后，日期列表只显示目标日期当前的“已配置”或“已有预约”状态，不长期显示“复制自 8/22”。如需追溯，在内部配置操作日志中记录来源日期、目标范围、操作人、操作时间和结果，不作为普通管理页面字段。

场次模板

场次模板是独立于开放日期的可复用配置对象，包含模板名称和一组场次明细。模板明细保存名称、开始时间、结束时间、名额模式、名额数量、排序、关联项目、项目库存模式和单独项目名额，不保存预约数据。

  • “保存为模板”是把某日当前场次结构复制为一份模板快照。
  • “应用模板”是把模板明细复制为目标日期自己的新场次记录，不建立模板与日期的持续关联。
  • 修改或删除模板不影响已经应用该模板的日期。
  • 已应用日期后续单独修改，不反向更新模板。
  • 日期列表不显示“模板·溪降每日 7 场”；模板来源只进入内部操作日志。
  • 目标日期存在任一有效预约场次时，不允许整体应用模板覆盖。

配置操作日志

复制和模板应用至少记录：活动 ID、操作类型、来源日期或模板 ID、目标日期范围、成功日期、跳过日期及原因、操作人、操作时间。操作日志用于技术追溯和异常排查，不参与游客端展示、库存计算或日期配置继承。

8. 通用业务规则

8.1 日期与场次模式

第一期支持：

  • 自选可约日期：逐日点选不连续日期，或通过开始日期和截止日期批量选择连续范围。
  • “每周规律循环-敬请期待”仅作为置灰占位展示，不可选择，不提供生效范围、开放星期、特殊开放日或特殊关闭日功能。

日期模式、日期选择和逐日场次统一放在 C04“日期与场次”页面，不拆成多个配置步骤。项目主数据先在 C03 配置，C04 再按日期和场次加载项目。

调整自选日期时，不以“活动是否曾产生预约”作为整页锁定条件。系统只校验从当天开始实际会被移除或关闭的日期：

  • 历史日期只读保留，不参与限制。
  • 未受本次操作影响的未来日期不参与限制。
  • 受影响日期没有有效预约时允许操作。
  • 受影响日期存在有效预约时只锁定该日期；管理员必须先取消该日期全部有效预约，才能移除或被新模式覆盖。
  • 日期已有预约但本次没有选择修改该日期时，不阻断其他日期调整。

每个开放日期独立保存自己的场次。复制日期场次和应用模板只用于快速生成目标日期的独立场次数据，不建立来源继承关系。

8.2 场次名额

  • 每个场次选择“不限名额”或“限制人数”。
  • 不限名额时不执行场次库存拦截。
  • 限制人数时必须配置名额上限。
  • 已有预约后，时间不可修改、场次不可删除。
  • 名额可增加；减少后不得低于当前已预约实际参与人数。
  • 取消全部预约后，才允许修改时间或删除场次。

8.3 场次与项目库存

  • 库存配置属于具体日期下的具体场次。场次未关联项目时，只配置和核算场次库存，游客端不展示项目选择。
  • 场次关联一个或多个项目时，由该场次固定选择一种项目库存模式：
    • 共用场次库存：关联项目共用该场次的同一库存池。该库存仍可选择“不限额”或“限额”；不限额时不执行库存拦截，限额时维护一份场次名额。预约选择任一项目都按实际参与人数扣减同一场次库存，不建立独立项目库存。
    • 单独项目名额：取消勾选“已选项目共用场次库存”后，每个关联项目必须配置大于 0 的有限名额并独立扣减；不允许留空或设置不限额。场次总名额由项目名额自动求和，不允许手工填写。
  • 单独项目名额模式下，预约提交只扣减所选项目库存；场次已预约人数和剩余量由关联项目实时汇总，不再额外扣减第二套场次库存。
  • 已有预约的场次锁定项目关联集合和项目库存模式；管理员只能调整原模式下的名额数值，不能在共用场次库存与单独项目名额之间切换。
  • 有限名额不得低于对应库存池当前有效预约的实际参与人数。修改参与人数时按原库存模式重新校验，取消后返还原库存池。

8.4 项目启用与禁用

  • 项目模块总开关只允许在活动不存在任何预约记录时切换。
  • 活动产生任意预约记录后，总开关锁定为当前状态，不允许从启用改为禁用，也不允许从禁用改为启用。
  • 项目总体启用时进入游客端新预约项目列表；总体禁用时对新预约隐藏并不可选择。
  • 禁用只影响后续新预约，历史预约继续有效，并继续占用原场次及项目名额。若项目仍被今天及以后有预约场次关联，则禁止禁用。
  • 禁用无未来预约占用的项目时，系统从今天及以后场次中移除该项目关联。共用场次库存的场次名额不变；单独项目名额的场次删除该项目名额，并按剩余项目名额重新计算场次总名额。历史日期不改写。
  • 有历史预约的项目不可物理删除；没有历史预约时允许删除。
  • 分类本身具有启用、禁用状态。禁用分类时分类数据及其项目归属关系保持不变，但该分类下所有项目均不进入后续场次关联和游客端新预约展示。
  • 分类下项目仍被今天及以后有预约场次关联时，禁止禁用该分类。不存在未来预约占用时，禁用分类按照本节项目禁用规则清理未来场次关联及对应独立项目名额；历史日期和历史预约不改写。
  • 重新启用分类后，分类下总体启用项目恢复为可关联项目，但不会自动加入既有场次，仍需管理员在目标场次重新选择。

8.5 单人和多人/团队

单人模式：

  • 未配置多人/团队字段。
  • 一张有效预约固定统计并扣减 1 人。
  • 游客端不显示人数加减控件。

多人/团队模式：

  • 一个活动最多配置一个多人/团队字段。
  • 字段显示名称由管理员自定义。
  • 最少人数和默认人数均为 1，最多人数由管理员配置。
  • 游客填写几人，即统计并扣减几人。
  • 第一期不采集每位同行人的独立资料。

8.6 提交与并发

  • 游客填写过程中不提前锁定库存。
  • 点击提交后，由服务端重新校验活动状态、开放截止、场次库存、项目库存和表单数据。
  • 预约创建、场次扣减和项目扣减作为一个事务处理。
  • 每次提交携带唯一请求标识，防止连续点击和网络重试产生重复预约。
  • 无法判断原请求结果时，先查询原请求，不允许直接再次提交。

8.7 修改

  • 游客和管理员均可修改普通填写资料及多人模式的实际参与人数。
  • 日期、场次、分类和项目不可修改，选错时需取消后重新预约。
  • 修改不设置截止时间，场次开始前后均允许。
  • 减少人数时返还差额库存。
  • 增加人数时校验并追加扣减差额库存。
  • 修改和库存变化作为一个事务，失败时保持原资料、人数和库存占用不变。

8.8 取消

  • 管理端可配置是否允许游客取消，默认开启。
  • 游客取消截止支持“不限制”“到场次开始时间截止”或“场次开始前 N 分钟截止”。选择“不限制”时，只要预约仍为有效状态，游客均可取消。
  • 游客取消原因选填；管理员取消原因必填。
  • 管理员不受游客取消截止时间限制。
  • 取消状态和库存返还作为一个事务，同一预约只能成功取消一次。
  • 取消不可撤销，需要参与时重新预约。

8.9 历史数据保护

  • 已有预约的日期不可直接移除。
  • 已有预约的场次不可删除或修改时间。
  • 已有预约的项目不可删除，但可隐藏。
  • 游客字段调整后，历史预约始终读取提交时的字段快照。
  • 活动下架不删除历史预约。
  • 预约详情和导出使用提交时快照。

9.5 C03 项目配置

页面目标：在日期和场次之前完成项目模块启停、项目资料、项目与分类排序及项目总体启用状态配置。本页不配置具体库存。

9.5.1 数据关系

  • 一个活动可关联多个项目；一个项目只归属于一个活动，即活动与项目为一对多。
  • 活动统一提供预约日期与场次，项目不重复创建日期和场次。
  • C03 只建立项目主数据，不展示脱离日期和场次的库存或已占用数字；项目关联和库存模式在 C04 的具体场次中配置。
  • 项目总体启用表示该项目可以被后续场次关联；总体禁用的项目不进入新的场次关联和新预约。
  • 项目预留未来票型关联标识。后续接入门票时，一个项目对应一个票型，票型售卖日期可扩展为预约日期来源；第一期无票预约不展示票型关联字段。
  • 场次未关联项目时，预约单的项目 ID 为空；场次关联项目时，预约单保存游客选择的项目 ID。

9.5.2 项目模块总开关

  • 总开关关闭时，C04 不加载项目关联配置，游客端不展示项目模块，所有场次只使用场次库存。
  • 总开关开启时，C04 可为每个场次关联总体启用项目，并配置共用场次库存或单独项目名额。
  • 总开关只在活动没有任何预约记录时可切换。活动产生任意预约记录后，开关置灰并保持当前状态。
  • 开启状态下没有总体启用项目时不得发布，并提示先新增或启用项目。
  • 页面在开关旁直接说明：“活动产生预约后，项目模块状态将锁定，不能再切换。”锁定后说明：“当前活动已有预约，项目模块状态不可修改。”

9.5.3 项目列表与状态

  • 列表展示项目名称、图片或无图占位、项目简介及状态。名称下方只显示项目简介，不混入分类、库存或已预约人数。
  • 项目简介最多 60 字；未填写时展示未填写状态。项目名称和简介的列表截断规则见页面样式清单 C03。
  • 总体状态只有“总体启用”和“总体禁用”：总体启用的项目才进入 C04 场次项目列表；总体禁用后不再进入新场次配置，只影响后续新预约。
  • 项目启用/禁用直接在列表操作；项目编辑弹层不重复展示启用开关。
  • 项目列表使用三横线拖动手柄排序，支持手机手指和电脑鼠标拖动；排序结果决定游客端项目展示顺序。
  • 未上传项目 LOGO 时，管理端列表使用主题色底＋项目名称首字作为占位；项目名称修改并保存后，占位首字同步更新。
  • 项目有预约记录后不可物理删除，可继续修改资料；项目启用、禁用必须遵守 8.4 的未来场次关联与预约限制。禁用不影响历史预约，历史预约继续占用原项目库存。
  • 没有预约记录的项目允许删除，删除前二次确认。
  • 项目模块总开关位于 C03 顶部，并按照 9.5.2 的活动预约数据条件控制是否可操作。

9.5.4 新增与编辑项目

  • 新增使用底部弹层，表单默认不加载已有项目数据；编辑使用相同弹层并加载当前项目数据。
  • 项目名称必填，最多 30 字；项目 LOGO 和项目简介选填，项目简介最多 60 字。新增、编辑项目时始终展示所属分类字段；分类功能关闭时字段置灰并标注“分类功能已关闭”。
  • 所属分类下拉框展示全部分类及其启用、禁用状态。启用项目分类时所属分类必填，新建项目只能选择启用中的分类；编辑原有项目时可看到其已禁用分类，并可移动到其他启用中的分类。
  • 项目 LOGO 建议尺寸为 400×400px；编辑弹层提供预览、更换和删除。
  • 未上传图片时游客端不展示图片字段；配置图片和简介后向游客端下发对应内容。
  • 项目编辑弹层只维护名称、所属分类、图片和简介，不配置启停和库存。
  • 图片上传通过明确的上传操作完成，不直接暴露底层文件路径。

9.5.5 分类

  • 分类为可选能力。关闭分类功能时，所属分类数据和项目归属关系保持不变，游客端不展示分类标签，启用中的项目直接平铺；重新开启后恢复原分类结构。启用分类功能时，游客先选择启用中的分类，再选择项目。
  • 支持分类新增、编辑、删除和排序；分类使用三横线拖动手柄排序，排序结果决定游客端分类展示顺序。新增或编辑时分类名称不得与其他分类重名，重名则阻止保存并提示更换。
  • 只有分类下项目数为 0 时才允许删除。分类下仍有项目时阻止删除，并提示先将项目移动到其他分类。
  • 分类列表始终展示全部分类，并明确标识“启用中”或“已禁用”。禁用分类不删除分类，也不改变分类下项目归属；该分类下全部项目不进入游客端展示。
  • 启用项目分类后，每个项目必须归入一个已建立分类，游客端不生成“未分类”标签。
  • 游客端只展示启用中，且在当前日期和场次下至少存在一个可预约项目的分类；全部分类禁用时不展示项目模块。

9.5.6 与日期、场次的关系

  • C03 不再提供“项目与场次库存”入口，也不选择共用或独立库存模式。
  • 项目模块关闭时，C04 的单个新增、批量新增和场次名额弹层都不展示项目区域。
  • 项目模块开启时，C04 的单个新增、批量新增和场次编辑均加载总体启用项目，管理员先选择本场次关联项目；未关联项目时仍只使用场次库存。
  • 场次项目配置大框顶部先显示“已选项目共用场次库存”，默认勾选；其下再显示关联项目。共用时库存方式可选“不限额”或“限额”，限额时只维护一份场次名额。取消勾选后展开项目名额输入，每个已选项目必须填写大于 0 的有限名额，并实时显示“场次总名额 X 名”和未填写项目数；场次总名额随项目名额输入自动求和。
  • 已有预约的场次锁定关联项目集合和项目库存模式。共用模式不能改为单独，单独模式不能改为共用；原模式下的名额仍可调整，但不得低于对应已预约实际参与人数。
  • 项目列表只加载总体启用项目，新建场次默认全选。总体禁用项目时，按 8.4 规则清理未来无预约场次关联及对应项目名额。
  • 第一期不在 C04 顶部提供“批量项目名额”入口，避免与逐日场次、场次模板和复制规则产生多套入口。
  • 场次以唯一场次 ID 关联单独项目名额。修改场次时间并重新排序时，项目名额设置仍跟随原场次，不得串到其他场次。
  • 共用模式的预约扣减场次库存；单独模式的预约只扣减所选项目库存。修改参与人数时按原模式重新校验，取消后返还原库存池。

页面关系：C03 决定 C04 可加载的项目集合；C04 决定 V04 当前日期与场次实际展示的项目及库存。保存对应步骤后更新后台游客端效果，最终发布后更新正式游客端。

数据联动：C03 新增并启用项目后，保存即写入待发布配置；刷新后台仍保留。C04 关联项目只读取该活动当前总体启用且分类有效的项目，并按项目 ID 建立场次关联。新项目不会自动加入已有场次，管理员须在目标场次中勾选并保存；未关联当前场次的项目不在该场次游客端显示。C04 保存后，游客端效果优先定位到本次确认的日期和场次并读取待发布配置；C07 发布或发布更新后，正式游客端读取同一结构的发布版本。总体禁用项目不进入新的关联列表。

页面状态：页面已确认并同步 HTML；具体场次项目关联与库存模式在 C04 继续复核。

9.6 C04 日期与场次

9.6.1 页面目标与入口

本页在 C03 项目配置之后完成自选开放日期、逐日场次、场次名额及可选的单独项目名额、日期复制和场次模板配置。管理员从 C03 点击下一步进入，也可从顶部步骤导航进入。

页面底部沿用统一的“上一步 / 保存 / 下一步”。本页所有调整只有点击“保存”后才进入待发布配置并同步游客端预览；最终发布前不更新正式游客端。

9.6.2 页面结构与显示元素

页面自上而下包含：

  1. 配置页头：活动名称、保存状态、游客端效果入口。
  2. 配置步骤导航：C01—C07，当前 C04 高亮。
  3. 日期模式卡片：自选可约日期默认选中；“每周规律循环-敬请期待”置灰展示且不可选择。
  4. 选择可约日期卡片：月份切换、月历、连续日期添加/删除和日期图例。
  5. 各日期场次卡片：月份切换、模板管理、当月已选日期摘要列表。
  6. 当天场次配置弹层：日期概要、按开始时间升序的场次列表、各场次项目与名额、添加场次、模板、复制、取消和确认。

9.6.3 日期模式

  • 默认选择“自选可约日期”。
  • 自选模式支持月历单点选择不连续日期，以及按开始、截止日期批量处理连续范围。
  • “每周规律循环-敬请期待”使用完整禁用态展示，不可点击、不可通过键盘或程序切换，不产生任何配置数据。
  • 页面不展示模式调整影响说明，也不展示循环规则配置区域。
  • 历史日期只读保留，不参与删除限制。
  • 有预约但未受本次操作影响的日期不阻断其他日期调整。
  • 实际受影响日期存在有效预约时，该日期保留并提示先处理预约；其他可变更日期继续处理。

9.6.4 自选日期月历

月历显示：月份、星期、日期、未选择、已选择、历史日期、已有预约四类状态。“未选择”只表示该日期尚未加入活动排期，不是游客端场次状态。

  • 点击未选择的未来日期：立即变为已选择状态并加入活动排期。
  • 再次点击已开放且无预约的未来日期：从开放日期中移除。
  • 点击已有有效预约的日期：不直接删除，打开日期预约管理弹层。
  • 历史日期只读且不可操作；其视觉状态见页面样式清单 C04。
  • 已有预约日期使用完整色块提示，不以难辨认的小边框表达。
  • 单点选择不逐次弹 Toast，月历不因选择重新定位到页面顶部。
  • 月历支持“上月 / 下月”连续切换；切换月份只改变当前查看月份，不清空已选日期、不改变其他月份配置，也不触发页面回到顶部。

月历下只保留两个范围操作：

  • 添加连续日期：使用手机底部日期选择器选择开始、截止日期，包含首尾两天；确认后一次性加入并立即回显。
  • 删除连续日期：选择开始、截止日期后，删除范围内已开放且无有效预约的日期；有有效预约的日期自动保留，并在确认结果中列明。

开放日期允许不连续。游客端日期区不额外展示连续范围或可预约日期数量说明，具体可约日期直接以日期卡片为准。

9.6.5 各日期场次摘要列表

列表按月份查看，不将数月或一年的全部场次明细纵向展开。月份可前后切换，每行代表一个已开放日期。

每个日期行展示：

  • 日期和星期。
  • 当前状态：待配置、已配置、已有预约；暂停新预约时增加暂停状态。
  • 场次数。
  • 时间摘要。
  • 当日场次总名额。
  • 有预约时展示有效预约单数或实际参与人数摘要。
  • 进入当天场次配置的箭头或整行点击区域。

日期行不展示“复制自某日”或“模板某某”。复制和模板应用完成后，目标日期就是普通的独立配置日期，来源不属于日常业务状态。

时间摘要规则：

  • 最后一个场次有结束时间：显示“最早开始时间—最晚结束时间”。
  • 只有一个场次且无结束时间：只显示该开始时间。
  • 多个场次且最后一个没有结束时间：显示“最早开始时间起 · 最晚开始时间”。
  • 不允许出现“09:30—”等残缺时间范围。

名额摘要规则：

  • 全部场次为有限名额：显示各场次名额之和。
  • 任一场次为不限额：当日显示“不限额”。
  • 已预约人数始终按各场次有效预约实际参与人数汇总。

9.6.6 当天场次配置弹层

点击日期行后，从底部打开较高的当天场次配置弹层，以容纳至少 10 个场次。弹层显示：

  1. 标题“编辑 YYYY-MM-DD”。
  2. 当天摘要：已锁定场次数、当日合计名额。
  3. 场次紧凑列表。
  4. “添加单个场次”“批量添加场次”。
  5. “保存为模板”“应用场次模板”。
  6. “复制当天配置到其他日期”。
  7. 底部“取消”“确认”。

未配置场次的日期显示空状态，并提供“手动添加场次”“应用场次模板”“复用其他日期配置”。

点击“取消”撤销本次打开弹层后产生的新增、批量添加、时间、名称、场次名额、项目关联、项目库存模式、单独项目名额、删除、模板应用和复用操作；点击“确认”时当天至少存在 1 个场次，否则阻止确认并保持“待配置”。确认后保留本次调整并将 C04 标记为未保存，仍需点击页面底部“保存”才进入待发布配置。

9.6.7 场次卡片与编辑权限

每个场次条目展示：

  • 开始时间；有结束时间时同时显示结束时间。
  • 场次名称；未配置时显示“未设置场次名称”。
  • 已预约实际参与人数。
  • 有预约时显示“时间已锁定”。
  • 当前名额：“不限额”或“名额 N”。
  • 名称编辑入口。
  • 零预约场次的删除入口。

规则：

  • 开始时间必填，结束时间选填。
  • 场次名称选填，最多 10 个字。
  • 同一天允许存在时间重叠的独立场次。
  • 零预约场次可修改时间、名称、名额并删除。
  • 已有有效预约的场次不能修改开始/结束时间，不能删除；场次名称可修改。
  • 已预约场次可调整名额，但有限名额不得低于当前有效预约实际参与人数。
  • 删除零预约场次前二次确认；删除当天最后一个场次后，该日期回到“待配置”。
  • 时间区域和时间编辑弹层均提供清除结束时间能力；开始时间为空不允许保存。
  • 未配置结束时间时只展示开始时间，不额外显示“仅开始时间”。
  • 管理端当天场次列表始终按开始时间升序；新增、批量新增、修改时间、复制和模板应用后均重新排序。
  • 场次排序不改变场次唯一 ID，已配置的单独项目名额和历史预约继续绑定原场次。

场次项目规则：

  • 项目模块关闭，或当前场次未关联项目时，场次条目不展示项目明细，只维护场次名额。
  • 项目模块开启且当前场次关联项目时，点击场次名额进入快捷名额弹层查看关联项目和库存模式。
  • 勾选“已选项目共用场次库存”时，关联项目共用场次名额，不显示项目名额输入；取消勾选时展开项目名额输入，场次名额区域隐藏并由系统自动求和。
  • 场次存在预约后，关联项目集合和“已选项目共用场次库存”选项置灰锁定；已预约 12 人的单独模式样例必须在项目明细中显示合计 12 人，不得同时显示项目均“暂无预约”。
  • 单独项目名额必须为大于 0 的整数且不得低于该项目已预约实际参与人数；项目名额总和即场次总名额。
  • C04 页面顶部不设“批量项目名额”入口。

9.6.8 添加单个场次

单个新增弹层包含：

  • 场次名称：选填，最多 10 个字。
  • 开始时间：必填，默认空。
  • 结束时间：选填，默认空。
  • 场次名额：无关联项目或勾选共用库存时选填，留空表示不限额；取消共用库存后隐藏该字段。
  • 项目模块开启时显示“关联项目”：可选择一个或多个总体启用项目，也可不关联。
  • 新建默认选中全部总体启用项目并勾选“已选项目共用场次库存”；取消勾选后逐项目填写有限名额并实时汇总场次总名额。
  • 取消、确认添加。

开始和结束时间使用手机底部滚轮选择器，不要求手工键入数字。结束时间不得早于或等于开始时间。

9.6.9 批量添加场次

批量新增弹层包含：开始时间、结束时间、场次间隔、统一场次名额、关联项目、项目库存模式、项目统一名额、拆分结果、取消和确认添加。

  • 开始和结束时间均必填。
  • 场次间隔从 5—180 分钟中选择，步长 5 分钟。
  • 拆分数量 X = (结束时间 - 开始时间) / 场次间隔。
  • 页面实时显示拆分数量和生成的时间段。
  • 总时长不能被间隔整除时禁止确认，提示调整结束时间或场次间隔。
  • 共用库存时，统一场次名额可选“不限额”或“统一限额”；统一限额必须为大于 0 的整数。取消共用库存后隐藏统一场次名额。
  • 项目模块开启时，批量添加与单个添加使用相同的项目关联和库存规则。取消共用库存后，每个项目必须填写有限名额，并应用到本次生成的每一个场次。
  • 批量添加只新增生成的场次，不自动删除当天原有场次。

9.6.10 复制当天配置

来源日期可以是任意已配置场次的日期，包括存在预约的日期。复制范围支持：

  • 指定开始、截止日期范围内的已开放日期。
  • 当前月份全部已开放日期。
  • 全部未来已开放日期。

复制内容包括场次名称、开始时间、结束时间、名额模式、名额数量、排序、关联项目、项目库存模式和单独项目名额。以下内容不复制：预约单、已预约人数、日期特殊提示参数和历史操作状态。

目标日期处理规则：

  • 来源日期本身不处理。
  • 目标日期没有有效预约时，用来源日期场次整体替换目标日期原场次。
  • 目标日期任一场次存在有效预约时，整日跳过，不部分覆盖。
  • 执行前二次确认受影响日期数量；执行后反馈成功数、跳过日期及原因。
  • 复制生成全新的目标场次 ID，目标日期后续独立编辑。

9.6.11 场次模板

  • 管理员只能从已完成配置的某一天执行“保存为模板”。
  • 模板名称必填，模板保存该日场次名称、时间、名额、排序、关联项目、项目库存模式和单独项目名额的快照，不保存预约数据。
  • “模板管理”展示模板名称、场次数和时间摘要，支持删除模板。
  • 删除模板不影响已经应用该模板的日期。
  • 应用模板会整体替换目标日期当前场次并生成新的场次 ID。
  • 目标日期存在任一有效预约场次时，不允许整体应用模板。
  • 模板应用完成后，日期列表只显示当前配置状态，不显示模板来源。

9.6.12 日期预约管理

未来日期存在有效预约时，点击月历日期可执行：

  • 暂停或恢复该日期新预约。
  • 取消该日期全部有效预约。

批量取消必须展示受影响预约单数和实际参与人数，管理员填写取消原因并二次确认。取消成功后返还场次和项目库存；预约不可恢复。全部有效预约取消后，该日期才允许移除。历史日期不执行上述日期配置操作。

暂停规则：

  • 暂停只关闭该日期的新预约，不删除日期、场次、分类、项目或库存配置。
  • 该日期及其场次在游客端继续展示“暂停预约”，但不可选择和提交。
  • 暂停前产生的预约单、预约快照、实际参与人数、已占库存和历史统计全部保持不变；游客仍可查看，并按原规则修改资料或取消预约。
  • 恢复后重新允许新预约，但仍需实时校验预约开放时间、截止时间和剩余库存。

9.6.13 页面关系与数据影响

  • 决定 V02/V03 的可选日期、场次时间、名称、名额和状态。
  • 决定预约提交时的场次库存校验。
  • 决定 O02 预约订单筛选、O05 日期/场次名单和 O07 导出中的日期场次数据。
  • 日期和场次正式生效遵循“页面编辑态 → 保存后的待发布配置 → 最终发布配置 → 历史预约快照”四层版本。
  • 复制与模板的数据模型遵循 5.7，不允许用来源标签代替真实目标场次数据。
  • 点击 C04“保存”后，待发布游客端必须同步展示本次保存的开放日期、暂停日期、各日期独立场次、场次名称、开始/结束时间、场次名额、单独项目名额（如开启）及满员状态；未保存修改不得进入游客端效果。
  • 最终发布或发布更新后，正式游客端使用同一套页面组件展示上述已发布数据；不能继续读取管理端原始样例场次。
  • 仅下发已经配置至少一个场次的开放日期；已选择但尚未配置场次的日期只保留在管理端待配置列表，不进入游客端，也不能因汇总名额为 0 被误判为“已满额”。
  • 日期“已满额”只能由该日期已配置场次的实时库存推导：全部可预约场次均已满员时才成立；日期已过期或全部场次已截止属于“已截止”，与满员状态分开计算。
  • 游客端效果与正式游客端使用同一套逐日数据结构；区别仅是前者读取最后保存的待发布版本，后者读取最后发布版本。

9.6.14 验收标准

  • 可选择不连续日期，也可批量添加和删除连续日期。
  • “每周规律循环-敬请期待”始终置灰且无法选中，页面不存在循环规则表单和模式调整说明。
  • 历史日期、未选择日期、已选择日期和已有预约日期清晰可辨。
  • 调整日期时只校验本次真正受影响的未来日期。
  • 可按月份查看两个月以上的日期场次摘要，不一次展开全年明细。
  • 未配置、已配置、已有预约、暂停四类日期状态正确。
  • 至少 10 个场次时弹层仍可滚动查看和操作，底部取消、确认明确。
  • 开始时间必填、结束时间选填、名称 10 字限制、有限/不限额均可正确保存。
  • 已预约场次的时间和删除锁定，零预约场次仍可编辑和删除。
  • 批量拆分整除与不整除两条分支正确。
  • 项目模块开启时，单个添加和批量添加均可配置关联项目与库存模式；关闭时不展示项目字段。
  • 已预约场次的关联项目集合和项目库存模式锁定，名额仍可在不低于已预约人数的前提下调整。
  • 单独项目名额模式下，场次已预约人数等于各项目已预约人数合计，样例数据和实际数据一致。
  • 复制和模板应用后目标日期拥有独立场次；修改来源或删除模板不影响目标日期。
  • 日期列表不出现“复制自某日”“模板某某”等来源标签。
  • 暂停日期在后台摘要和游客端日期、场次中均显示明确的“已暂停/暂停预约”状态，且不能新建预约。
  • 未点击页面底部保存时，关闭或离开 C04 恢复上次保存的数据。
  • 保存后游客端效果逐日展示对应场次；修改某日的名称、时间、名额或暂停状态，不得错误套用到其他日期。
  • 管理端和游客端场次均按开始时间升序；修改场次时间导致排序变化后，单独项目名额仍绑定原场次。
  • C03 总体禁用的项目不进入游客端新预约；C04 只配置场次名额以及可选的单独项目名额。

页面状态：原日期、场次、复制和模板逻辑保留；场次卡片已恢复紧凑结构，项目名额改为快捷名额弹层按需展开，待本轮页面复核。

9.7 C05 展示设置

页面目标：配置游客端是否展示剩余名额，以及是否隐藏已截止日期和场次。

功能结构：

  • 向游客展示剩余名额开关，默认开启；统一控制日期、场次和项目三个层级的剩余名额文案。
  • 隐藏已截止日期和场次开关，默认开启。
  • 选择规则：每次预约只能选择 1 个场次。本规则只读展示，不提供管理端配置。具体提示样式见页面样式清单 C05。

游客端关系：只有已经配置并处于展示状态的日期和场次才下发游客端，不设置“未开放”状态。未配置内容等同于不存在；无预约且不再展示的场次可直接删除，有预约但需要停止新预约时使用暂停预约。日期、场次和项目统一遵循名额展示开关：有限名额有余量时，开启显示“剩余 X 名”，关闭显示“可预约”；不限额开启显示“不限额”，关闭显示“可预约”。满员始终显示“已满员”。已截止内容按照隐藏开关隐藏或展示“已截止”。

保存与发布联动：点击 C05“保存”后，两个展示开关立即进入管理端“游客端效果”；只有完成活动发布或发布更新后，正式游客端才使用本次配置。未保存的切换不进入游客端效果，未发布的保存不影响正式游客端。

状态判定顺序：

  1. 日期未配置场次：不向游客端展示。
  2. 日期或当天全部场次已超过截止时间：按“隐藏已截止日期和场次”开关隐藏，关闭开关时显示“已截止”。
  3. 日期暂停：显示“暂停预约”。
  4. 已配置场次全部无剩余库存：显示“已满额”。
  5. 存在不限额场次：名额展示开启时显示“名额不限”，关闭时显示“可预约”。
  6. 其他情况：按照逐日场次剩余库存显示可预约状态。

“已截止”是时间状态，“已满额”是库存状态，两者不得互相替代。

页面状态：业务规则与页面结构已确认。

9.8 C06 游客预约配置

9.8.1 游客信息字段列表

页面目标：维护游客预约时需要填写的动态表单。

功能结构：

  • 字段新增、编辑、删除和排序；所有字段类型均允许删除。
  • 常用字段：姓名、手机号、身份证号。
  • 姓名、手机号、身份证号均为系统语义类型，每种类型在同一活动中最多配置 1 份；管理员可修改游客端展示名称，但不能重复添加相同语义类型。
  • 自定义字段：单行文本、多行文本、数字、单选、多选、日期。
  • 特殊字段：多人/团队。
  • 配置过程中允许暂时没有填写项；发布前至少保留 1 个游客填写项。
  • 存在“多人/团体”字段时为多人模式，按游客填写人数统计和扣减库存；不存在时为单人模式，一笔预约固定统计 1 人。

历史保护：每张预约保存提交时的表单快照，后续调整当前活动字段不改变历史详情与导出。

提交规则：游客填写预约信息时不展示“我已阅读并同意本活动预约规则”勾选项，提交预约不校验该项。

页面状态：页面、交互与业务规则已确认。

9.8.2 字段编辑与多人/团队设置

常用字段

  • 姓名：名称可改，类型固定；默认必填；默认自动填充上次姓名。
  • 手机号：名称可改，类型固定；默认必填；固定格式校验；填写时可通过微信授权加载并继续修改。
  • 身份证号：名称可改，类型固定；默认非必填；校验大陆居民身份证格式。

自定义字段

  • 单行文本：最大 50 字。
  • 多行文本：最大 200 字。
  • 数字：只允许非负整数，默认最多 15 位。
  • 单选：游客端使用纯文字下拉框，至少 2 项，不做“其他”和批量添加。
  • 多选：纯文字，至少 2 项；必填时最少选择默认 2 项。
  • 日期：只选择年月日，不支持时间和范围。

多人/团队字段

  • 一个活动最多一个。
  • 字段名称自定义、类型固定、字段必填。
  • 最少人数和默认人数为 1，最多人数由管理员设置。
  • 不自动填充历史人数。
  • 第一期不收集每位同行人的资料。

新增字段先选择字段类型，再打开对应字段配置弹层；完成该字段的名称、必填和专属规则后才加入列表，不允许点击类型后直接生成未配置字段。字段类型创建后不可修改。

页面状态：页面、交互与业务规则已确认。

9.8.3 预约开放、截止与取消规则

页面目标：配置日期、场次何时进入游客端可预约范围，以及游客取消权限。

功能结构：

  • 第一期开放规则固定为“立即开放”，页面只读展示，不提供下拉修改。
  • 预约截止支持“不限制”“到场次开始时间截止”和“场次开始前 N 分钟截止”，默认为“到场次开始时间截止”。选择提前截止时只展示分钟数输入，不提供小时单位。
  • 是否允许游客取消默认开启；游客取消截止支持“不限制”“到场次开始时间截止”和“场次开始前 N 分钟截止”。关闭游客取消后不展示取消截止字段。
  • 管理员取消不受游客取消截止时间限制。

游客端控制：游客端根据预约日期、场次开始时间和上述分钟参数实时判断。达到预约截止时间后，该场次显示“已截止”且不可选择；达到游客取消截止时间后，预约详情不再显示“取消预约”入口。“不限制”不触发对应的时间截止判断。

页面状态：页面、交互与业务规则已确认。

9.8.4 游客端效果

  • C06 点击“游客端效果”时，直接进入游客信息填写页，展示当前已保存的字段、人员统计模式和本次预约摘要。
  • 管理端游客端效果只用于核对展示，不创建预约单、不扣减库存，底部不提供可提交的“立即预约”按钮。
  • C01—C05 的游客端效果进入现有日期、场次、项目选择页；管理端各步骤共用正式游客端页面组件，但读取待发布配置。
  • 只有正式游客端允许游客完成资料提交并产生预约数据。

9.9 C07 活动发布

9.9.1 页面目标

集中检查当前活动是否满足发布条件；全部必备项通过后，允许新活动发布或已发布活动发布更新。本页不混入游客字段编辑、开放截止或取消规则。

9.9.2 发布检查

发布页逐项列出检查名称、通过状态和问题说明，并至少检查：

  1. 基础信息：活动名称存在且长度有效；活动 LOGO、封面、详情和联系方式按选填规则处理。
  2. 必读须知：启用时标题、图文内容和阅读时长有效；关闭时跳过。
  3. 项目配置：启用项目模块时模块名称有效且至少有一个总体启用项目；分类名称不重复；项目名称、分类关系有效。
  4. 日期与场次：至少有一个今天及以后的已配置日期；每个日期至少一个场次；开始时间有效，结束时间如填写则晚于开始时间；场次名称不超过 10 个字符；场次有限名额不得低于已预约实际参与人数。
  5. 场次项目：项目模块开启时至少有一个总体启用项目；场次关联项目时共用状态有效；不共用时每个项目均有大于 0 的有限名额，且不得低于各项目已预约实际参与人数，项目名额总和与场次总名额一致。项目模块关闭或场次未关联项目时跳过项目库存检查。
  6. 游客字段：至少存在一个填写项；同一活动最多一个多人/团体字段；单选、多选至少两个不重名有效选项；多选上下限、文本字数、数字位数、团队最多人数均在有效范围内。
  7. 预约规则：开放方式、预约截止方式、游客取消权限及取消截止参数有效。

校验失败时发布按钮呈禁用视觉，但仍可点击查看原因；点击后提示未通过项数量，并定位到首个未通过项目。管理员返回对应步骤修改并保存后重新检查，未通过检查不得真正发布。

9.9.3 发布、发布更新与下架

页面目标：根据当前活动状态执行发布、发布更新或下架，并控制游客端正式版本是否生效。

功能结构：

  • 本规则适用于 C01—C07 全部活动配置页面及其所有字段、开关、单选、多选、日期、场次、分类、项目、库存和游客填写项，不允许某一配置页绕过保存直接更新正式游客端。
  • 任一配置发生修改后，当前步骤立即标记为“未保存”。未保存内容只存在于当前页面编辑态，不进入游客端预览或正式游客端。
  • C01—C06 底部将“保存”和“下一步”拆分为两个按钮：“保存”只将当前步骤写入待发布配置，“下一步”只切换到下一配置页。
  • 当前步骤存在未保存修改时，点击上一步、下一步、顶部其他步骤或返回列表，直接放弃未保存内容并恢复上次保存结果，不弹保存确认。
  • 后台游客端效果与正式游客端复用同一个游客端页面和组件，仅数据源不同：前者读取当前活动已保存的待发布配置，后者读取最后一次成功发布的正式配置。
  • 未执行最终发布前，待发布配置不更新正式游客端。
  • 配置修改只存在于当前编辑页，点击“保存”后才写入待发布配置并更新游客端预览。未保存时切换配置标签、进入上一步/下一步或返回列表，不提示并直接放弃本页修改；再次进入时展示上次保存的数据。
  • C07 首先判断当前活动状态，页面状态文案显示为“已上架”或“已下架”。
  • 已上架状态：C07 不再提供单独“保存”按钮，主操作为“发布更新”；发布更新使用各配置步骤已经保存的待发布配置替换线上版本，未保存内容不得进入发布。页面同时提供“下架活动”危险操作，二次确认后停止接受新预约。
  • 已下架状态：C07 同时提供“保存”和“发布上架”两个独立操作。“保存”只更新待发布配置和游客端效果，不改变活动状态；“发布上架”只发布已经保存且通过检查的完整配置，成功后活动变为已上架。发布成功后 A02 活动状态和所属标签立即同步。
  • 下架后停止新预约，但历史预约可查看、修改和取消；已保存配置、游客端预览和历史预约数据均保留。
  • 发布、发布更新与重新上架统一在 C07 操作；下架可从 C07 或 A02 已发布活动卡片发起，二者执行同一二次确认及数据规则。O01 运营管理首页不直接处理活动状态。

统一数据版本：

  1. 页面编辑态：仅存在于当前后台页面，游客端预览和正式游客端均不可见。
  2. 待发布配置：点击当前步骤“保存”后更新，供后台“游客端效果”读取。
  3. 正式配置：仅在 C07 执行“发布”或“发布更新”成功后，由完整待发布配置覆盖。
  4. 历史预约快照：预约提交时保存，不随之后的待发布配置或正式配置修改。

页面关系：发布或下架后，A02 标签、活动数量和排序同步刷新。

页面状态：业务规则已确认，操作位置与页面结构待逐页复核。

10. 游客端页面功能

本章只记录已经确认的功能逻辑。游客端页面样式统一维护在《HTML 原型页面样式清单 V3.4》和《预约小程序 Figma 与主题规范 V3.4》中。

原型辅助页：活动效果浏览（本期不开发）

  • 独立位于场次预约页之前，不嵌入场次预约页面内部。
  • 仅供产品和业务在 HTML 原型中集中查看全部已上架活动，并逐个进入对应的场次预约页比对配置效果。
  • 列表只读取各活动最后一次成功发布的快照；后台仅保存待发布配置时，辅助列表和对应活动的正式效果均保持不变。
  • 活动首次发布或执行“发布更新”后，辅助列表及该活动的全部游客端原型页面同步为最新发布快照；活动下架后从辅助列表移除。
  • 本页不是一期真实小程序功能，不作为开发交付和验收范围。

10.1 V01 预约首页/活动详情

  • 展示活动图片、名称、详情介绍和联系方式。
  • 提供“我的预约”入口。
  • 同页依次承载日期、场次、分类和项目选择。
  • 下架活动展示详情和下架状态，不允许发起新预约。
  • 默认加载当天可预约日期；无当天日期时按照可用日期规则展示。

10.2 V02 日期月历弹窗

  • 横向日期条可打开月历。
  • 月历选择日期后关闭弹窗，并将所选日期定位为横向日期条首选日。
  • 月历允许点击遮罩关闭。
  • 横向日期条可前后滚动，不因选择日期反复重排造成眩晕。

10.3 V03 日期与场次选择

  • 默认从当天开始展示，不展示今天以前的日期。
  • 默认选中当天并直接加载当天场次。
  • 日期和月份横向区域保留边缘留白并可滚动。
  • 场次按时间顺序展示；自动定位当前时间对应场次，同时允许向前查看历史时间段。
  • 配置结束时间时显示起止时间，未配置时仅显示开始时间。
  • 配置名称时显示名称，未配置时不显示名称行。
  • 游客端只接收已配置且需要展示的场次，不存在“未开放”场次状态。
  • 可预约场次显示剩余名额或不限额，满员显示“已满员”。
  • 已截止场次根据配置隐藏或显示“已截止”。
  • 暂停日期继续显示“暂停预约”；该日期的场次同步显示“暂停预约”并不可选择。暂停不影响已有预约记录、详情、资料修改和取消。

10.4 V04 分类与项目选择

  • 无项目时整个项目模块不显示。
  • 有项目、无分类时直接展示项目。
  • 启用分类时先展示分类，再展示当前分类项目。
  • 分类支持横向切换；切换分类后保留当前横向位置，并确保新选中的分类仍处于可操作范围。
  • 一次只能选择一个项目。
  • 项目可采用有图图文卡片或无图简洁卡片。
  • 项目禁用后不展示；项目满员时显示“已满员”并不可选。
  • 项目只有展示或隐藏；隐藏后不向游客端下发，不设置“未开放”状态。

10.5 V05 必读须知

  • 命中须知条件时，在日期正式选中前弹出。
  • 展示配置标题、图文内容和倒计时确认按钮。
  • 倒计时结束后才能确认。
  • 关闭弹窗时不选中日期。
  • 同次进入页面，同一日期确认后不重复弹出；重新进入页面需再次确认。

10.6 V06 游客信息填写

  • 顶部展示已选日期、场次、分类和项目摘要。
  • 摘要仅展示当前实际配置内容，不增加冗余字段。
  • 动态展示管理员配置的填写项。
  • 手机号可通过微信授权加载，也可手动修改。
  • 单人模式不显示人数控件。
  • 多人模式显示管理员自定义名称的人数控件，默认 1 人。
  • 页面不展示可能随库存变化失真的“本场次最多还可添加 X 人”。
  • 页面不展示“我已阅读并同意本活动预约规则”勾选项，提交时不校验该项。
  • 返回后临时保留本次填写数据。

10.7 V07 提交与预约结果

  • 主按钮为“立即预约”。
  • 提交中禁用重复点击。
  • 服务端执行最终状态、表单和库存校验。
  • 成功页突出游客预约号，并展示活动、日期、场次、分类、项目和实际参与人数。
  • 实际参与人数保持单行展示。
  • 成功后可查看预约详情或返回预约首页。
  • 库存不足时留在填写页并保留资料。

10.8 V08 我的预约列表

  • 标签：全部、已约/报名、已取消；默认全部。
  • 查询当前微信用户在当前景区下的全部预约活动记录。
  • 卡片展示状态、活动、日期、场次、项目、人数、预约号和提交时间。
  • 点击卡片进入预约详情。
  • 未来有效预约按日期和场次升序，历史预约排后；取消记录按取消时间倒序。

10.9 V09 游客预约详情

  • 顶部显示预约成功或已取消，并突出游客预约号。
  • 展示预约内容和全部填写资料。
  • 手机号和身份证号第一期不脱敏。
  • 填写信息较多时可折叠展开。
  • 成功状态根据配置提供修改和取消。
  • 已取消状态展示取消时间、方式和原因，不再提供修改取消。
  • 活动下架后历史详情仍可查看。

10.10 V10 游客修改与取消

  • 修改只进入信息填写页，不返回选择流程。
  • 日期、场次、分类、项目只读。
  • 可修改普通资料和多人实际参与人数。
  • 增加人数重新校验库存，减少人数返还差额。
  • 取消弹窗展示活动、日期场次、项目和预约号。
  • 游客取消原因选填。
  • 取消后状态变为已取消并立即返还库存。

  • 点击活动卡片进入该活动的 O01 活动管理首页。
  • 本页只用于选择运营对象，不提供新建、复制、删除和编辑配置操作。

11.2 O01 活动运营首页

  • 展示活动名称、发布状态、更新时间和更新人。

  • 预约运营区只提供三个入口：全部预约、场次名单、数据导出。

  • 不设置近期预约模块。
  • 下架后仍可查看数据和处理历史预约；运营首页不提供编辑配置、下架或重新发布，活动配置及状态操作在配置管理端处理。
  • 业务范围和页面操作已确认。页面样式见《HTML 原型页面样式清单 V3.4》O01。

11.3 O02 预约订单列表

  • 页面顶部展示当前活动名称和今日预约人数；今日预约人数按当日提交成功预约的实际参与人数统计，不展示活动累计总参与人数。
  • 标签仅包含“已预约”“已取消”，不显示数量；进入页面默认加载“已预约”。
  • 搜索游客预约号、姓名和手机号。
  • 筛选条件包含预约日期范围、场次、分类和项目，默认收起，通过筛选入口展开或隐藏。
  • 预约日期提供“指定单日”和“全部日期”两种范围。进入页面默认“指定单日”，日期默认为当天；管理员可通过手机日期控件选择昨天、明天或其他任意单日。选择“全部日期”时隐藏单日日期控件，必须输入预约号、姓名或手机号后才执行查询；空关键词不加载全量预约，并提示先填写查询条件。

  • 日期、场次、分类和项目筛选区域支持横向滑动，不能因屏幕宽度遮挡末尾条件。
  • 支持简要列表和详情卡片切换。
  • 默认按提交时间倒序排列，可切换提交时间正序；指定单日和全部日期查询使用同一排序规则。
  • 展示当前结果预约单数和实际参与人数合计。
  • 列表点击进入 O04 管理端预约详情，不在列表直接修改或取消。
  • 详情卡片中的场次名称及时间、分类及项目分别作为两组预约内容展示。
  • 业务与页面已确认；页面样式见《HTML 原型页面样式清单 V3.4》O02。

11.4 O03 详情卡片字段设置

  • 字段来源为当前活动最新保存的游客填写项配置，与 C06 使用同一字段定义；C06 增加、删除、改名或排序并保存后，O03 同步加载最新字段清单。
  • 界面展示管理员配置的“填写项名称”，不展示姓名、单选、多选等底层控件类型名称。
  • 只加载当前活动实际配置的填写项；未配置的控件不进入字段设置，也不在详情卡片中展示。
  • 进入详情卡片时默认选择并展示当前活动的全部游客填写项；管理员可调整显示字段，但至少保留 1 项。
  • 配置变更后，全部历史预约也按照当前字段配置展示，不保留各历史时期的卡片字段布局；历史记录没有对应值时展示空值状态。
  • 字段显示顺序为：姓名与手机号一行，身份证号与多人/团队一行，单选一行，多选一行且允许换行，数字与日期一行，单行文本一行，多行文本一行。
  • 同一双列行只配置了一个字段时，该字段占满当前行；未配置的字段不保留空位。
  • 设置只影响 O02 管理端详情卡片显示，不改变游客填写表单、预约原始数据和 O04 详情字段。

11.5 O04 管理端预约详情

  • O04 不单独生成详情样例数据。由 O02 或 O06 点击预约记录时传入预约记录唯一标识，并读取同一条预约对象；列表与详情中的预约号、状态、提交时间、预约日期、场次名称、场次时间、分类、项目和实际参与人数必须一致。
  • 展示状态、游客预约号、活动、提交时间和最近修改时间。
  • 展示日期、场次、分类、项目和多人模式人数。
  • 游客提交预约时，将当时使用的字段 ID、填写项名称、字段类型、选项配置和填写值一并写入预约表单快照。O04 按该预约记录的表单快照展示全部游客资料，不使用详情页写死字段或另一套样例数据；手机号可点击拨打。
  • 游客提交后，管理员在 C06 改名、删除、增加或调整字段，不修改历史预约的字段名称、类型和填写值；新配置只影响之后提交的新预约。
  • 操作记录读取同一预约对象的创建、修改和取消记录；没有发生的操作不生成虚假记录。
  • 支持复制预约号、手机号和身份证号。
  • 有效预约可修改允许字段或取消；管理员取消原因必填。
  • 操作记录只显示已经实际发生的事件，按发生时间正序展示。记录头固定为“操作名称”，第二行固定为“时间 · 操作人”，第三行为操作结果说明。游客执行时操作人统一记录为“游客”，不读取游客姓名，也不显示“游客端”；管理员执行时记录实际登录管理员姓名。
  • 操作记录覆盖以下事件：游客创建预约、游客修改预约资料、管理员修改预约资料、游客修改实际参与人数、管理员修改实际参与人数、游客取消预约、管理员取消预约。创建、修改、取消以外的页面浏览行为不记入操作记录。
  • 不展示系统内部 ID 和本单库存占用字段。

  • 增减人数执行库存差额校验、扣减和返还。

  • 日期或场次批量取消展示受影响预约单数和实际参与人数，并要求二次确认。

13. 状态、统计与数据一致性

13.1 预约状态

第一期只有：

  • 预约成功。
  • 已取消。

不设置待审核、审核拒绝、候补、待核销和已核销。

13.2 场次和项目状态

  • 游客端可预约。
  • 已满员：继续展示，不可选择。
  • 已截止：根据配置隐藏或展示，不可选择。
  • 未配置或隐藏：不向游客端下发，不作为状态卡片展示。
  • 项目禁用：视为不存在。

13.3 统计口径

指标 口径
有效预约单数 当前状态为预约成功的预约单数量
有效实际参与人数 有效预约实际参与人数之和
今日新增预约单数 当天创建且当前有效的预约单数量

13.4 事务与幂等

以下操作必须使用服务端完整事务：

  • 创建预约与场次/项目库存扣减。
  • 修改实际参与人数与库存差额变化。
  • 取消预约与库存返还。
  • 日期或场次批量取消。

每次请求使用唯一标识，避免重复创建、重复扣减和重复返还。

15. 全局验收标准

15.1 主流程

  • 管理员可完成活动配置、校验并发布。
  • 游客可完成无项目、有项目无分类、有分类有项目三条预约流程。
  • 单人和多人模式均能正确生成预约并扣减库存。
  • 游客和管理员能查看、修改和取消预约。
  • 管理员能查看订单、场次名单并导出数据。

15.2 异常流程

  • 场次满额、项目满额不可提交。
  • 填写过程中库存被占用时保留资料并提示调整。
  • 已截止内容按配置隐藏或不可选择。
  • 总体禁用项目不参与新预约，但历史预约继续有效。
  • 活动下架后不接受新预约，历史预约仍可查看、修改和取消。
  • 重复点击和网络重试不产生重复预约。

15.3 历史数据

  • 配置更新不改变历史预约快照。
  • 取消后正确返还场次和项目库存。
  • 人数修改只处理差额，失败不改变原数据。
  • 导出字段与预约提交时表单一致。

15.4 页面适配

  • 五档手机宽度无横向溢出、遮挡和不可点击区域。
  • 长活动名、长项目名、四位数以上人数和动态字段正常展示。
  • 横向日期、月份和场次滚动不会丢失前后内容。
  • 固定底栏和键盘不遮挡表单与错误提示。
