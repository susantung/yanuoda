## 第二组：项目列表及基本信息（2026-11-05）

用户已同意先制作该部分，再逐块展开。依据06第13.2/13.3、25节以及本轮明确顺序。沿用同一外壳、列表卡片/筛选/操作/表格/分页；操作列固定右侧。赛事列表“报名项目”进入所属赛事项目列表，返回保留原赛事筛选上下文。项目名称筛选，不增项目数量筛选。

项目列表字段：名称、每份报名人数、报名开始截止、签署要求、收费方式、配置状态、排序、操作；示例专业竞技组/大众体验组各2人，需签署/关联票来自已确认场景，报名日期未最终配置留空，不编造早鸟时间或票。配置状态仅显示待完善，不声明可报名或已对外生效。排序为正整数，同值稳定按原位置排列；编辑操作进入独立项目页；报名记录入口后续制作。

编辑页用现有el-steps+el-card+el-form模式，步骤基本信息/报名资料/报名人数/阅读与签署/关联门票；本轮只制作基本信息，后续步骤不提供假跳转。字段所属赛事（只读）、项目名称、项目说明、比赛起止日期、报名起止时间（含时分秒）。比赛日期默认当前赛事举办日期，可调整；不强加未确认的“报名必须早于比赛”等限制。保存只存本地基础配置，不开通报名。项目名称必填，未配置完整的日期可留空存草稿；已填写起止要合法且开始不得晚于截止。

控件转译：项目说明用画像支持的el-input type=textarea；比赛日期el-date-picker daterange，报名时间datetimerange；完整表单独立页，label140px，主输入500px、日期时间范围500px；底部取消/保存。结构、字段与操作均来自当前已讨论规则；草稿保存边界参照13.3，但发布/启用仍不制作。

游客端对应内容另附对照说明，不在后台加入未经确认的前台预览业务按钮。本轮不制作正式小程序设计或绕过选定Figma路径。


## 2026-11-09 补充：报名人数汇总与记录页面

- 项目列表、赛事列表增加“报名人数”，显示“已报名人数/总报名名额”，例如3/300；不限名额显示3/不限。
- 已报名人数只统计报名成功的参赛人数，双人报名成功一笔计2人；暂存、待签署、待提交、待付款不计入。
- 赛事已报名人数为所有项目成功人数之和；总名额为所有项目总名额之和。任一项目不限名额，赛事显示不限；无不限项目但存在未配置名额的项目时显示未配置，不把未知名额当0。
- 报名记录和报名详情均使用可关闭的内部标签。记录筛选姓名、手机号、身份证、报名状态、最新订单号及订单状态；多个人员条件匹配同一参赛者。详情展示提交资料快照、每位参赛者电子签名及最新订单号、状态、实收金额，不展示历史订单。
- 原型使用本地记录与示例签名，尚未接真实订单跳转地址；报名编号生成规则仍待业务确认。
