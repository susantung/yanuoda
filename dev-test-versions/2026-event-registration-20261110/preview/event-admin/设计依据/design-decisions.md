# 设计决定

范围：本地路线，先完成赛事层两页，后续项目配置单独审阅；不是恢复旧人数规格Demo。

1. 赛事名称/举办时间是筛选；项目数仅展示。依据06第25节和用户取消项目数查询要求。
2. 全域正常浅色外壳；真实列表密度优先于画像通用值，差异见制作契约。一级赛事管理与活动预约管理并列。
3. 完整赛事表单采用独立页，基本信息与介绍分卡；用现有Element控件和标准居中保存区，避免自造弹窗承载整套长表单。
4. 举办时间与报名时间分离。本页仅举办日期，不添加总报名起止、收费、票或人数；那些属于项目配置。
5. 封面本地选择预览，正文基础编辑；现阶段核对结构，不承诺上传服务或完整生产富文本功能。
6. 初始示例仅用于页面讨论；1月3日来自本场资料，具体比赛时刻、正式封面和章程未最终配置。
7. 后续页面入口显式禁用并说明，不将未完成页面包装为可用；新页面逐页增量，不修改旧讨论原型。

## 报名项目基本信息与游客展示的对应

本轮实现项目列表及基本信息独立页；后续资料、人数、阅读签署、关联票分步补齐。此轮不恢复旧版多人数规格选择。

| 后台配置 | 游客端用途 | 当前边界 |
|---|---|---|
| 所属赛事 | 确定该项目出现在谁的报名列表中 | 从赛事进入，表单只读展示 |
| 项目名称 | 项目列表及报名流程的项目标题 | 本轮唯一保存必填项，保存为草稿 |
| 项目说明 | 选择项目前了解参加内容 | 前台展开或摘要方式留待逐页设计 |
| 比赛时间 | 告知项目实际举行日期 | 与赛事默认日期分开存储，可编辑 |
| 报名时间 | 展示项目报名起止与可报名状态 | 关联票后还须结合真实售卖条件，当前未实现状态计算 |

每份人数、是否签署、关联票与价格将由后续配置决定。列表现有两组示例用于结构讨论，不能据此认为项目已经配置完整、可以上线报名。后四步仅显示后续配置方向，不提供虚假跳转。

赛事正文现已替换为同源TinyMCE4.9.2；此前基础正文编辑描述属于首次实现历史状态。
