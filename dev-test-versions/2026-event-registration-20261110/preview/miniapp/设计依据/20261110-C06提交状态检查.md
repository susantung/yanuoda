# C06提交交互检查（2026-11-10）

产品第4/6阶段、设计第1/4步。提交交互规则获用户“好”确认后制作，页面状态原型自检通过，新增呈现仍待用户看效果；不等于真实接口验收。

## 实际文件

- submission.js：审阅区成功/库存失败/结果未知场景与模拟核实响应；捕获一次提交快照、锁定控件、失败恢复、成功锁定及自动支付衔接（按用户纠正删除去付款按钮）。
- registration.js：立即报名接入提交状态，进入新资料示例时清理演示状态，状态切换时维持锁定。
- registration.css：原支付衔接按钮复用品牌和底栏尺寸。
- index.html：本地脚本及资源版本更新；入口?view=submission，免费示例追加kind=free。

## 已执行与观察

1. 点击立即报名后，按钮为提交中，资料输入、暂存和重复提交禁用。
2. 模拟库存校验失败后，保留两人姓名/手机/身份证及已签2/2，输入和立即报名恢复，无草稿自动写入。
3. 结果未知时显示正在核实，输入和提交持续禁用；模拟核实未提交，恢复重试。
4. 最新行为：收费提交/下单成功后自动进入微信支付调用演示，无去付款按钮；全部资料锁定，暂存/报名/签署按钮隐藏。原先保留去付款的做法已按用户要求删除。
5. 切换须知/资料后锁定仍保留；取消/未支付保留待付款，不恢复提交按钮或重复下单。支付核实成功则报名完成；未知则核实原有效订单。
6. 免费模拟成功显示报名成功、资料锁定，无支付按钮，无订单/支付调用；完整C08结果页未制作。
7. 实际手机框宽度320/360/375/390/414均无横向溢出，提交按钮48px。曾先观察到浏览器滚动条导致实际宽度少15px，随后调整测试视口并重新核对，以上是校准后的实际宽度。
8. 此前绿色/蓝色/暖色衔接按钮已检查；最新改为自动支付，原衔接按钮已删除。控制台未见error，registration.js及submission.js语法检查通过。
