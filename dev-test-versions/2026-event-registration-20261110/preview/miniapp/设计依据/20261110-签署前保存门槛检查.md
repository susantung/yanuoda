# 签署前保存门槛局部检查

依据：用户确认签署前须成功暂存的方案；最新纠正为仅底部一个“暂存”按钮，并要求全部调整结束后统一重新打包。当前既有研发ZIP未更新。

修改：registration.js/css（资料保存快照及暂存门槛提示）、records.js（首次暂存生成本地记录、后续更新及恢复）、signature.js/shared-registration.js（保存门槛防绕过、签署进度更新）、submission.js（保存中锁定、预览示例）、index.html（脚本版本与演示边界）。主方案12.7—12.8、评审入口工作稿及纪要对照同步。

## 实际检查

- 五份修改JS通过node --check。
- 浏览器“仅姓名”双人模板：未齐全只普通暂存及统一提示，签署/分享入口隐藏。
- 填齐出现先暂存提示，签署区无新增保存按钮；演示保存失败后保留输入、不开放签署；重试成功后出现逐人去签署/分享。
- 保存时输入/返回/相关动作锁定，完成后恢复。
- 首次保存创建一条本浏览器记录；再次保存更新该条；列表出现一条新增“待签署”，未显示提交时间。
- 保存后进入画布并实际绘制测试笔画，确认后进度1/2；已签人员显示重签署、不显示分享。
- 修改另一位未签人员资料后显示“请先暂存资料，再进行签署或分享”，隐藏签署/分享；保存后已签人员保持1/2。
- 刷新页面，从我的报名找回新增记录，已存两人姓名及1/2签署进度恢复。
- 修改已签人员姓名，原签署失效为0/2，需先保存修改；截图记录此门槛。

初次检查遇到旧版本签署脚本未加载导致openSignature未定义；更新脚本缓存版本后重新加载，实际进入画布并完成签署通过。

## 限制

以上为同浏览器localStorage示例和局部检查，非真实跨设备读取、账号授权、服务端原子保存或姓名识别。检查使用仅姓名模板；手机、证件等非姓名字段修改的签署保留逻辑沿既有实现，本轮未新增该场景的操作验证。未重复做所有视口/主题、真实订单支付或全系统验收。

最新截图：20261110-仅底部暂存.png。已实际复验底部暂存成功后开放签署/分享、保留未改名人员1/2签署；修改已签姓名后0/2且重新提示暂存。旧上方保存按钮已删除。
