## 需求背景与目标

### 1. 业务背景：先承接呀诺达本次赛事

呀诺达景区要为“2027呀诺达一二三热带雨林水陆挑战赛”提供线上报名。最初业务材料包含专业竞技组、大众体验组、双人报名及早鸟／正价等场景，报名还涉及文明参赛倡议、安全风险提示、参赛声明等阅读和签署要求。这些赛事名称、组别、价格和材料应由运营按最终活动内容配置。

目前全域平台已有散客票配置、游客资料、下单、支付、订单和票券能力，但现有购票页面围绕选票、使用日期和购买数量组织。赛事报名需要围绕报名项目、整组参赛资料、暂存、逐人签署和报名结果组织，不能直接用现有购票页承接完整体验。

因此，独立建立赛事、报名配置与报名记录，新增面向参赛者的报名页面；需要收费时关联现有门票，用报名资料生成原下单所需信息，复用既有交易链路。赛事介绍的前置展示页仍由现有页面配置功能搭建。

### 2. 本次要解决的实际问题

| 使用者 | 业务问题 | 本期要达到的结果 |
| --- | --- | --- |
| 参赛者／主报人 | 一次报名可能包含多位参赛者，资料填写和本人签署需要跨步骤、跨手机完成 | 主报人统一填写N人资料，按确认规则暂存；需要签署时各人签本人，全部就绪后统一提交 |
| 参赛者／付款人 | 报名与支付属于同一链路，支付中断后仍需找到资料和原订单 | 收费提交后调用微信支付；待付款可看资料并继续原订单支付，实际订单取消后保留资料回到未提交阶段 |
| 报名成功者 | 报名结果、参赛资料、分享和现场核验各有用途 | 成功后出海报并支持保存分享；“我的报名”可查资料和海报，有订单时可进入原订单查看核销二维码 |
| 景区运营 | 不同项目的报名时间、人数、填写项、签署材料及收费方式不同 | 后台按赛事和项目配置，查看报名、签署及关联订单信息；报名成功的公开查询由独立赛事查询入口承接 |

### 3. 通用产品目标：后续赛事以配置复用

用户于2026-11-03明确要求：先说明本次呀诺达的目标和用户问题，再说明借此次建设形成哪些通用配置能力。**呀诺达双人收费赛事是首个落地场景，不固化为所有赛事的默认规则。**

通用能力以“赛事 → 报名项目 → 报名选项／关联门票”组织。项目名称、报名人数、报名窗口、资料项、阅读材料和是否签署按项目配置；关联门票承接收费，不关联门票承接免费报名。后续运营可配置单人或多人、收费或免费、需要或无需签署的不同活动，同一赛事中的多个项目可以各有规则。

期望复用的场景包括景区双人／多人挑战、公开收费单人赛、简单免费报名及内部活动。内部或公开分发可通过既有页面和二维码入口组织；不据此增加员工身份验证、抽签审核、成绩排名、证书或其他未经确认的能力。

### 4. 方案的核心边界

1. 赛事负责报名规则、资料和签署；门票负责既有交易、库存与订单能力，两者通过关联衔接。
2. 小程序独立完成报名资料收集，关联下单时复用这些资料，避免用户再次选票、重复填写游客信息。
3. 本文目标不替代逐页规格。字段、状态、保存与校验以后台B01—B10、小程序C01—C11及公共规则K01—K07为准。
4. 不设未经业务确认的转化率、收入或效率指标，不将可操作原型等同于真实支付、库存、短信等服务已经接通。
