### 时间来源与判断

- 赛事举办日期、项目比赛日期、项目报名窗口、原票可售窗口各有职责。开始不得晚于自身结束；不额外要求报名截止早于比赛首日，不按比赛首日00:00截断。
- 收费报名项有效窗口取项目报名窗口与本票真实可售窗口交集；开始取较晚值，截止取较早值。无交集则不匹配。允许各票窗口衔接、交叉或空档，不合并为虚假的连续时段。
- 免费项目直接使用项目报名窗口。展示可到分钟，交易判断仍精确到秒；当前基线包含起止时刻，真实服务端边界须与票务语义对齐。
- 后台项目时间状态仅“未开始／进行中／已截止”，缺时间“未配置”，不代表有库存、已发布或可下单。游客报名项另判时间、名额和票库存。
- 草稿绑定原报名项，不自动从早鸟换到正价，不保留已过期价格资格。后续提交必须重新检查当时窗口与原票。

### 名额、库存与交易

| 内容 | 规则 |
| --- | --- |
| 项目总名额 | 免费/收费均独立配置限制或不限；有限总人数为N整数倍 |
| 首次票容量检查 | 限制名额时，关联票可用库存张数合计×N不得小于项目总名额，可以更大；存在不限库存票可覆盖有限名额 |
| 后续报名 | 分别检查项目剩余可用人数≥N及所选票库存≥1张；不能拿剩余票库存反比初始总名额 |
| 不限 | 项目不限不能绕过票库存；票库存不限也不能解除项目名额上限 |
| 阅读/暂存/签署 | 不占名额或票库存，不算报名成功，不锁价 |
| 收费下单待付款 | 临时占用，付款成功转正式；失败、实际取消或超时关闭按原交易链路释放，不能重复扣减/释放 |
| 免费提交 | 最终提交时校验项目窗口和名额，成功计入报名人数，无票务占用与支付 |

后台“门票可支持人数”是库存折算展示，不是另一项可编辑报名名额。使用“库存合计张数×N＝可支持人数”。库存-1代表不限，原型99999只是演示，不能据此形成生产库存规则。成功人数不能代替含待付款占用的可用名额。
