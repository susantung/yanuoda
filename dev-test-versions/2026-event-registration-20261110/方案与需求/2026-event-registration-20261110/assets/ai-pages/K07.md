### 配置原则

先配报名N与字段，再匹配原票；不从票反向覆盖报名模板。价格、库存、预订限制只读，修改到原票系统处理。后台匹配通过不保证未来可下单，提交仍实时校验。全部N人资料传入原链路，不按旧购票表单的框数截取。

| 原票预订信息模式 | 关联约束 |
| --- | --- |
| 无需游客资料 | 可匹配，仍保留报名N人的资料和签署 |
| 仅一位游客 | 沿既有票模式，不强制N=1，报名全部N人资料仍须传入 |
| 所有游客 | 固定买1张，沿原票模式，不强制N=1，真实契约待验证 |
| 每张券需X位游客 | X必须与N完全相等，不能按X≤N |

姓名始终必填，票未要求姓名不构成不匹配。票要求身份证必填，报名必须配置且必填；票不要求身份证，不因报名额外收集而禁选。其他原票必需字段也须有对应来源。购票联系人手机号取发起人授权手机号，不能拿其覆盖所有参赛者。

报名关联阶段不增加“最低起售量>1就禁选”的规则；最终固定买1张，按原票实际起售量、限购、年龄、地区、性别等校验并返回实际原因。全部N人及对应资格校验是既定业务要求，真实参数/年龄基准待核实，不能退化为只验证第一人。

### 比赛日期、价格、库存与可售期

| 比赛/票类型 | 匹配与取值 |
| --- | --- |
| 单日＋日历票 | 真实已配置日期集合须包含比赛当天；读取当日价格和库存，不拿最早/最晚范围代替完整日期集合 |
| 单日＋固定有效期票 | 使用期覆盖比赛当天；从总库存配置取价格库存 |
| 多日比赛 | 本期只用固定有效期票，完整覆盖比赛起止；不使用日历票或选择日期起X天方案 |
| 日历票开放/截止 | 根据传入比赛日和原预订规则计算 |
| 固定有效期免选日票 | 提前预订逻辑无效，取价格库存中的可售时间；使用有效期与付款可售期分别检查 |
| 可订当日提前X小时的既有文案 | 当前基线按可订当日23:59:59处理，不由文案另加硬拦截；真实接口语义待核对 |
| 固定日期且下单后X天生效 | U06a待核实完整计算；原型暂不支持不等于生产永久禁用 |
| 缺比赛日配置/价格库存记录 | 显示“—”并禁止关联，不用最低价、其他日、0或不限补缺 |

总库存是库存方式，不能等同相对有效期或延迟生效票。已知可售窗口按K02取交集。全域与三方配置一致性人工保证，不新增跨系统配置强比对；报名与最新全域票的兼容检查仍保留。

进入/重开项目编辑、打开选票、最终完成时读取最新票配置重新匹配；最终不匹配须显示原因并阻止完成。游客提交仍查实时票、全部人员资格和库存，不能依赖旧配置结果。真实接口接入见开发清单，不把原型变量当正式字段名。
