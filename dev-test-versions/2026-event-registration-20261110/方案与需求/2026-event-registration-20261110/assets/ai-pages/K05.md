> **项目内迭代新增V1.1 · V11-12（规则细化）**：仅打开页面、阅读或完成全部材料阅读，不生成报名记录，不触发后台配置锁定；阅读进度独立保存。首次主动暂存成功（包括半填暂存）产生报名记录后，才按K05限制后台配置修改。

此触发条件针对项目内是否已有报名记录：某游客仅阅读不解除其他游客已产生报名记录带来的配置限制。已有记录后仍按配置分别判断：资料项不可改删、允许新增；N及是否签署不可修改；有限总名额只增不减；免费/收费及关联票继续按是否产生过相应订单判断，不因首次暂存一律锁定。

> **项目内迭代新增V1.1 · V11-11（规则细化）**：区分后台项目配置限制与游客已填资料的修改权限；暂存产生记录不等于游客资料只读，不改变已确认业务。

本节“已配置资料项不可改删”“单次N、是否签署锁定”均指**后台运营修改项目配置**，不表示游客已填资料不可修改。字段定义（例如是否收集手机号）与游客填写值（例如手机号具体号码）是两类对象。游客数据修改权限按C03/K04/K06判断：主报人未提交可改；成功下单待付款或报名成功后只读；原未付订单实际关闭后恢复未提交可改；组员查看始终按只读权限。下表涉及“修改参赛者姓名”“待付款或成功报名的人员资料与签署”的行，是游客数据规则，与后台模板配置分开理解。

> **项目内迭代新增V1.1 · V11-06**：有限总名额只增不减且仍须N整数倍；限制/不限模式与N仍锁定，不改票库存及旧占用。


| 修改对象 | 允许范围 | 历史/进行中数据 |
| --- | --- | --- |
| 已配置资料项 | 有游客报名记录（包括半填暂存）后不可改删；允许新增，新项本次保存前可改删，保存后同样限制；不额外禁止排序 | 未提交保留旧值并展示新增项；已提交只读提交快照，不追补 |
| 单次N、是否签署 | 首次主动暂存成功产生报名记录后，后台不可修改；仅阅读或完成阅读不触发锁定。**项目内迭代新增V1.1 · V11-12（规则细化）** | 项目是否已有报名记录以服务端实际记录判断，不以阅读进度或本地示例判断 |
| 有限总名额 | 已有报名后只增不减，仍为N整数倍 | 不改原报名/订单/占用，不自动增加门票库存 |
| 限制/不限模式 | 已有报名后不可切换 | 本轮只放开有限总名额增额 |
| 免费/收费 | 尚未产生订单可切换，已有暂存/阅读/签署不锁；已有订单不可切换 | 保留资料进度，最终按当前模式校验；已提交不追改历史 |
| 有过报名订单的关联票 | 不替换、不移除，订单取消或退款也不解除历史限制 | 展示名称和逐项限制说明仍可改；已提交保留当时展示名称，不改历史票/价/人数/订单 |
| 从未产生订单的关联票 | 按该票自身判断可移除重加；不因项目另一票有订单就全部锁住 | 新增关联票允许，旧暂存不自动换项 |
| 报名时间 | 可调整，提示影响未提交报名 | 过期草稿不可提交；延长不延长票售卖期；不自动取消已有成功或仍有效待付款订单 |
| 赛事介绍/报名须知/已有材料正文 | 可改，展示最新正文，不做完整原文版本 | 已读已签保留，不自动重读重签；未完成继续最新正文 |
| 新增签署材料 | 需签署项目仍至少一份 | 未提交补读新增材料，已有有效签名保留；已提交含待付款不追补 |
| 删除签署材料 | 需签署项目仍至少一份 | 未提交不再读被删材料，其他已读已签保留；已提交不追改 |
| 修改参赛者姓名 | 未下单可改 | 仅该人原签署失效，其他人保留；非姓名资料修改不重签，仍须重新暂存后签/分享 |
| 待付款或成功报名的人员资料与签署 | 不可修改或换人 | 未付款原订单实际取消/关闭后才恢复未提交；全额退款后的名额释放和新旧订单关联按本节退款规则执行，不能直接套用未付款取消规则 |
| 比赛延期/取消 | 另专题待讨论 | 不能从允许改报名时间推导已出票使用期或退款政策 |
