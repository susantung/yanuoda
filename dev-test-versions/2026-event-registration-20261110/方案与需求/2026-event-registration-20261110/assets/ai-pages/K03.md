# K03｜暂存、记录与快照

> **项目内迭代新增V1.1 · V11-02**：全员资料齐且底部暂存成功才开放签署/分享；改资料后再用同一暂存按钮。首次暂存建记录的方向原已存在，本轮补齐本地同一记录保存及恢复。
> **项目内迭代新增V1.1 · V11-03**：暂存成功短暂浮层约2秒，不占底栏；不新增上方保存按钮。


| 动作/状态 | 保存与显示规则 |
| --- | --- |
| 仅打开页面、阅读或完成材料阅读 | 阅读进度独立保存，不生成报名记录，不触发后台配置锁定。**项目内迭代新增V1.1 · V11-12（规则细化）** |
| 普通输入、切换须知标签 | 保留本页内存输入，不自动保存到报名记录 |
| 首次主动暂存成功 | 生成一条报名记录，按资料/签署完整性取资料待完善、待签署或待提交 |
| 后续暂存、签署成功 | 更新同一份记录及对应人员进度，不另建报名 |
| 暂存一半资料 | 允许，不要求全部必填先齐；不能因缺项丢弃已填值。非法格式的完整存储契约待接入核实 |
| 直接离开未保存输入 | 本次未保存变更丢弃；有上次成功暂存则保留上次数据，不删除旧记录；无离开确认三按钮 |
| 进入签署或分享 | 必须全部N人必要资料齐且已成功暂存。暂存后再改资料需使用同一个底部暂存成功后再签/分享，无上方保存按钮 |
| 最终提交 | 资料和必要签署/阅读齐备并通过实时校验后保存提交快照；收费同步下单，免费直接完成 |
| 提交后的资料 | 含待付款，按提交时字段与数据快照展示，不补填之后新增字段 |
| 未提交的资料 | 读上次成功保存值和适用最新模板，新增字段显示，既有已填值保留；按必填规则补齐 |

保存失败不得声称成功或覆盖上次成功数据。签署确认保存与普通资料暂存是不同业务动作，签署不等于最终提交。报名时间取最终报名提交成功时间；前端标签“报名时间”，后台标签“报名提交时间”，不取创建/暂存/支付时间。未提交不编造时间。正式报名编号及生成时机待用户给规则。
