PRD｜散客合作伙伴管理

1. 文档信息

项目 内容
产品 程程票票务系统
功能 散客合作伙伴管理
版本 V1.0
当前范围 后台合作伙伴及账户财务管理、售票窗口“临时/长期合作伙伴”售票、合作伙伴散客订单详情
后续扩展 充值审核开关、预付款转挂帐

2. 需求背景

当前散客挂帐在系统中仅记录支付方式和金额，无法识别具体挂帐对象、对接负责人及后续账户资金变化。需要参考团队旅行社账户的基础能力，为散客企业、个人及临时客户建立合作伙伴档案和账户基础数据，为后续挂帐、预付款、充值、资金流水及售票窗口能力提供支撑。

3. 产品入口与菜单规划

3.1 后台管理

合作伙伴管理
├─ 合作伙伴管理
├─ 合作伙伴账户管理
│  ├─ 挂帐管理
│  └─ 预付款管理
├─ 充值申请
└─ 资金流水

报表中心
└─ 散客挂帐相关报表

后台“合作伙伴管理”菜单承载合作伙伴档案、账户、充值和流水管理；“报表中心”属于后台入口，散客挂帐相关报表纳入本期，详细指标、筛选项和页面方案待后续讨论确认。

3.2 售票窗口与订单入口

售票窗口
└─ 售票
   ├─ 散客票
   ├─ 团队票
   ├─ 临时/长期合作伙伴（本期新增）
   └─ 挂单列表

后台订单中心/售票窗口
└─ 散客订单管理
   └─ 散客订单详情（本期增加合作伙伴信息及挂帐回款状态）

“临时/长期合作伙伴”仅是售票窗口中的售票模式，不归入后台“合作伙伴管理”菜单；该模式不支持挂单操作。

3.3 本期原型覆盖范围

本期原型覆盖以下两套操作端：

  • 后台管理端：合作伙伴管理、合作伙伴账户管理（挂帐管理、预付款管理）、充值申请（账户充值、其他收入）、资金流水，以及相关新增、编辑、查看、额度记录、充值回款和页面跳转交互。
  • 售票窗口端：“临时/长期合作伙伴”售票页、选择合作伙伴、公共临时客户快捷选择、支付订单确认、余额及额度校验。
  • 后台订单端：合作伙伴散客订单详情，展示合作伙伴信息；挂帐订单额外展示挂帐回款状态。
  • 报表中心的散客挂帐相关报表属于本期范围，详细方案与原型待后续讨论后补充。

3.4 总体业务流程图

总体业务流程图已在本页上方以可放大图片展示；Mermaid 源码收纳在图片下方的折叠代码框中。

4. 核心对象

4.1 合作类型

合作类型同时也是主账户类型：

  • 企业
  • 个人
  • 临时客户

企业和个人属于固定合作伙伴；临时客户为系统中唯一的公共合作伙伴，由管理员首次手动创建一次。

4.2 账户结构

创建合作伙伴成功后，系统自动生成唯一账户号和对应子账户：

类型 自动生成子账户 默认支付方式范围
企业 挂帐、预付款 挂帐、预付款
个人 挂帐、预付款 挂帐、预付款
临时客户 仅挂帐 固定为挂帐

账户号由系统生成，新增时显示“-”，查看和编辑时展示真实账户号且不可修改。

5.1 页面结构

页面按票务系统现有列表页结构展示：

  1. 顶部系统页签
  2. 面包屑
  3. 条件筛选区
  4. 页面操作区
  5. 合作伙伴表格
  6. 分页

5.2 筛选条件

合作伙伴名称 文本框 支持模糊搜索
支付方式 下拉单选 挂帐、预付款
对接负责人 文本框 输入员工名或手机号，按已保存的对接负责人模糊搜索，不使用下拉选择
状态 下拉单选 启用、禁用

操作包括“查询”和“重置”。

5.3 页面按钮

  • 新增
  • 导出

“新增、导出”按钮位于筛选区下方、表格上方，并在页面操作区最右侧对齐。

5.4 列表字段

字段 说明
合作类型 合作类型，同时为主账户类型
合作伙伴名称 全系统唯一
账户号 创建成功后由系统自动生成
默认支付方式 挂帐或预付款
联系人 合作伙伴外部联系人

5.5 操作逻辑

查看

点击“查看”后打开与新增页相同结构的弹窗表单：

  • 弹窗标题为“查看合作伙伴”。
  • 加载合作伙伴全部资料。
  • 所有字段只读，不允许修改。
  • 账户号展示系统生成的真实账户号。
  • 弹窗底部仅展示“关闭”按钮。

编辑

点击“编辑”后打开与新增页相同结构的弹窗表单：

  • 弹窗标题为“编辑合作伙伴”。
  • 默认加载合作伙伴已有资料。
  • 合作类型只读，不允许修改。
  • 账户号只读，不允许修改。
  • 允许修改合作伙伴名称、联系人、联系电话、对接负责人、默认支付方式、状态和备注。
  • 企业、个人可在“挂帐、预付款”之间修改默认支付方式。
  • 临时客户的默认支付方式固定为“挂帐”，不可修改。
  • 合作伙伴名称保存前去除首尾空格，并重新校验全系统唯一。
  • 对接负责人新增选择范围仅包含启用员工；原对接负责人后续被禁用时，编辑页仍允许回显和保留。
  • 保存成功后更新“更新人”和“更新时间”，不重新生成账户号，不新增、删除或重建子账户。

默认支付方式允许实时修改，只影响售票窗口选择合作伙伴时默认选中的支付方式，不调整余额、不产生资金流水、不影响历史订单。

启用/禁用

  • 当前状态为“启用”时，操作列显示“禁用”。
  • 当前状态为“禁用”时，操作列显示“启用”。
  • 操作前展示确认弹窗。
  • 状态只影响该合作伙伴是否在售票窗口展示和可选，不影响历史数据查询。

确认文案：

  • 禁用：确认禁用该合作伙伴吗？禁用后，该合作伙伴将无法在售票窗口中选择。
  • 启用：确认启用该合作伙伴吗？启用后，该合作伙伴可在售票窗口中选择。

账户

点击“账户”跳转“合作伙伴账户管理”，同时携带：

  • 账户号
  • 默认支付方式

目标页面按照默认支付方式匹配“挂帐管理”或“预付款管理”标签，并只展示对应合作伙伴。

删除

  • 账户未产生充值、消费、退票记录时允许删除。
  • 任一子账户已产生充值、消费或退票记录时不允许删除。
  • 即使账户余额恢复为零，只要存在历史资金记录仍不允许删除。
  • 允许删除时，操作前提示“删除后无法恢复，确认删除该合作伙伴吗？”。
  • 删除成功后，合作伙伴档案及未产生业务的主账户、子账户一并删除。

不允许删除时提示：

该合作伙伴账户已产生资金记录，不允许删除，可将合作伙伴设置为禁用。

6. 新增合作伙伴

6.1 承载方式

按照票务系统轻量维护功能规范，点击“新增”后打开宽度为 600px 的弹窗表单。

6.2 表单字段

字段 控件 必填 展示与校验规则
类型 下拉单选 是 企业、个人、临时客户
合作伙伴名称 文本框 条件必填 企业、个人最多25个字符且全系统唯一；临时客户自动显示“公共临时客户”且不可修改
联系人 文本框 条件必填 企业、个人必填，最多15个字符；临时客户不展示
联系电话 文本框 条件必填 企业、个人必填，最多15个字符；临时客户不展示
对接负责人 可搜索下拉单选 条件必填 企业、个人必填，仅查询启用员工；临时客户不展示
默认支付方式 下拉单选 条件必填 企业、个人必填；临时客户不展示，系统固定为挂帐
状态 下拉单选 条件必填 企业、个人必填，新增时默认选择“启用”；临时客户不展示，系统固定为启用
账户号 只读文本 否 企业、个人新增时显示“-”；临时客户不展示，保存后自动生成；具体编码格式由开发按系统现有规则实现
备注 多行文本框 否 补充合作信息，最多500字

6.3 字段规则

类型与默认支付方式

  • 未选择类型时，默认支付方式不可选择。
  • 选择企业或个人后，默认支付方式可选“挂帐、预付款”。
  • 选择临时客户后，合作伙伴名称自动填入“公共临时客户”并不可修改；联系人、联系电话、对接负责人、默认支付方式、状态和账户号均不展示，也不要求填写。
  • 临时客户由系统固定默认支付方式为“挂帐”、状态为“启用”，保存时自动生成账户号；备注的展示、填写和保存规则与企业、个人保持一致。
  • 已存在临时客户时，不允许再次创建临时客户。

合作伙伴名称

  • 最多25个字符。
  • 新增和编辑均校验全系统唯一。
  • 存储前去除首尾空格。
  • 去除首尾空格后不能为空。
  • 唯一性校验使用去除首尾空格后的名称。

校验提示：

  • 未填写：请输入合作伙伴名称
  • 超长：合作伙伴名称最多输入25个字符
  • 重复：合作伙伴名称已存在，请重新输入

联系人和联系电话

  • 均为必填文本框。
  • 最多15个字符。
  • 存储前去除首尾空格。
  • 联系电话允许手机号、座机号及短横线。

对接负责人

数据来源：

系统 → 员工管理 → 员工管理

只获取启用员工，下拉展示“员工名 + 手机号”，支持按员工名、手机号模糊搜索，不展示部门。

保存时只记录：

  • 员工名
  • 手机号

不关联员工ID，只记录员工名和手机号。

状态

  • 下拉单选。
  • 可选启用、禁用。
  • 只影响售票窗口是否展示该合作伙伴。

账户号

  • 新增时显示“-”。
  • 不允许输入或修改。
  • 保存成功后由系统自动生成。

6.4 保存逻辑

点击“保存”：

  1. 校验全部必填字段。
  2. 对文本字段去除首尾空格。
  3. 校验合作伙伴名称全系统唯一。
  4. 类型为临时客户时，校验系统不存在其他临时客户。
  5. 创建合作伙伴档案。
  6. 自动生成主账户及唯一账户号。
  7. 企业、个人生成挂帐和预付款子账户；临时客户只生成挂帐子账户。
  8. 更新人记录当前操作账号对应的员工名。
  9. 更新时间记录为当前时间。

合作伙伴、主账户和子账户必须在同一业务事务中创建；任一步骤失败，不保留本次新增数据。

7. 查看与编辑表单

7.1 承载方式

查看和编辑均使用与新增相同的600px弹窗表单，字段顺序保持一致。

7.2 字段权限

字段 查看页 编辑页
类型 只读 只读
合作伙伴名称 只读 可编辑
联系人 只读 可编辑
联系电话 只读 可编辑
对接负责人 只读 可编辑
默认支付方式 只读 企业、个人可编辑；临时客户只读
状态 只读 可编辑
账户号 只读 只读
备注 只读 可编辑

7.3 编辑保存逻辑

  1. 按新增页相同规则校验必填项、字符长度及联系电话格式。
  2. 文本字段存储前去除首尾空格。
  3. 合作伙伴名称排除当前记录后校验全系统唯一。
  4. 保存合作伙伴档案修改。
  5. 更新人记录当前操作账号对应的员工名。
  6. 更新时间记录为当前时间。
  7. 不修改账户号和既有子账户结构。
  8. 默认支付方式变更不产生资金流水，不改变余额和历史订单。

8. 合作伙伴账户管理

8.1 页面与标签

页面名称为“合作伙伴账户管理”，包含两个标签：

  • 挂帐管理
  • 预付款管理

从左侧菜单直接进入时，默认打开“挂帐管理”并查询全部挂帐账户。

从合作伙伴管理列表点击“账户信息”时，携带账户号和默认支付方式：

  1. 根据默认支付方式打开对应标签。
  2. 将账户号回填到筛选条件。
  3. 自动执行查询，等同于用户填写账户号后点击查询。
  4. 用户可修改或清除筛选条件；重置后查询当前标签全部账户。
  5. 每次切换标签均清空所有筛选条件并查询目标标签全部账户。

参数异常规则：

  • 标签参数缺失或无法识别时默认打开挂帐管理。
  • 账户号不存在或合作伙伴已删除时，保留账户号条件并显示暂无数据。
  • 禁用合作伙伴仍可正常查询和展示。
  • 在预付款管理查询临时客户账户号时显示暂无数据。

8.2 账户号与子账户

  • 企业、个人只有一个对外展示的主账户号。
  • 挂帐和预付款子账户共用对外账户号，系统内部通过“账户号＋子账户类型”区分。
  • 企业、个人分别出现在挂帐管理和预付款管理中，两个标签展示相同账户号。
  • 临时客户仅有挂帐子账户，只出现在挂帐管理。

8.3 固定合作伙伴与临时客户

以下客户应建立企业或个人固定合作伙伴账户：

  1. 长期合作企业。
  2. 长期合作个人。
  3. 多次到访或多次消费客户。
  4. 一次性支付金额较大、当次未消费完，需要保留余额供后续消费的客户。

固定合作伙伴同时生成挂帐和预付款子账户。回款优先冲抵挂帐欠款，超过欠款的部分进入预付款账户，可以留存供后续消费。

一次性、零散、暂时无法明确为固定合作伙伴的客户统一归入公共临时客户账户：

  • 全系统仅有一个公共临时客户主账户。
  • 不设置预付款子账户，统一按挂帐处理。
  • 由业务员或相关责任人根据实际到账情况平帐。
  • 回款金额不得超过该具体临时客户的待平帐欠款。
  • 存在余额留存或持续合作需求时，必须转为企业或个人固定合作伙伴账户。
  • 挂帐管理只展示公共临时客户的一条汇总记录；具体平帐按临时客户欠款明细控制，不能按公共账户汇总欠款判断回款上限。

8.5 挂帐金额与额度

  • 挂帐金额使用负数口径。
  • 0.00表示无挂帐欠款，-100.00表示欠款100元。
  • 挂帐金额不允许为正数。
  • 消费使挂帐金额减少，回款和退款使挂帐金额向0恢复，最多恢复到0。
  • 金额统一保留两位小数并使用千分位展示。

额度限制禁用：

  • 不因额度不足拦截挂帐。
  • 未配置过额度时挂帐额度为0.00。
  • 曾配置过额度时保留原挂帐额度。
  • 可用挂帐额度显示“无限额”。

额度限制启用：

可用挂帐额度 = max（挂帐额度 + 挂帐金额，0）
  • 挂帐额度必须大于0，最多保留两位小数，不设置业务最大值。
  • 可用挂帐额度为0时不允许新增挂帐。
  • 允许将额度调低至当前欠款绝对值以下；不改变已有欠款，可用额度显示0，欠款回落至额度范围内前不允许新增挂帐。
  • 禁用额度限制时保留原额度，重新启用时默认沿用原配置。
  • 调整后额度与当前额度一致时不允许提交。

8.6 额度操作

“启用额度限制”和“调整额度”共用额度维护弹窗，展示：

  • 合作伙伴名称，只读
  • 账户号，只读
  • 当前挂帐金额，只读
  • 当前挂帐额度，只读
  • 调整后挂帐额度，必填且大于0
  • 调整原因，非必填

额度调整直接生效，不需要审核，不属于充值申请，不产生资金流水。保存前二次确认。

调整后额度低于当前欠款时提示：

调整后的挂帐额度低于当前欠款金额，保存后该合作伙伴将暂时无法继续挂帐，确认调整吗？

启用额度限制时提示：

确认启用额度限制吗？启用后，合作伙伴可用挂帐额度将根据挂帐额度和当前挂帐金额计算。

当前欠款超过拟启用额度时追加：

当前欠款已超过挂帐额度，启用后该合作伙伴将暂时无法继续挂帐。

禁用额度限制时提示：

确认禁用额度限制吗？禁用后，该合作伙伴挂帐将不再受额度限制，请谨慎操作。

8.7 额度记录

点击“额度记录”打开只读弹窗。顶部展示合作伙伴名称、账户类型、账户号、当前挂帐金额、当前挂帐额度和当前额度限制状态。

记录列表只展示三个字段：

  • 调整内容
  • 操作人
  • 操作时间

“调整内容”使用业务描述展示，不平铺调整前后字段。例如：

  • 挂帐额度由1,000.00元调整为2,000.00元
  • 额度限制由“禁用”调整为“启用”，挂帐额度由0.00元调整为1,000.00元
  • 额度限制由“启用”调整为“禁用”，原挂帐额度1,000.00元保留

存在调整原因时，在调整内容下一行展示“原因：具体原因”；未填写原因时不展示原因行。

创建挂帐账户时生成初始化记录；启用、禁用、调整均生成记录。启用时同时修改额度只生成一条启用记录。记录按操作时间倒序分页展示，不允许修改或删除。

9. 充值申请

9.1 当前流程

  • 本期不设充值审核，提交后直接处理。
  • 后续可增加“是否开启充值审核”设置，但不属于当前范围。
  • 充值、账户金额变更、订单平帐及剩余金额处理必须作为一个完整事务执行。
  • 当前只有“充值成功”一种充值状态。全部业务处理成功后才生成充值记录；任一环节失败则整体回滚且不生成充值记录。
  • “充值提交、充值失败”仅在后续启用充值审核功能时考虑，本期不展示、不生成。
  • 充值申请页包含“账户充值、其他收入”两个标签，切换标签时清空上一标签的筛选条件和分页状态。
  • 账户充值类型为“挂帐回款、预付款、调账”。“挂帐回款”仅用于充值业务命名，不改变账户管理及支付方式中的“挂帐”名称。
  • “调账”只允许系统在已回款挂帐订单退款成功后自动生成，人工充值弹窗不可选择。

9.5 挂帐回款处理信息

充值类型选择“挂帐回款”后始终展示“挂帐回款处理信息”，根据充值金额与待平挂帐总额的比较结果切换状态。

充值金额小于待平挂帐总额

  • 必须选择本次平帐订单。
  • 订单只能整单选择，不支持订单部分回款。
  • 已选订单应回款合计不得超过充值金额。
  • 充值金额可以大于已选订单应回款合计，剩余部分必须由操作人选择转入预付款或计入其他收入。
  • 选择“转入预付款”时，一次提交拆分生成两条充值记录：挂帐回款记录金额等于本次实际平帐金额，预付款充值记录金额等于剩余到账金额；两条记录保留同一来源关联。预付款账户余额同步增加剩余到账金额。
  • 两条充值记录建立双向关联：两侧关联字段统一显示为“充值记录单号”，不在字段名称中区分来源或充值类型。挂帐回款详情在“剩余到账金额/处理去向”后展示关联充值记录单号；预付款充值详情在默认备注“由挂帐回款剩余金额自动转入预付款”下展示关联充值记录单号。单号均可点击查看对应充值详情，并提供复制操作。

公共临时客户特殊规则

  • 公共临时客户无论充值金额与待平挂帐总额的大小关系如何，每次挂帐回款都必须进入“选择待回款订单”弹窗并至少选择一笔订单，不允许自动平清全部订单。
  • 充值金额必须大于或等于已选订单应回款金额；小于已选金额时不允许提交。订单仍按整单回款，不支持部分回款。
  • 充值金额等于已选订单应回款金额时，只生成挂帐回款记录。
  • 充值金额大于已选订单应回款金额时，差额为剩余到账金额；因公共临时客户没有预付款账户，剩余金额处理方式只能选择“计入其他收入”，不能转入预付款。
  • 出现剩余到账金额时，在处理方式下方展示提示：“公共临时客户没有预付款账户，本次多余款项只能计入其他收入。如游客希望将多余款项留作下次使用，请先按已选订单金额完成挂帐平帐，再为游客建立企业或个人固定合作伙伴账户，并将剩余款项充值至该游客的预付款账户；请勿在公共临时客户账户中留存余额。”
  • 公共临时客户合作伙伴档案不保存默认对接负责人。订单维度的对接负责人由售票窗口收银人员在下单时人工填写，具体交互在售票窗口方案中确认。

充值金额等于待平挂帐总额

  • 不需要选择订单。
  • 提交后自动平清全部未回款订单，全部转为“已回款”。
  • 平帐后挂帐金额为0。

充值金额大于待平挂帐总额

  • 不需要选择订单，自动平清全部未回款订单。
  • 剩余到账金额不默认处理，操作人必须人工选择“转入预付款”或“计入其他收入”。
  • 临时客户没有预付款账户，剩余金额只能计入其他收入。

9.6 待回款订单

“选择待回款订单”作为充值申请的子弹窗，弹窗及遮罩层级必须始终高于充值申请弹窗，不能因打开顺序或重复操作被父弹窗遮挡。

  • 订单回款状态只有“未回款”和“已回款”，不支持部分回款。
  • 不在订单上新增持续维护的“待回款金额”字段。
  • 未回款订单当前应回款金额 = 订单总金额 - 已生效的正常退款 - 已最终确认的强制退票退款。
  • 未回款订单全部退款后应回款金额为0，不再进入待回款订单列表。
  • 一个订单可包含多个票型，待回款订单弹窗按订单展示一行，不允许按票型勾选。
  • 订单列表展示订单号、下单时间、订单总金额、已退款金额、本次应回款金额；不直接展示票型摘要。
  • 弹窗宽度应满足订单信息横向展示，并提供订单号、下单时间、对接负责人三个筛选条件；订单号支持模糊查询，下单时间可输入日期或时间关键词查询，对接负责人支持输入员工名或手机号模糊查询。
  • 待回款订单列表增加“对接负责人”字段，展示订单创建时保存的员工姓名和手机号；该字段取订单历史记录，不取合作伙伴档案的当前负责人。
  • 每行支持展开查看票型信息。展开区域不重复展示“票型明细”标题和序号，每个票型直接单独一行并允许自然换行，内容宽高撑满展开区域，兼容单个票型名称最长100个字符、单个订单最多5种票型的场景。
  • 订单号以链接形式展示，点击后在新页面打开对应订单详情页。
  • 待回款订单按10条/页分页，订单数量较多时表格内容区支持纵向滚动。
  • 无论逐笔勾选还是点击表头全选，系统都必须校验已选订单应回款合计不得超过本次充值金额；超额订单不得被选中，不能仅依赖单行复选框的禁用状态。
  • 提交前后端必须重新校验订单回款状态、退款金额、应回款金额及并发锁定，不得只依赖前端校验。

9.7 充值详情

点击“查看”打开只读弹窗，展示充值基础信息、申请人、对接负责人历史快照、充值状态、备注和附件。

  • 备注说明独占一整行展示，长文本自动换行。
  • 充值相关资料独占一整行展示；有附件时展示附件名称及“查看”“下载”操作，无附件时展示“-”。
  • 详情弹窗在备注和附件数量正常时不显示内部滚动条；仅当整体内容超过浏览器可视区域时，由弹窗容器按系统公共规则处理滚动。
  • 挂帐回款详情额外展示本次平帐金额及关联订单；关联订单号以链接形式展示，点击后在新页面打开订单详情页。
  • 只有本次充值存在未用于平帐的剩余到账金额时，才展示“剩余到账金额”和“处理去向”；剩余金额为0时不展示这两个字段。

9.8 已回款挂帐订单退款自动调账

  • 合作伙伴挂帐订单保存挂帐回款状态“未回款、已回款”。
  • 未回款订单退款时只生成正常正数退款流水，减少动态应回款金额，不生成调账记录。
  • 已回款订单退款成功时，正常生成正数退款流水，同时由系统生成一条金额相同、方向相反的负数充值调账记录，使挂帐账户净变化为0。
  • 调账充值类型为“调账”，充值金额为退款金额负数，备注固定为“退款调账”，关联本次退款售后单号。
  • 调账记录申请人显示“系统自动”；对接负责人保存订单下单时记录的员工姓名和手机号；申请时间、完成时间均取退款成功时间；充值状态为“充值成功”。
  • 调账记录只在退款真正成功后生成。普通退票直接生效后生成；强制退票只有最终确认并退款成功后生成。审批中、拒绝、失败均不生成。
  • 同一已回款订单发生多次部分退款时，每张退款成功的售后单分别生成一条调账记录，不合并。
  • 调账详情展示售后单号，支持点击新页打开售后详情和复制。
  • 调账资金流水的主单据仍显示【充值记录单号】，售后单号在充值详情内追溯。
  • 未回款全额退款订单仍保持“未回款”，但动态应回款金额为0；仅在挂帐回款充值的待回款订单弹窗中，按“当前所选合作伙伴 + 支付方式为挂帐 + 回款状态为未回款 + 动态应回款金额大于0”查询可选订单。

9.9 其他收入充值

“其他收入充值”是独立财务入账记录，不关联合作伙伴账户，不改变挂帐金额、挂帐额度、可用挂帐额度或预付款余额。

  • 仅当挂帐回款存在剩余到账金额且操作人选择“计入其他收入”时联动生成，不提供单独新增入口。
  • 一次操作分别生成挂帐回款记录和其他收入记录，两条记录各自生成独立充值记录单号，并在数据层双向关联。
  • 挂帐回款详情展示其他收入充值记录单号；其他收入详情展示来源挂帐回款充值记录单号。两侧单号均支持点击查看对应详情和复制。
  • 其他收入备注默认为“由挂帐回款充值记录单号XXX的剩余到账金额计入其他收入”。
  • 两条记录的申请人、对接负责人和时间取同一次操作信息；对接负责人保存员工姓名和手机号历史快照。
  • 两条记录及账户处理必须作为一个完整事务，任一环节失败则整体不生成、不改变账户数据。
  • 本次充值资料可在两条详情中查看和下载，底层可关联同一组附件。

其他收入充值筛选条件：合作伙伴名称、充值记录单号、申请人、对接负责人、申请时间。列表默认按申请时间倒序，支持查询、重置和按当前条件导出全部命中数据。

列表字段：充值记录单号、合作伙伴名称、充值类型（固定“其他收入”）、充值金额、申请人、对接负责人、申请时间、充值状态（固定“充值成功”）、完成时间、查看。

10. 资金流水

10.1 页面结构与筛选

资金流水以合作伙伴维度统一查询，标签为“全部、充值、消费、退款、其他收入”。“全部”包含该合作伙伴名下挂帐、预付款账户的充值、消费、退款及不入账户的其他收入，便于统一查询和导出。

筛选条件：合作类型、合作伙伴名称、账户号、账户类型（挂帐、预付款）、对接负责人、发生时间、单据编号。对接负责人统一使用文本框，输入员工名或手机号进行模糊搜索，不使用下拉选择。

  • 筛选区默认收起且严格展示两行：第一行展示合作类型、合作伙伴名称、账户号；第二行展示账户类型、发生时间，查询、重置及“展开”固定在第二行最右侧。
  • 默认隐藏对接负责人和单据编号。点击“展开”后显示第三行：对接负责人位于第三行首位，单据编号紧随其后；按钮文字变为“收起”。点击“收起”后重新隐藏第三行。
  • 发生时间默认值为当前时间向前一个月至当前时间。点击重置或切换标签后恢复该默认时间范围。
  • 切换到“其他收入”标签时隐藏账户号和账户类型筛选项；切换标签时清空其他筛选条件并恢复默认时间范围。

10.2 统一列表

列表字段顺序：合作类型、合作伙伴名称、账户号、处理操作、账户类型、金额（元）、单据编号、对接负责人、发生时间。默认按发生时间倒序。

  • 充值：处理操作显示“充值”，金额为正数；系统自动调账为负数。
  • 消费：金额为负数。
  • 退款：金额为正数。
  • 账户类型用于区分挂帐、预付款。
  • 充值显示【充值记录单号】，点击查看充值详情并支持复制。
  • 消费显示【订单号】，点击新页打开订单详情并支持复制。
  • 退款显示【售后单号】，点击新页打开售后详情并支持复制。
  • 挂帐回款剩余金额转入预付款时，两条充值记录分别生成两条资金流水，不合并。
  • 对接负责人保存业务发生当时的员工姓名和手机号，后续合作伙伴负责人变化不回改历史流水。
  • 列表不展示“变动后账户金额”。

10.3 其他收入流水

其他收入虽然不影响合作伙伴账户，但作为独立财务流水进入资金流水。

  • “其他收入”标签字段为合作伙伴名称、处理操作（固定显示“其他收入”）、金额（元）、单据编号（充值记录单号）、发生时间。
  • 单据编号支持查看其他收入详情和复制。
  • 在“全部”标签中，其他收入的账户号、账户类型等无数据字段统一显示“-”。
  • 其他收入不改变任何账户数据。
  • 标签切换沿用票务系统资金流水的分段按钮样式，选中项为蓝底白字。标签行右侧提供蓝色“导出”和普通“配置列”按钮。

10.4 导出

按当前标签及全部筛选条件导出全部命中数据，不只导出当前页；不导出操作列。“全部”标签导出包含其他收入记录。

11. 权限、日志与数据约束

  • 页面按钮及操作后续接入系统菜单与按钮权限。
  • 所有新增、编辑、启停、删除操作记录操作人、操作时间和变更内容。
  • 账户号创建后不可修改。
  • 已产生资金记录的合作伙伴不可删除。
  • 禁用合作伙伴不影响历史订单、账户及资金流水查询。

12. 售票窗口

12.1 页面入口与票型范围

售票窗口“售票”页面标签依次为“散客票、团队票、临时/长期合作伙伴、挂单列表”。本功能使用“临时/长期合作伙伴”标签，整体复用团队票的左右布局。左侧依次展示合作伙伴、门票分类、票型名称、活动标签、价格类型和查询条件，不展示导游、团队类型等团队专属字段。

“临时/长期合作伙伴”售票模式不支持挂单，页面不提供挂单操作按钮；“挂单列表”为售票窗口原有独立查询标签，不代表该模式允许新增挂单。

票型范围完全沿用散客票逻辑，只展示当前售票窗口允许销售的散客票。

12.2 选择合作伙伴

售票页左侧第一行展示一个较长的“请选择合作伙伴”输入区域，并在其右侧并列展示“临时客户”快捷选项。合作伙伴与临时客户必须二选一：

  • 点击“请选择合作伙伴”打开选择弹窗，弹窗只查询启用状态的企业、个人合作伙伴，不展示公共临时客户。
  • 点击“临时客户”无需打开弹窗，直接选中系统唯一的公共临时客户并刷新右侧信息。
  • 选中企业或个人后取消“临时客户”的选中状态；点击“临时客户”后清空左侧已选择的企业或个人，二者不能同时生效。

筛选条件：

  • 合作伙伴名称：支持名称模糊搜索。
  • 联系人/电话：同一文本框支持联系人或联系电话模糊搜索。
  • 对接负责人/电话：同一文本框支持员工姓名或手机号模糊搜索。

列表字段：单选、合作类型、合作伙伴名称、对接负责人（员工名+手机号）、联系人（联系人+电话）、账户余额、挂帐额度、可用挂帐额度。

  • 默认每页10条。
  • 企业、个人按更新时间倒序排列。
  • 选择并确定后，合作伙伴名称回填左侧输入框，合作伙伴名称、对接负责人、联系人、预付款余额和可用挂帐额度同步展示在右侧。
  • 更换合作伙伴时，原支付方式、临时客户对接负责人及账户展示数据全部清空后重新加载。

12.3 合作伙伴信息与支付方式

右侧合作伙伴信息展示：合作伙伴、对接负责人、联系人、账户余额、可用挂帐额度。

  • 企业、个人默认带出档案中的默认支付方式，可在挂帐和预付款之间切换；切换只影响当前订单。
  • 公共临时客户只允许挂帐，支付方式不可切换。选中公共临时客户后，右侧合作伙伴信息区只展示“合作伙伴：公共临时客户”“可用挂帐额度”和“对接负责人”输入框，不展示固定合作伙伴的对接负责人、联系人和账户余额字段。
  • 公共临时客户的“对接负责人”输入框支持模糊搜索全部启用员工，选项显示员工名+手机号；未找到时允许直接输入任意内容，不限定输入格式。该内容只写入当前订单，不回写员工管理或合作伙伴档案。

12.4 支付订单确认

点击售票主页面“确认下单”只打开“支付订单确认”弹窗，不创建订单、不调整账户。

  • 弹窗自动带入主页面支付方式。
  • 企业、个人仅展示挂帐、预付款两项并允许再次切换。
  • 公共临时客户只展示挂帐且不可切换。
  • 最终以弹窗内确认出票时选择的支付方式为准。

点击“确认出票”时执行最终校验：

  • 合作伙伴已禁用：提示“合作伙伴已禁用，不允许下单。”
  • 当前支付方式对应账户已禁用：提示“账户已禁用，不允许使用对应支付方式。”
  • 公共临时客户未填写对接负责人：提示“请填写对接负责人后再下单。”
  • 预付款余额不足：提示“对不起，该合作伙伴预付款余额不足，请联系【当前合作伙伴对接负责人姓名】充值。”
  • 挂帐额度限制禁用时不校验可用额度，允许继续挂帐。
  • 挂帐额度限制启用且可用挂帐额度不足：提示“对不起，该合作伙伴可用挂帐额度不足，请联系【当前合作伙伴对接负责人姓名】调整挂帐额度或处理欠款后再试。”
  • 公共临时客户提示中的负责人取当前订单选择或手工填写的对接负责人。

本期不支持组合支付，预付款必须足额支付。所有校验均在确认出票时重新读取最新状态、余额和额度，不能只使用打开弹窗时的数据。

12.5 下单及资金处理

校验通过后，在同一事务中完成订单创建、账户处理、消费资金流水生成和出票；任一步骤失败均整体回滚。

  • 预付款：预付款余额扣减订单金额，生成账户类型为预付款、金额为负数的消费流水，单据编号关联订单号。
  • 挂帐：挂帐金额扣减订单金额，生成账户类型为挂帐、金额为负数的消费流水，单据编号关联订单号；订单挂帐回款状态初始化为“未回款”。

12.6 散客订单详情

合作伙伴订单进入散客订单管理，订单基础信息中的团散类型显示“散客”。订单支付信息中的支付类型按确认出票时最终支付方式显示“挂帐”或“预付款”。

原团队基础信息区域替换为“合作伙伴信息”，字段为：

  • 合作类型
  • 合作伙伴名称
  • 合作伙伴账户号
  • 对接负责人
  • 联系人
  • 联系电话
  • 挂帐回款状态

挂帐回款状态仅在支付类型为挂帐时展示，状态为未回款或已回款；预付款订单不展示该字段。

12.7 冲红限制

合作伙伴产生的散客订单本期暂不允许发起冲红申请，包括使用预付款和挂帐支付的订单。

  • 本规则仅涉及售票窗口“统计 → 销售记录/冲红申请”页面；后台没有合作伙伴订单的冲红申请入口，不增加后台判断或提示。
  • 销售记录列表判断订单是否为合作伙伴订单：若是，操作列只显示“查看”，不显示“冲红申请”按钮。
  • 非合作伙伴订单继续沿用现有冲红申请按钮及处理逻辑。
  • 因合作伙伴订单不展示“冲红申请”按钮，不存在点击后的拦截提示。
  • 因冲红会改变原订单支付方式并影响预付款、挂帐金额及资金流水，在完整的账户冲销和流水关联方案确认前不开放该能力。
  • 本限制不影响订单按既定售后退款流程处理。
