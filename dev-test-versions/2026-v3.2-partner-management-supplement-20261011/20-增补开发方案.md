# V3.2上线前增补｜本次新增与修改

更新：2026-10-29。仅写本次增补，未列出的原功能保持不变。与原V3.2合并上线，不覆盖历史基线。01—19号文件保留讨论依据，本文件为当前增量方案。

## 1. 本次共用变化

- 窗口增加公共临时客户回款、临客转长期；增加待认领客户入款、整笔来源付款、先找款再选订单回款。
- 标签顺序：合作伙伴充值 → 账户充值记录 → 其他收入记录 → 公共临时客户回款 → 充值报表。后台对帐单仍在报表中心。
- 待认领客户后台唯一创建，只建预付款账户、初始余额0；不能售票、透支、作为迁移目标、后台充值或导入。
- 本期不做录错撤销、来源部分使用、不同打款合并抵缺、补收差额、混合付款；窗口不开放人工调账。

**支付日期（W02／W03／W06新增）：**默认当天、可补过去、禁止未来，保存当日00:00:00；申请／完成时间仍为实际操作时刻。

**支付配置联动：**普通方式按景区、场景和操作主体资格取有效配置并排序。扫码付／银行卡按账号或设备绑定取资源；固定资源只读，多资源可搜索切换。柜台编码／POS编号由资源自动带出、必填且只读。缺绑定、默认失效或编号空时禁止确认，可人工换其他有效方式，不自动切现金。保存资源ID、名称和编号快照，保留前导零。

**待认领付款：**内部来源入口，不加入普通支付配置枚举，不再次扫码；沿用来源原方式、资源及编号，使用支付日期不得早于来源日期。

## 2. 窗口页面增量

### W00 原售票页关联

路径：售票窗口 → 售票 → 临时／长期合作伙伴。

仅将原长期伙伴充值入口接本次W02，返回不清购物车；客户选择排除待认领。不重做原售票字段和下单流程。

### W01 合作伙伴充值列表

路径：售票窗口 → 合作伙伴 → 合作伙伴充值。

新增唯一“待认领客户”行，默认预付款，仅查看、充值。无联系人／档案负责人显示“—”，不能把某笔入款负责人写回共享档案。其他原筛选及普通伙伴操作不改。

### W02 长期合作伙伴充值弹窗

路径：W01长期伙伴行 → 充值；或W00原充值入口。

- 新增支付日期、配置资源及“待认领账户”付款。
- 选待认领打开W04；来源摘要显示单号、金额、原方式及编号，可重新选择。
- 来源金额S＝客户充值C＋其他收入I，默认C=S、I=0；可调整，均不得负，合计必须S。C=0不生成零元客户充值。
- 目标账户及负责人沿用原长期伙伴规则；其他收入归公司，不入客户余额。
- 成功关联来源、客户充值、公司收入及负转出，见第4节。

### W03 待认领入款弹窗

路径：W01待认领客户行 → 充值。

新增特殊表单：只读合作类型／名称、账号／预付款、当前余额；支付日期、本笔负责人、客户／付款人、充值金额、整行备注、普通支付区及合计。

日期、金额、支付必填；金额>0、最多两位小数。负责人可按姓名／手机选择，选填；付款人、备注选填，备注最多500字。现金校验实收与找零，扫码／银行卡按配置资源。

不出现其他收入、订单选择或待认领自付。全额入预付款，生成成功未使用充值及正数流水，保存当前申请人／售票员和窗口；负责人只属于本笔入款。

### W04 来源选择与待认领款回款

路径：W02／W06 → 待认领账户；先找款入口：W05 → 待认领款回款。

**普通选择：**仅成功未使用的原入款，每次一笔、整笔一次用完，不拆分／合并／补收。单号可查看。查询顺序：充值金额精确值、支付日期范围、负责人、原充值售票员、支付方式、柜台号／POS编号；充值单号放后。不限当天／当前售票员。取消不覆盖原来源，切普通支付清来源；提交再次核验未使用。

**先找款再找订单：**一次单选一笔成功未使用的来源，再选择对应的一笔或多笔待回款订单，最后进入原W06确认回款。不支持多选来源、队列、自动处理下一笔或批量结果页。可重新选择款项；取消不扣款。

**选择订单：**一行综合搜索客户／订单／负责人，后接下单时间、应回款精确金额、查询／重置。订单号可查看；保留应回款、订单总额、已退款、下单时间，金额表头单行且去“（元）”。跨页保留选择，页脚合计及清空选择。

- 来源少于所选订单净额：立即提示并禁用下一步，不能合并其他款项补足。
- 等于直接确认；大于转W06主动确认其他收入。
- 成功后关闭弹窗并刷新列表，再次处理须重新进入。失败保留当前输入，来源不扣款、订单不结清；提交仍重新核验来源和订单，防止重复使用。

### W05 公共临时客户回款页面

路径：售票窗口 → 合作伙伴 → 公共临时客户回款（其他收入记录后）。

新增订单页，回款状态下拉切待回款／已回款，不增加子标签。

- 查询首行：客户、负责人、下单时间；之后订单号、原售票员。已回款另有回款单号、操作人、来源、支付日期。条件全展示，不留无效展开／收起。
- 客户／负责人按订单快照模糊查，负责人兼容姓名、手机及手填文字；原售票员不默认当前人。日期初次不限，自动查询；查询回第一页，重置清条件。切视图／改变条件清选择，表头全选仅当前页。
- 候选仅公共临客挂帐、未回款且净额>0；应回款＝订单总额−成功退款，排除全退／迁移／结清。
- 待回款列表：勾选、客户、负责人、原售票员、订单号、应回款、订单总额、退款、下单时间、状态。
- 已回款展示本单结清快照、回款单号、操作人、来源、方式、编号及支付日期；不重复显示主记录总金额，不提供再次回款／迁移。
- 勾选后回款和迁移蓝色启用、待认领款回款禁用；未勾选反之。
- 待回款按下单时间倒序；已回款按支付时间倒序，相同再下单时间倒序，排序后分页。
- 订单号开原详情，回款单号开充值详情。后台回款也可查询，但不能冒计为某售票员窗口收款。

### W06 公共临客回款弹窗

路径：W05勾选 → 回款；或W04先选一笔款 → 选择订单 → 下一步。

新增窗口入口，沿用后台临客结清逻辑；带入已选订单及应回款，明细保留总额／退款。增加窗口普通支付区、支付日期、当前售票员／窗口。

设净应回款D、登记收款S：

| 条件 | 处理 |
| --- | --- |
| S<D | 提示差额、禁止提交，不允许部分结清 |
| S=D | 客户充值D，所选订单全部结清 |
| S>D | 主动选择差额计其他收入，不设默认；客户入D，公司收入S−D |

待认领S由来源带入只读，同样逐笔校验。现金找零与公司收入分别处理。提交重读订单状态／退款；变化要求重新查选。成功退出候选、清选择，取消不写账。

### W07 多订单不一致确认

路径：W06或W08所选订单客户／负责人不一致时。

提示核实同一客户，允许人工确认继续，不硬性禁止；保存确认人、时间、订单快照，改选择使确认失效。不能绕过金额、日期或订单状态校验。

### W08 迁移第一步

路径：W05勾选 → 临时客户转合作伙伴。

窗口新增入口，带入待迁移订单及净迁移金额，订单可查看；不作为回款。信息不一致走W07。

### W09 迁移目标方式

路径：W08 → 下一步。

可新建长期伙伴或选已有启用企业／个人，排除公共临客、待认领、禁用对象。保存本次操作售票员／窗口，原开单售票员不改。

### W10 新建迁移目标

路径：W09 → 创建新的长期合作伙伴。

复用原建档字段及校验，不重新定义普通建档规则。新档案、双账户和迁移一起提交，失败不留空档案；按默认账户承接消费。

### W11 已有迁移目标

路径：W09 → 选择已有合作伙伴。

实时带入所选档案、默认账户、挂帐／可用额度及预付款余额，不另造资料。

**本次规则变更：迁移不校验目标余额／额度充足，即使限制开启也不因此拦截。**已经发生的消费归属转移，后续新消费仍按原额度规则。原迁移消费、退款及调账-往来保持；不标已回款、不入窗口充值报表。

### W12 账户充值记录列表

路径：售票窗口 → 合作伙伴 → 账户充值记录。

原列表纳入临客充值、待认领入款、“调账-认领款转出”；不新增“回款”处理类型。待认领原单可识别未使用／已使用，保留已用历史但退出可选来源。

取消无效展开／收起；充值及收入按支付时间倒序、再完成时间倒序，无支付时间的系统迁移以完成时间参与排序。其他原字段不重写。

### W13 充值详情

路径：W12查看；W05回款单号；W04来源单号。

只补本次来源、转出、目标及其他收入关联，沿用历史单号互查方式，放备注／关联处理区，不单设“待认领款来源”业务字段。备注有正文或关联时不另显“—”；备注、资料各占整行，边框连续。

### W14 其他收入列表

路径：售票窗口 → 合作伙伴 → 其他收入记录。

纳入临客超额及待认领分配产生的公司收入，不入客户余额；账号／账户类型沿用原其他收入口径。取消无效展开／收起，排序同W12。

### W15 其他收入详情

路径：W14查看；W13收入单号。

只补本次来源／目标关联，复用原详情；正文及关联不叠加占位“—”。

### W16 窗口充值报表

路径：售票窗口 → 合作伙伴 → 充值报表。

原报表增加临客充值及收入、待认领入款正数、认领转出负数。不纳入迁移调账-往来、人工调账或退款自动调整，不另做回款报表。

- 按填写支付日期、实际操作售票员／窗口统计；原方式及编号归列。
- 分组按“合作类型＋合作伙伴名称＋对接负责人快照”；负责人不同（包括多个负责人组合不同）分别成组，不把公共临客与长期伙伴合并。组内再按处理操作＋账户类型汇总，连续明细合并前三列。
- 每个小组末尾均显示一行“合作伙伴小计”，只有一条明细也显示；小计文字不追加伙伴名称或负责人。小计累加该组金额及各支付列，末尾“总计”只累计原明细一次，不再累加小计。
- 现金、支付宝、微信各一列；银行卡按POS编号、扫码付按柜台号动态拆列，无发生额显示0.00。认领转出按负数进入原方式及编号列，不挪到其他支付列。
- 目标正数沿用目标负责人规则，来源负数保留原入款负责人，一来源一负数；两者可不同。临客主记录可显示多个订单负责人，订单各自保留；临客其他收入不分摊个人。
- 使用日目标充值＋其他收入−转出＝0；原实收只在原入款日计一次，主记录与订单明细不重复累加。
- 例：甲昨日入250，乙今日结临客200＋收入50；昨日甲＋250，今日乙＋200＋50−250＝0。

## 3. 后台页面增量

### B01 合作伙伴管理列表

路径：后台 → 合作伙伴管理 → 合作伙伴管理。

增加待认领类型、唯一行，仅查看／账户，无编辑、禁用、删除。其他伙伴不改。

### B02 新增合作伙伴

路径：B01 → 新增。

类型增加待认领客户；名称固定、账户类型固定预付款；隐藏普通联系人、电话、档案负责人、状态、余额及额度设置。备注选填，账号保存前“—”；固定启用、余额0，只建预付款，不生成入款。

按类型唯一创建，已有禁选、提交再校验；档案账户一起成功。切类型清除隐藏字段草稿及校验。

### B03 待认领档案查看

路径：B01待认领行 → 查看。

新增特殊只读展示；不能编辑成普通伙伴。每笔负责人独立保留，不回写档案。

### B04 预付款管理

路径：后台 → 合作伙伴管理 → 合作伙伴账户管理 → 预付款管理。

纳入待认领唯一账户，余额随入款／转出更新，始终不得负；不可关闭非负限制，无挂帐账户。

### B05 后台充值列表

路径：后台 → 合作伙伴管理 → 充值申请 → 账户充值。

读取窗口同一充值／转出记录，不复制入账；筛选及导出纳入待认领类型和转出操作。不新增回款来源列；申请人就是实际回款操作人。排序同W12。

### B06 后台新增充值

路径：B05 → 充值。

只改对象范围：排除待认领客户，保存也拒绝，不能仅隐藏选项；原后台长期／临客流程不改。

### B07 后台批量导入

路径：B05 → 批量导入。

新增拒绝待认领对象校验，不新增模板列，不提供后台待认领入款。导入弹窗沿用十一列模板，错误行显示拒绝原因；超过50条非空数据整份拒绝，不生成记录或流水。

### B08 后台充值详情

路径：B05查看；B11充值单号。

查看同一窗口结果，补来源／目标／转出关联，规则同W13；不单列“回款来源”／“待认领款来源”。实际申请人、售票员、窗口与窗口记录一致。

### B09 后台其他收入列表

路径：后台 → 合作伙伴管理 → 充值申请 → 其他收入。

纳入同一批新增公司收入，金额及关联与窗口一致，不重复入账、不入客户余额；排序同W12。

### B10 后台其他收入详情

路径：B09查看；B08收入单号。

只补本次来源／目标关联，复用原详情；备注关联不叠加占位“—”。

### B11 资金流水

路径：后台 → 合作伙伴管理 → 资金流水。

新增待认领入款＋S、“调账-认领款转出”−S；目标充值及收入按原类型。六个原标签不变，认领转出和调账-往来归调账，行内完整显示操作名。

发生时间取实际完成时刻，倒序；不取补录支付日期。原消费只更新回款状态，不删除历史、不重复消费。

### B12 原合作伙伴对帐单

路径：后台 → 报表中心 → 合作伙伴对帐单 → 按日／按月。

原报表新增待认领选项，不另建。选待认领时只将当日／当月消费改为当日／当月认领转出，列数、查询、导出不变。

原入款按原支付日计到款，来源负转出按使用支付日取绝对值计认领转出，不再重复计底部调账。目标只计客户充值，不含公司收入。其他原消费、退款、人数及余额口径不重写。

### R01 原订单详情关联

路径：本次列表／弹窗 → 订单号 → 原详情。

不改版。同步回款状态、结清关联或迁移伙伴／账户及追溯，原售票员不变。销售记录、退票页不新增页面，继续读取原订单结果。

## 4. 新增联动与保存

| 动作 | 必须一起关联更新 |
| --- | --- |
| 待认领入款S | 原充值＋S、预付款＋S、正流水、未使用、原日期和收款人报表 |
| 来源S用于长期充值 | C＋I=S；转出−S、源余额−S、来源已用、目标＋C及流水、同日正负报表 |
| 来源S结临客 | 净额D全部结清、充值D、收入S−D、转出−S、来源已用、账户流水及同日正负报表 |
| 普通支付结临客 | 充值D、收入S−D、逐单结清、原消费已回款、当前售票员／窗口及支付报表 |
