## 2. 替代本增补旧口径

| 旧表述 | 本次联动后的规则 |
| --- | --- |
| 五种支付全部固定显示、现金默认 | 从五种普通方式中按当前景区启用、充值／回款场景及原业务资格取交集，再按配置序号升序；新弹窗选本次候选第一项 |
| 收银员必填柜台号／POS编号 | 有效编号仍是提交必需信息，但由收款资源自动带出、只读，不由收银员手填 |
| 扫码付固定跟设备、银行卡固定跟账号 | 各自读取已保存归属，可跟当前收银账号或实际窗口设备；不是按支付方式写死 |
| 编号相同就足以关联资源 | 绑定及保存按稳定资源ID，编号为文本快照；不按名称或编号反推绑定 |
| 记录仅保存方式及编号 | 每笔扫码付／银行卡记录保存实际资源ID、名称、柜台编码／POS编号快照，后续改名改码不回写历史 |

固定资源灰显不可换；多资源默认必须有效，可在当前主体有效绑定内按资源名称搜索选择。缺默认不自动取首项，不跨主体兜底。现金／微信／支付宝隐藏资源区。

首次方式与首次资源是两件事：方式取过滤排序第一项，资源取该方式指定的有效唯一／默认资源。第一方式缺资源不能自动跳现金；在弹窗提示，允许收银员主动换方式。无可用方式／配置加载失败明确提示，不用写死现金伪装成功。有效手选不因重绘或仅排序变化而重置；失效后按公共规则重新选择并清理旧资源草稿。

## 4. 待认领来源的衔接边界

- “待认领账户”保留为本增补内部资金来源入口；支付配置最终白名单的充值／回款只有五种普通方式，不能未经确认把它加成第十种全局配置方式，也不能映射为普通预付款后重新扣款。
- 2026-10-26改为每次单选一笔来源，整笔使用、一条负数转出；目标保存来源当时资源快照，不解析本次主体绑定，不因原售票员不同而禁止选择。
- W04已取消多笔来源合选，不再存在跨资源合选的目标资源歧义；目标保存所选单笔来源的资源快照，不按当前配置反推历史。
- 既有“方式＋编号一致”规则不在本次默默升级或废除；当前配置失效是否影响历史已收款使用也不能机械套用新收款校验，须与来源使用规则分开。
