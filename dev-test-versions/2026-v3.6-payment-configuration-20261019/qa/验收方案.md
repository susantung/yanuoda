## 3. 执行流程与顺序

环境与基线确认 → 记录原配置/绑定 → 新建隔离测试数据 → 配置及资源校验 → 各窗口支付与排序 → 跨端逐笔回查 → 冲红申请/审核/再回查 → 内导结账补收/异常 → 同宽样式核验 → 恢复测试配置并回查 → 问题复测与验收结论。

依赖顺序：先验证配置与资源能保存、刷新、读取，再跑依赖它的支付；先成功生成新订单，再做冲红；先完成内导开单，再结账。不把同一订单重复用于互相冲突的分支，例如同意和驳回分别建单。

## 6. 每条用例怎么跑

每条执行至少记录：验收项/变体编号、版本、时间、景区、账号及实际设备、前置配置、单据编号、步骤、预期、实际、证据、结果、缺陷号。用例台账附82条原操作与预期，不另写一套互相冲突的规则。

1. 读对应页面及字段规则，记录本轮前置配置和原始金额/状态。
2. 从真实菜单进入，按变体操作；记录关键字段、候选全集和显示顺序，不能只截选中项。
3. 成功提交后刷新并跨端回查；若可查看授权响应/持久化数据，一并核对；只有UI证据时明确“跨端持久化回查”，不宣称已查数据库。
4. 按本轮范围验证取消和配置变更；失败、并发及聚合实际交易分支保留清单，本轮不执行。
5. 保存证据，填实际值；完成所有必测变体才判父项通过。任一失败为有问题；无失败但有依赖阻塞为阻塞；尚有未跑则仍未跑。

## 8. 问题池、证据与复测

功能用例统计与问题池分开：一条用例可关联多个问题，同一根因跨页面只建一个问题并列影响范围。样式问题也进入同一问题池，类型标为“页面样式”。

- 用例：未跑 / 通过 / 有问题 / 阻塞 / 后续验证 / 本轮不执行。后续验证为已确认延期范围，不作已执行结果。各分支独立回填；尚未执行不算阻塞。
- 问题：当前缺陷 / 待复测 / 已验证修复 / 方案调整后关闭 / 已撤销。只对实际复现建立缺陷；环境不可用记阻塞，不直接算功能缺陷。
- 优先级：P0为错账、串主体、重复收款、审核前生效等资金/数据风险；P1为关键链路、选择/校验、编号丢失或重要信息缺失；P2为次要交互/可用性；P3为不影响业务的视觉差异。以实际影响定级，不直接抄历史报告的等级。
- 缺陷记录：编号、类型/等级、涉及用例/页面、前置、复现步骤、预期、实际、单据号、截图/响应证据、首次/复测版本、状态与结论。
