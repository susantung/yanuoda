# 支付配置化｜全程流程图

版本：V1.4｜2026-10-19。节点对应[页面清单](01-页面清单.md)。仅展开本次新增/修改；原下单、支付和充值处理用一个节点表示，不重新定义。

## 一、全程总览

![支付配置化全程总览](assets/payment-overview.svg)

```mermaid
flowchart TB
  B01[B01/B02 配置启用、场景及统一资源规则] --> FILTER[K01 按场景过滤支付方式]
  B03[B03/B04/B05 维护资源名称及柜台编码/POS编号] --> OWNER{资源跟谁走}
  OWNER -->|设备| B07[B06/B07 窗口售票机绑定资源]
  OWNER -->|账号| B09[B08/B09 收银账号绑定资源]
  B07 --> K02[K02 确认弹窗按当前归属读取绑定]
  B09 --> K02
  FILTER --> W04[W01/W02 → W04 散客/团队确认]
  FILTER --> W12[W11 → W12 内导确认]
  FILTER --> W07[W05/W06 → W07 伙伴账户支付确认]
  FILTER --> W09[W05充值 / W08行内充值 → W09共用弹窗]
  K02 --> W04
  K02 --> W12
  K02 --> W09
  W04 --> CHECK[K03 本期配置及资源复核]
  W12 --> CHECK
  W09 --> CHECK
  CHECK --> ORIG[执行原下单、支付或充值处理；其他逻辑不变]
  W07 --> ORIG
  ORIG --> RECORD{本次是否扫码付或银行卡}
  RECORD -->|是| SNAP[每笔记录实际资源及柜台编码/POS编号]
  RECORD -->|否| UNCHANGED[原支付记录，不附带本期资源]
  SNAP --> D01[D01 订单支付 / D02充值支付信息展示]
```

## 二、内导售票与支付确认

```mermaid
flowchart TB
  W11[W11 原内导开单] --> KIND{散客还是团队}
  KIND -->|散客| SIX[六种普通支付与配置取交集]
  KIND -->|团队| NINE[九种支付与配置取交集]
  SIX --> ORIGINAL[原业务资料校验]
  NINE --> ORIGINAL
  ORIGINAL --> W12[W12 支付确认；此时才提示资源问题]
  W12 --> WAY{所选方式}
  WAY -->|扫码付/银行卡| RESOURCE[原打印按钮右侧显示资源及只读编号]
  WAY -->|其他| KEEP[原打印按钮右侧保留原现金等交互]
  RESOURCE --> VALID{本期配置及资源有效}
  VALID -->|否| ERR[弹窗提示一次，阻止出票；可换方式或取消]
  ERR --> WAY
  VALID -->|是| SUBMIT[确认出票，沿用原内导下单和支付处理]
  KEEP --> SUBMIT
  SUBMIT --> SNAP[扫码付/银行卡每笔订单记录实际资源及编号]
  SNAP --> D01[D01 订单支付展示，历史值不回写]
```

## 三、管理员配置、绑定与后续变更

```mermaid
flowchart TB
  A[进入当前景区] --> P[B01/B02 配置支付方式]
  P --> C{合法场景非空、五场景及内导散客均有可用方式?}
  C -->|否| E[阻止保存，指出具体场景；保留草稿]
  C -->|是| SAVE[保存统一规则]
  SAVE --> RES[B03/B04 维护同景区资源]
  RES --> BIND{该支付方式跟谁走?}
  BIND -->|账号| ACC[B08/B09 选择账号，配置资源]
  BIND -->|设备| DEV[B06/B07 选择窗口售票机，配置资源]
  ACC --> USE{固定还是多个?}
  DEV --> USE
  USE -->|固定| ONE[单选一个有效资源，自动成为默认]
  USE -->|多个| MANY[多选有效资源；草稿预选或修改默认，保存后生效]
  ONE --> V[校验景区 / 类型 / 启用 / 默认 / 数量]
  MANY --> V
  V -->|失败| ERR[保留绑定草稿并提示]
  V -->|通过| BS[保存绑定，全部适用场景共用]
  BS --> TEST[用实际账号及设备检查窗口可用性]
  CHANGE[后续编辑资源] --> TYPE{修改内容}
  TYPE -->|名称或编号| EDIT[ID不变，当前引用同步新主数据]
  TYPE -->|停用或删除| REF{存在账号或设备绑定?}
  REF -->|是| BLOCK[阻止，列出引用；先改绑后处理]
  REF -->|否| REMOVE[停用 / 删除二次确认；提交时再验引用]
  EDIT --> HIST[已完成交易保留原快照]
  REMOVE --> HIST
```

归属由账号切为设备不自动复制绑定。多个改固定后旧绑定不合格，须管理员明确重选；窗口不自动取第一项。

## 四、扫码付/银行卡公共资源解析

```mermaid
flowchart TB
  START[W04 / W09 / W12弹窗内；读取当前景区、场景、方式、账号及实际设备] --> PAY{方式已启用且适用当前场景?}
  PAY -->|否| NO[提示重新选择支付方式]
  PAY -->|是| NEED{扫码付或银行卡?}
  NEED -->|否| OTHER[走原线下 / 建行 / 账户流程，不带本期资源]
  NEED -->|是| OWNER{统一资源归属}
  OWNER -->|跟账号| A[只读取当前登录账号ID的绑定]
  OWNER -->|跟设备| D[只读取实际窗口设备ID的绑定]
  A --> EXIST{存在绑定?}
  D --> EXIST
  EXIST -->|否| MISSING[弹窗内提示账号或窗口未配置；阻止最终提交，不跨主体兜底]
  EXIST -->|是| FILTER[按景区、资源类型及启用状态过滤]
  FILTER --> MODE{资源使用方式}
  MODE -->|固定| FIX{恰好一个且默认有效?}
  MODE -->|多个| MULTI{默认属于已绑定的有效资源?}
  FIX -->|否| FAIL[弹窗内提示资源或默认失效；阻止最终提交]
  MULTI -->|否| FAIL
  FIX -->|是| READ[名称置灰，带出只读编码]
  MULTI -->|是| SELECT[带出默认；允许在有效绑定范围选名称]
  SELECT --> CODE[编码随选择自动带出且只读]
  READ --> SUBMIT[最终提交再次校验归属、绑定及编码]
  CODE --> SUBMIT
  SUBMIT --> ORIGINAL[执行原下单或充值处理，不新增支付分支]
  ORIGINAL --> SNAP[每笔记录实际资源及柜台编码/POS编号]
  MISSING --> KEEP[留在弹窗，保留业务；可换方式或取消，主页面不留资源错误]
  FAIL --> KEEP
```

## 五、散客/团队售票与订单支付记录

```mermaid
flowchart TB
  SCENE[W01散客 / W02团队；原对象选择W03不变] --> FILTER[按启用状态及当前场景显示支付方式]
  FILTER --> ORIGINAL[选票、资料及确认下单沿用原流程]
  ORIGINAL --> W04[W04 支付订单确认]
  W04 --> WAY{所选支付方式}
  WAY -->|扫码付/银行卡| RESOURCE[一人一票右侧：资源及只读编号]
  WAY -->|现金及其他| KEEP[原现金或其他方式交互]
  RESOURCE --> CHECK{本期配置与资源有效}
  CHECK -->|否| ERROR[弹窗提示，保留业务，可换方式]
  ERROR --> WAY
  CHECK -->|是| SUBMIT[确认出票，执行原下单及支付处理]
  KEEP --> SUBMIT
  SUBMIT --> RECORD{是否扫码付/银行卡}
  RECORD -->|是| SNAP[每笔订单支付记录保存资源ID、名称及编号快照]
  RECORD -->|否| OLD[保留原支付记录，不带旧资源]
  SNAP --> D01[D01 订单详情的订单支付信息展示]
```

## 六、长期合作伙伴与临时客户售票

```mermaid
flowchart TB
  W05[W05/W06 原伙伴售票与选择对象] --> TYPE{伙伴类型}
  TYPE -->|长期| DEFAULT[原默认账户：挂帐或预付款]
  DEFAULT --> ENABLE{对应方式启用且包含长期伙伴场景}
  ENABLE -->|否| ERR[提示不可用，不自动改另一账户]
  ENABLE -->|是| LOCK[锁定原默认方式]
  TYPE -->|临时| TEMP[原固定挂帐，无充值入口]
  LOCK --> W07[W07 原支付确认，无扫码付/银行卡资源字段]
  TEMP --> W07
  W07 --> ORIGINAL[确认后执行原下单、账户支付及出票逻辑]
  LOCK -->|充值| W09[共用W09充值弹窗，见下一图]
```

## 七、两个充值入口共用资源与编号

```mermaid
flowchart TB
  SALE[W05售票页充值] --> W09[W09 原共用充值弹窗]
  LIST[W08列表行充值] --> W09
  W09 --> FILTER[按充值/回款场景过滤五种原支付方式]
  FILTER --> WAY{所选方式}
  WAY -->|扫码付/银行卡| RESOURCE[支付按钮下方：资源及只读编号]
  WAY -->|现金| CASH[下方原现金实收及找零]
  WAY -->|微信/支付宝| EMPTY[不显示现金/资源字段，不留空槽]
  RESOURCE --> CHECK{本期配置及资源有效}
  CHECK -->|否| ERR[弹窗提示，阻止确认，可换方式]
  ERR --> WAY
  CHECK -->|是| ORIGINAL[确认充值，执行原充值/回款及其他收入处理]
  CASH --> ORIGINAL
  EMPTY --> ORIGINAL
  ORIGINAL --> SNAP[扫码付/银行卡记录本次实际资源及编号]
  SNAP --> D02[D02 原充值支付信息展示；其他收入逻辑不改]
  D02 --> RETURN[按原成功/失败流程返回]
```

## 八、配置变化、挂单恢复与历史展示

```mermaid
flowchart TB
  CHANGE[改配置、改绑定或改资源] --> RELOAD[新业务及最终提交读取当前配置]
  RESTORE[W10 原挂单恢复] --> RELOAD
  RELOAD --> VALID{本期配置及资源有效}
  VALID -->|否| ERROR[确认弹窗提示并保留业务，不兜底]
  VALID -->|是| ORIGINAL[原下单/支付处理]
  ORIGINAL --> SNAP[每笔保存实际资源名称及编号]
  SNAP --> DETAIL[D01订单支付 / D02充值支付信息]
  CHANGE -.-> HISTORY[不回写已完成历史编号]
  DETAIL --> OLD{记录有当时编号}
  OLD -->|有| SHOW[按记录展示，不读当前绑定替换]
  OLD -->|无| DASH[显示横线，不补写历史]
```
