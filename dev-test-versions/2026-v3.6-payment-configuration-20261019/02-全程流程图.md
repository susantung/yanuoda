# 支付配置化｜全程流程图

版本：V1.7｜2026-10-23。节点对应[页面清单](01-页面清单.md)。仅展开本次新增/修改；原交易处理用一个节点表示，不重新定义。

## 一、全程总览

打开原型：[后台配置 ↗](prototype/admin/index.html?page=payment) · [散客售票 ↗](prototype/window/index.html) · [内导 ↗](prototype/window/index.html?view=innerGuide)

[独立打开全程总览图](assets/flow-01.svg)

```mermaid
flowchart TB
  B01[B01/B02 配置启用、场景、排序及统一资源规则] --> FILTER[K01 各页面先过滤候选再升序；首次选本页最小序号]
  B03[B03/B04/B05 维护资源名称及柜台编码/POS编号] --> OWNER{资源跟谁走}
  OWNER -->|设备| B07[B06/B07 窗口售票机绑定资源]
  OWNER -->|账号| B09[B08/B09 收银账号绑定资源]
  B07 --> K02[K02 确认弹窗按当前归属读取绑定]
  B09 --> K02
  FILTER --> W04[W01/W02 → W04 散客/团队确认]
  FILTER --> W12[W11 → W12 内导确认]
  FILTER --> W18[W16/W17 内导结账补收 → W18独立确认]
  FILTER --> W07[W05/W06 → W07 伙伴账户支付确认]
  FILTER --> W09[W05充值 / W08行内充值 → W09共用弹窗]
  K02 --> W04
  K02 --> W12
  K02 --> W18
  K02 --> W09
  W04 --> CHECK[K03 本期配置及资源复核]
  W12 --> CHECK
  W18 --> CHECK
  W09 --> CHECK
  CHECK --> ORIG[执行原下单、支付、内导补收或充值处理]
  W07 --> ORIG
  ORIG --> RECORD{本次是否扫码付或银行卡}
  RECORD -->|是| SNAP[每笔记录实际资源及柜台编码/POS编号]
  RECORD -->|否| UNCHANGED[原支付记录，不附带本期资源]
  SNAP --> D01[D01 订单支付 / D02充值支付信息展示]
  SNAP --> D05[D05/W19 内导开单与补收逐笔展示，原押金不覆盖]
  D01 -->|订单支付需更正| REV[W13/W14 订单冲红：更正方式或柜台/POS]
  REV --> REVIEW[B10/B11 按申请主体复核及原审批]
  REVIEW --> EFFECT{同意且处理成功}
  EFFECT -->|是| UPDATE[更新有效支付；D01显示新方式及资源编号]
  EFFECT -->|否| KEEP[待审批或驳回不改有效支付]
  UPDATE --> HISTORY[W15/D04 各次前后快照独立保留]
  KEEP --> HISTORY
```

冲红增量：申请选择与订单当前有效支付分开保存；扫码付/银行卡可保持方式只更正资源或编号。同意成功后才生效，原交易金额及既有换方式处理不变；详细分支见第九—十一图。

排序处理：各页面先按启用、场景及业务资格取候选，再按序号升序；9项排9项、3项排3项，跳号不补齐。首次进入选本页候选中最小序号，不取其他场景的最小项。同一景区全部支付方式（含停用）序号不可重复。确认弹窗沿用已选方式，当前有效选择不因重排被覆盖；伙伴账户锁定、冲红初始不选。默认方式缺资源时弹窗提示，不自动跳到现金。

## 三、管理员配置、绑定与后续变更

打开原型：[支付配置 ↗](prototype/admin/index.html?page=payment) · [资源管理 ↗](prototype/admin/index.html?page=paymentResources) · [设备绑定 ↗](prototype/admin/index.html?page=device) · [账号绑定 ↗](prototype/admin/index.html?page=systemRole)

```mermaid
flowchart TB
  A[进入当前景区] --> P[B01/B02 配置支付方式]
  P --> C{合法场景非空、五场景及内导散客均有可用方式?}
  C -->|否| E[阻止保存，指出具体场景；保留草稿]
  C -->|是| SAVE[保存统一规则]
  SAVE --> RES[B03/B04 维护同景区资源]
  RES --> BIND{该支付方式跟谁走?}
  BIND -->|账号| ACC[B08/B09 选择账号，配置资源]
  BIND -->|设备| DEV[B06/B07 选择窗口售票机，配置资源]
  ACC --> USE{固定还是多个?}
  DEV --> USE
  USE -->|固定| ONE[单选一个有效资源，自动成为默认]
  USE -->|多个| MANY[多选有效资源；草稿预选或修改默认，保存后生效]
  ONE --> V[校验景区 / 类型 / 启用 / 默认 / 数量]
  MANY --> V
  V -->|失败| ERR[保留绑定草稿并提示]
  V -->|通过| BS[保存绑定，全部适用场景共用]
  BS --> TEST[用实际账号及设备检查窗口可用性]
  CHANGE[后续编辑资源] --> TYPE{修改内容}
  TYPE -->|名称或编号| EDIT[ID不变，当前引用同步新主数据]
  TYPE -->|停用或删除| REF{存在账号或设备绑定?}
  REF -->|是| BLOCK[阻止，列出引用；先改绑后处理]
  REF -->|否| REMOVE[停用 / 删除二次确认；提交时再验引用]
  EDIT --> HIST[已完成交易保留原快照]
  REMOVE --> HIST
```

归属由账号切为设备不自动复制绑定。多个改固定后旧绑定不合格，须管理员明确重选；窗口不自动取第一项。

## 四、扫码付/银行卡公共资源解析

打开原型：[散客支付确认入口 ↗](prototype/window/index.html) · [合作伙伴充值入口 ↗](prototype/window/index.html?view=partnerList)

```mermaid
flowchart TB
  START[W04 / W09 / W12弹窗内；读取当前景区、场景、方式、账号及实际设备] --> PAY{方式已启用且适用当前场景?}
  PAY -->|否| NO[提示重新选择支付方式]
  PAY -->|是| NEED{扫码付或银行卡?}
  NEED -->|否| OTHER[走原线下 / 建行 / 账户流程，不带本期资源]
  NEED -->|是| OWNER{统一资源归属}
  OWNER -->|跟账号| A[只读取当前登录账号ID的绑定]
  OWNER -->|跟设备| D[只读取实际窗口设备ID的绑定]
  A --> EXIST{存在绑定?}
  D --> EXIST
  EXIST -->|否| MISSING[弹窗内提示账号或窗口未配置；阻止最终提交，不跨主体兜底]
  EXIST -->|是| FILTER[按景区、资源类型及启用状态过滤]
  FILTER --> MODE{资源使用方式}
  MODE -->|固定| FIX{恰好一个且默认有效?}
  MODE -->|多个| MULTI{默认属于已绑定的有效资源?}
  FIX -->|否| FAIL[弹窗内提示资源或默认失效；阻止最终提交]
  MULTI -->|否| FAIL
  FIX -->|是| READ[名称置灰，带出只读编码]
  MULTI -->|是| SELECT[带出默认；允许在有效绑定范围选名称]
  SELECT --> CODE[编码随选择自动带出且只读]
  READ --> SUBMIT[最终提交再次校验归属、绑定及编码]
  CODE --> SUBMIT
  SUBMIT --> ORIGINAL[执行原下单或充值处理，不新增支付分支]
  ORIGINAL --> SNAP[每笔记录实际资源及柜台编码/POS编号]
  MISSING --> KEEP[留在弹窗，保留业务；可换方式或取消，主页面不留资源错误]
  FAIL --> KEEP
```

## 九、冲红申请：原信息回显与资源选择

打开原型：[W13销售记录 → W14冲红申请 ↗](prototype/window/index.html?view=reversal)

```mermaid
flowchart TB
  ENTRY[W13 原销售记录冲红入口] --> QUAL{原申请资格通过}
  QUAL -->|否| BLOCK[沿用原拦截，不创建申请]
  QUAL -->|是| OPEN[W14 原支付信息显示有效快照；申请人和来源提前一行]
  OPEN --> WAY[按原冲红范围与启用、订单场景取交集选择方式]
  WAY --> NEED{扫码付或银行卡}
  NEED -->|是| OWNER[按统一归属读取申请账号或实际设备绑定]
  OWNER --> VALID{有效绑定、默认及编号合格}
  VALID -->|否| ERROR[弹窗内提示，保留原因；可换方式]
  ERROR --> WAY
  VALID -->|是| SELECT[固定只读或多资源可搜索选择；编号自动带出]
  NEED -->|否| CLEAR[隐藏并清除草稿资源及编号]
  SELECT --> DIFF{方式、资源ID或编号有变化}
  CLEAR --> DIFF
  DIFF -->|否| SAME[提示未调整，不能提交]
  SAME --> WAY
  DIFF -->|是| CHECK{提交复核资格、原支付及当前配置通过}
  CHECK -->|否| RECONFIRM[提示刷新或重选，保留草稿]
  CHECK -->|是| SAVE[保存待审批、前后快照及申请主体；有效支付不变]
```

图下处理规则：

- 原资源及编号读取订单有效支付快照；历史缺值显示“—”，与下方申请选择互不覆盖。
- 原方式为扫码付/银行卡时可选相同方式更正资源或编号；其余范围沿用原冲红资格，不新增独立场景。
- 资源只从申请账号或实际设备的有效绑定中取值；无默认不取首项，固定一个不允许切换，多资源支持名称搜索。
- 切换方式清除旧资源；配置、绑定或编号变化须重新确认。保存前再校验，取消不创建申请，重复提交不生成多条待审批。

## 十、后台审核：复核、生效与驳回

打开原型：[B10冲红审核 → B11同意 / 驳回 ↗](prototype/admin/index.html?page=reversal)

```mermaid
flowchart TB
  PENDING[B10 待审批列表；原列保留] --> MODAL[B11 只读显示申请前后支付资源及编号]
  MODAL --> ACTION{审核操作}
  ACTION -->|驳回| REJECT[原原因说明校验；保存驳回结果，有效支付不变]
  ACTION -->|同意| STATE{仍待审批且原资格、有效支付未变}
  STATE -->|否| STOP[提示刷新，不覆盖当前订单]
  STATE -->|是| VALID{按申请主体复核方式、场景、绑定及资源快照}
  VALID -->|否| INVALID[阻止同意，保留待审批；可驳回重提]
  VALID -->|是| SAME{同支付方式仅更正资源或编号}
  SAME -->|是| RESOURCE[仅更正支付资源，不再次收款或动账]
  SAME -->|否| ORIGINAL[执行原冲红换方式及账户处理]
  RESOURCE --> SUCCESS{处理成功}
  ORIGINAL --> SUCCESS
  SUCCESS -->|否| FAIL[提示失败；不标记同意，不提前更新资源]
  SUCCESS -->|是| EFFECT[同意结果与有效方式、资源及编号一致生效]
  EFFECT --> DETAIL[D01显示有效支付；D04保留前后快照]
  REJECT --> DETAIL
```

图下处理规则：

- 同方式更正的列表前后类型可以相同；进入原审核弹窗查看具体资源差异，不增加列表资源列。
- 审核人只能同意/驳回，不能改申请值；资源复核始终使用申请记录的主体，不使用审核人的绑定。
- 名称、编号、归属或绑定等配置变化时，不静默替换资源；驳回不受失效资源阻拦。
- 新方式无需资源时，生效支付清除柜台/POS关联；原值保留在历史。失败、重复审核不能造成半完成或重复账务处理。

## 十一、冲红记录与订单支付：多次调整及历史

打开原型：[W15冲红记录 / 窗口订单详情 ↗](prototype/window/index.html?view=reversal) · [D04后台已审批详情 ↗](prototype/admin/index.html?page=reversal)

```mermaid
flowchart TB
  RECORD[每次申请独立保存前后快照] --> STATUS{申请结果}
  STATUS -->|待审批| PENDING[隐藏冲红申请；目标不改有效支付]
  STATUS -->|驳回| REJECT[保留目标及意见，不改有效支付]
  STATUS -->|同意成功| APPROVE[更新有效方式及资源编号；按原资格恢复申请]
  PENDING --> HISTORY[W15/D04读取本次快照及原审核日志]
  REJECT --> HISTORY
  APPROVE --> HISTORY
  APPROVE --> ORDER[D01两端显示最新成功生效信息]
  SALES[窗口统计：销售记录 → 查看] --> WINDOWORDER[独立订单详情页签：基础、支付、检票、游客门票]
  WINDOWORDER -->|返回；保留查询条件| SALES
  ORDER --> WINDOWORDER
  WINDOWORDER --> ADJUST[支付信息下方展示已同意调整：九列；前后类型格展示资源及编号快照；单号打开详情]
  HISTORY --> AGAIN{审核结束后再次申请且原资格通过}
  AGAIN -->|是| NEW[以当时有效支付为调整前值；新建申请]
  NEW --> RECORD
  CHANGE[后续改名改码、解绑或删除资源] -.-> SNAPSHOT[历史快照不回写；原无值仍显示横线]
  HISTORY --> SNAPSHOT
```

图下处理规则：订单支付显示最新有效结果，冲红详情显示每次申请自己的前后值；二者不混用。再次冲红不覆盖上一笔记录；历史未记录资源或编号时显示“—”，更正只改变本次生效值。
