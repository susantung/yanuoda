W01/W02、W09、W11、W18各自按启用、场景及资格取候选，再按配置序号升序展示；首次默认本页候选中序号最小的一项。W04、W12确认弹窗同序并保留主页面已选值。W14冲红候选同步排序但初始不选；W05/W07保留原账户锁定。


## 三、记录与详情

| 编号 | 路径 / 入口 | 页面 | 类型 | 本期内容 |
| --- | --- | --- | --- | --- |
| [D01 ↗](prototype/admin/index.html?page=order) | 后台订单中心 → 现有散客/团队订单列表 → 详情；窗口现有订单查询 → 详情 | 订单详情 / 支付信息 | 修改展示 | 每笔扫码付/银行卡订单的“订单支付”新增资源及柜台编码/POS编号，原支付字段不变 |
| [D02 ↗](prototype/window/index.html?view=partnerList) | 窗口合作伙伴 → 账户充值记录 → 详情；后台现有对应账户充值记录 → 详情 | 充值/回款详情 | 修改展示 | 收款方式、资源名称、统一编码及原有充值字段 |
| [D03 ↗](prototype/window/index.html?view=partnerList) | 现有其他收入记录 → 详情 | 其他收入详情 | 复用展示关联 | 原关联及展示不变，不新增字段或记账规则 |
| [D04 ↗](prototype/admin/index.html?page=reversal) | W15 → 查看；B10 已审批 → 详情 | 冲红记录详情 | 修改原详情 | 前后资源及编号、原审核结果及日志；历史快照不覆盖 |
| [D05 ↗](prototype/window/index.html?view=innerDetail) | 内导订单记录 / 交易记录 / 异常订单 → 查看；后台现有内导订单 → 详情 | 内导订单详情及交易记录 | 修改原详情 | 保留内导结构，分别显示开单与补收的资源和编号，不套用散客门票详情 |

D01窗口入口包括“统计 → 销售记录 → 查看”，打开独立订单详情页签；沿用基础、支付、检票和游客门票详情四个区块，返回保留原列表条件。支付信息补充冲红后的有效值：待审批/驳回不改，审核同意成功后方式、资源和编号一并展示最新有效值。

D01—D03不新增同名重复菜单。开发先按现有记录入口定位组件；后台具体二级菜单名称沿用当前系统。原型未完成真实历史详情联调，本方案定义其应落实的增量。

## 五、本期不新增

- 微信、支付宝等新线上支付接口；聚合支付继续使用现有建行链路。
- 商户号、证书、密钥维护，平台开发配置、跨景区复制、恢复默认、独立配置历史页面。
- 新的合作伙伴档案、授信、审批、临时客户回款/调账及退款流程；冲红复用原审批，补充资源更正。
- 收银员日交款单及新的统计报表页面；不调整原统计口径。
- 生产账号/设备自由切换控件。原型里的测试账号、测试设备不进入上线页面清单。
