版本：V1.6｜2026-10-22。以下为完整需求方案第24—28节；配套[页面清单](01-页面清单.md)、[全程流程图](02-全程流程图.md)及[验收清单](04-开发核对与验收清单.md)。

## 24. W13、W14｜销售记录与冲红申请

[打开原型：统计 → 销售记录 → 冲红](prototype/window/index.html?view=reversal)

### 24.1 入口与可选方式

复用原销售记录的冲红入口、申请资格及审批流程；新增支持扫码付、银行卡保持原支付方式，仅更正收款资源或柜台编码/POS编号。

| 项目 | 规则 |
| --- | --- |
| 业务场景 | 原冲红允许范围与当前已启用、适用订单所属业务场景的方式取交集；不新增“冲红”适用场景 |
| 原支付方式 | 原方式为扫码付/银行卡时仍可选，用于更正资源或编号；其他方式按原规则排除原方式；聚合支付不进入可选范围 |
| 申请资格 | 沿用原校验；聚合支付订单、有退票或已有待审批申请的订单不允许申请 |
| 申请入口状态 | 提交成功后隐藏该订单的“冲红申请”；待审批期间不能再次申请。审核同意成功后，按原资格恢复入口，下一次以最新有效支付为调整前值 |
| 无可选方式 | 在申请弹窗内提示无可用支付方式，不能提交；取消返回销售记录 |

### 24.2 弹窗内容与字段取值

保留原订单基础信息、团队信息、订单状态及原因区域。订单基础信息、订单支付信息仍为无边框三列。

| 区域 / 字段 | 显示、取值与交互 |
| --- | --- |
| 订单支付信息：收款资源 | 原有效方式为扫码付/银行卡时新增，只读；取订单当前有效支付记录的资源名称快照，不取本次申请选择值或当前绑定 |
| 订单支付信息：柜台编码/POS编号 | 与原资源一并显示，只读；取同笔支付记录的编号快照，历史无值显示“—” |
| 冲红申请售票员 | 当前发起申请的登录账号，只读；与订单原售票员分别展示 |
| 冲红申请来源 | 发起申请的实际窗口设备，只读；与订单原销售来源分别展示 |
| 上述两项布局 | 在冲红调整信息第一行，占三列网格的第一、第二列，第三列留空；与上方信息及下一行控件列起点对齐 |
| 冲红后支付类型 | 必选；按26.1取候选后按后台排序序号升序，初始不选、不默认最小项；位于下一行第一列 |
| 收款资源 | 仅新方式为扫码付/银行卡时显示、必填，位于第二列；分别取扫码付柜台/银行卡POS |
| 柜台编码/POS编号 | 仅新方式需要资源时显示，位于第三列；随资源自动带出，只读，按文本保留前导零 |
| 冲红申请原因 | 沿用原选填，最多500字，整行显示；切换方式不清空原因 |

弹窗沿用900px宽、居中、24px内边距，正文最高60vh并内部滚动；取消申请/提交申请位于正文外。窄屏按网格换行，不横向溢出。

### 24.3 资源加载、默认与切换

| 条件 / 操作 | 处理 |
| --- | --- |
| 跟收银账号 | 读取申请时当前账号的绑定；不按订单原售票员重新取值 |
| 跟窗口设备 | 读取申请时实际窗口设备的绑定；不用账号档案中的绑定窗口替代 |
| 资源候选 | 仅当前景区、匹配类型、已启用、编号非空且绑定给该主体的资源；不跨主体或类型兜底 |
| 固定使用一个 | 恰好一个有效绑定且默认有效，名称灰显不可切换，自动带出编号 |
| 允许多个并默认一个 | 带出有效默认；下拉支持输入名称搜索，仅在有效绑定中选择，不允许输入新资源或手填编号 |
| 无绑定、默认失效、数量不符或编号缺失 | 在申请弹窗资源区提示，阻止提交；不自动取第一项，可换其他允许方式 |
| 切换支付方式 | 清除上一方式的草稿资源和编号，按新方式重新加载；非扫码付/银行卡隐藏资源区且不提交残留资源 |
| 弹窗期间配置、绑定、资源名称或编号变化 | 提交时提示重新确认；刷新资源后由申请人明确重选，不静默替换或提交旧编号 |

### 24.4 提交与取消

提交时复核原申请资格、订单有效支付信息、可选方式及资源配置。以**支付方式、资源ID、编号**比较是否调整；三者均未变化时提示“支付信息未发生调整”，不创建申请。历史缺编号的原记录可选择当前有效资源补正，仍须审核。

通过后保存待审批申请：订单关联、调整前后支付方式及资源ID/名称/编号快照、申请账号、实际设备、订单业务场景、申请时间及原因。资源解析主体一并留存，供审核复核；此时不修改订单有效支付信息。

保存失败保留草稿；重复提交不产生多条待审批申请。取消或关闭不保存、不改变订单。

## 25. B10、B11｜冲红审核与审核弹窗

[打开原型：冲红管理 → 冲红审核 → 同意 / 驳回](prototype/admin/index.html?page=reversal)

### 25.1 列表与审核内容

复用待审批/已审批列表及原筛选、列、导出、配置列和分页，不增加资源列或资源筛选。待审批保留同意/驳回，已审批保留详情。同方式更正时，列表原支付类型与冲红后支付类型允许相同，进入弹窗核对资源差异。

| 弹窗区域 | 本次增量 |
| --- | --- |
| 订单支付信息 | 原方式为扫码付/银行卡时，增加调整前收款资源、柜台编码/POS编号；只读，取本次申请的调整前快照 |
| 冲红调整信息 | 申请方式为扫码付/银行卡时，增加冲红后收款资源、冲红后柜台编码/POS编号；只读，取申请快照 |
| 历史缺值 | 显示“—”，不按当前绑定或主数据补填 |
| 审核操作 | 审核人不能修改申请方式、资源或编号；原因说明沿用原必填、最多500字，初始为对应操作“同意”或“驳回” |

同意、驳回、详情沿用“订单冲红申请”弹窗，原基础信息、团队信息及顺序保持。宽960px、内边距24px、三列无边框；正文高640px，视口高度≤720px时440px，内部滚动，底部操作在正文外；详情保留日志及关闭按钮。

### 25.2 同意前复核与结果

| 校验 / 结果 | 处理 |
| --- | --- |
| 申请已处理、订单已退票或有效支付已被其他操作修改 | 不执行同意，提示刷新，不覆盖现有效支付 |
| 方式启停、场景、归属、使用方式或绑定已变更 | 按申请记录的账号/实际设备及订单场景复核；配置不一致时阻止同意并提示，不读取审核人的绑定 |
| 所选资源失效、名称或编号已变更 | 不换成当前默认或新编号；申请保留待审批，可按原流程驳回重提 |
| 复核通过 | 换支付方式沿用原冲红审批及账户处理；全部成功后方式、资源及编号一并生效 |
| 同方式仅更正资源或编号 | 更正有效支付记录并留冲红记录；金额不变，不再次收款、扣账、返还或退款 |
| 新方式无需资源 | 生效支付不附带原柜台/POS资源，原资源保留在调整前历史快照 |
| 驳回 | 记录原审核意见和结果，有效方式、资源及编号不变；资源失效不阻止驳回 |
| 失败或重复操作 | 失败不标记同意、不提前改资源；重复审核不再次执行，审批结果与有效支付保持一致 |

## 26. W15、D04｜冲红记录与详情

[窗口原型：统计 → 冲红记录 → 查看](prototype/window/index.html?view=reversal) · [后台原型：已审批 → 详情](prototype/admin/index.html?page=reversal)

列表沿用原字段、状态及操作。详情在原支付信息、冲红调整信息中分别增加资源名称和统一柜台编码/POS编号；仅对应快照方式为扫码付/银行卡时显示，无值显示“—”。

| 申请状态 | 展示与生效 |
| --- | --- |
| 待审批 | 分别显示调整前快照、申请目标值；目标值尚未生效 |
| 已同意 | 显示本次前后快照及审核结果；有效支付按成功结果更新 |
| 已驳回 | 保留申请目标值及驳回意见；有效支付不变 |

每次申请独立留存，审核结束后按原资格允许再次申请；新申请以当时最新有效支付作为调整前值。再次冲红、资源改名改码、解绑或删除均不改写历史。审核日志沿用原节点、操作人、状态、意见、时间、耗时。

## 27. D01｜订单详情、门票详情中的支付与冲红信息

[窗口原型：销售记录 → 查看](prototype/window/index.html?view=reversal) · [后台订单详情原型](prototype/admin/index.html?page=order)

| 位置 | 本次规则 |
| --- | --- |
| 窗口入口 | 统计 → 销售记录 → 查看，打开独立“订单详情”页签；返回统计时保留列表查询条件 |
| 窗口详情结构 | 沿用订单基础信息、订单支付信息、订单检票信息、游客门票详情；基础与支付信息为无边框三列，宽表在表格内部滚动 |
| 订单支付 | 两端同源显示最后一次成功生效的方式；扫码付/银行卡同时显示有效资源及编号快照 |
| 审核中 / 已驳回 | 不用申请目标值替换有效支付 |
| 冲红调整信息 | 在订单支付信息下方、订单检票信息上方显示已同意记录；待审批/已驳回申请仍在冲红记录中查看，不提前显示为已生效调整 |
| 调整表格 | 保留九列：冲红单号、原支付类型、冲红后支付类型、申请人、申请时间、支付金额（元）、审批人、审核状态、审核时间。原支付类型、冲红后支付类型单元格分别展示本次申请前后快照：支付方式、收款资源、柜台编码/POS编号；仅扫码付/银行卡显示后两项，历史无值显示“—”。即使支付方式相同，也可直接对照资源和编号变化。点击冲红单号仍可查看详情 |
| 多次冲红 | 订单支付显示最新成功结果，各次详情保持各自快照 |
| 历史缺编号 | 显示“—”，不按当前配置回填；更正后更新生效值，原快照仍保留缺值 |

按对应原支付记录更新，不新建支付拆分；原金额、支付时间、流水、出票和账户处理沿用原逻辑。

## 28. K05｜冲红保存与生效规则

| 环节 | 保存 / 修改 |
| --- | --- |
| 提交申请 | 独立保存前后快照和解析主体，不修改有效支付 |
| 同意成功 | 审批结果与有效方式、资源ID、名称、编号一致生效；保留原冲红关联及流水 |
| 驳回 / 失败 | 驳回只记录原审核结果；失败不生效，原有效支付及历史快照不变 |
| 历史查询 | 读取交易及申请快照，不用当前主数据替换 |

账户支付与线下方式互转仍执行原校验、扣回/返还及流水逻辑；本次只补资源取值、校验、记录与展示。
