## 31. W18｜结账补收支付订单确认

打开原型：[补收支付订单确认 ↗](prototype/window/index.html?view=innerSupplement)

只调整原支付方式区域，资源字段紧接支付方式；不增加打印选择区。

### 31.1 字段、取值与默认

| 字段 | 显示与取值 |
| --- | --- |
| 支付方式 | 可输入筛选的必选下拉。取已启用、包含“内导售票”且符合本单团散及账户资格的方式；散客最多六种，团队最多九种。按配置序号升序，允许跳号、序号不重复 |
| 支付方式初值 | 每次新进入默认本次候选中序号最小的一项；不取原押金方式。无候选留空，提示“当前场景无可用支付方式”，禁止确定 |
| 收款资源 | 仅扫码付/银行卡显示。按当前结账账号或实际窗口设备取已绑定、启用且类型匹配的资源；不取开单人/开单设备绑定 |
| 资源默认与选择 | 固定使用一个：只读；允许多个：默认绑定默认项，可输入筛选切换。无资源或默认失效在本弹窗提示，禁止该方式确定；不跨主体取资源、不自动改成现金 |
| 柜台编码/POS编号 | 仅扫码付/银行卡显示，跟随资源自动带出，只读 |
| 动态字段 | 现金显示原实收/找零；扫码付/银行卡显示资源/编号；其他方式不显示资源字段。隐藏字段不占位、不校验 |

### 31.2 选择与确认

- 同一次弹窗内保留有效手选值；仅调整排序不重置。方式失效时改选剩余候选第一项；切换扫码付/银行卡重新读取对应资源，不串用草稿。
- 确定时复核方式及账户资格；扫码付/银行卡增加资源归属、绑定、启用、默认规则和编号校验。失败留在本弹窗，不新增成功收款。
- 通过后执行原支付处理，本笔金额取结算结果中的补收金额。补收资源及编号独立保存，不覆盖原押金快照。
- 未提交时取消返回W17；重新进入重新加载候选和资源。

## 32. D05、W19｜内导订单详情与交易记录

打开原型：[内导订单详情 ↗](prototype/window/index.html?view=innerDetail) · [交易记录 ↗](prototype/window/index.html?view=innerTrades)

| 位置 | 本次新增 |
| --- | --- |
| D05原开单支付信息 | 支付方式后显示本笔收款资源、柜台编码/POS编号 |
| D05交易记录表、W19交易记录列表 | 支付/退款方式后新增“收款资源”“柜台编码/POS编号”两列，按每笔开单、补收交易快照展示 |
| 各入口的内导订单详情 | 窗口和后台读取同一笔交易快照；保留各自详情结构 |

每笔扫码付/银行卡保存资源ID、名称及编号快照，关联本次操作员和实际设备；资源后续更名、改号、停用不回写历史。其他方式、旧交易缺值显示“—”；退款仅在明确关联原收款交易时回显其快照。

验收示例：押金0.02元为“扫码付 / 散客1号柜台码 / CCB-SK-01”，补收0.48元为“银行卡 / 团队POS-01 / POS-TD-01”，两笔分别展示；同为扫码付但更换柜台码，也应分别展示两个编号。

## 33. W20｜异常支付与重复提交控制

打开原型：[内导异常订单 ↗](prototype/window/index.html?view=innerExceptions)

- 已提交、结果未明的补收保留提交时支付方式、账号/设备及资源快照；查看使用该次快照，不按最新配置改写，不新增支付方式选择。
- 成功后将该笔资源及编号与收款结果一起保存；重复查询不得产生第二笔补收。
- 明确失败后，若原流程允许重新结账，新尝试重新读取配置并保存独立快照，不覆盖失败交易。
