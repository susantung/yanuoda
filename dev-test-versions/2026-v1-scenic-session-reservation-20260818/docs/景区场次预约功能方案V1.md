# 景区场次预约功能方案 V1

> 历史方案：本文件不再作为最新开发依据。当前唯一正式方案为[《场景活动预约管理功能 PRD》](./场景活动预约管理功能PRD.md)。本文件仅用于追溯早期总体结构。

> 版本：V1.0  
> 日期：2026-08-13  
> 产品形态：全域景区 SaaS 管理后台＋景区微信小程序游客端  
> 详细决策依据见：[景区场次预约方案确认清单.md](./景区场次预约方案确认清单.md)

## 一、产品目标

为景区提供一套可配置的场次预约能力。第一期解决游客已经完成购票后，独立选择预约日期、场次及项目，并填写资料完成预约的问题。

第一期预约系统不读取、不校验、不绑定票务订单。任何进入预约页面的游客均可提交预约；预约成功只代表获得预约资格，不代表已经购票。

系统采用 SaaS 模式。管理员进入全域景区管理后台前已经选择景区账号，因此预约活动直接归属当前景区，不在本功能内重复配置景区绑定关系。

## 二、第一期范围

### 2.1 本期建设

- 多套预约活动并存、发布、下架、复制和删除。
- 日期、场次、开放时间、截止时间及场次库存配置。
- 可选的项目、项目分类、项目库存及按日期或场次隐藏项目。
- 必读须知与全局展示或按特殊提示日期展示。
- 自由配置游客填写字段，支持单人和多人/团体预约。
- 游客预约、查看记录、修改资料或人数、取消预约。
- 管理员查看预约、修改、取消、按场次查看名单及导出数据。
- 访问人数与预约人数的基础数据概览。

### 2.2 本期不建设

- 票务订单校验、购票预约一体化及 OTA 订单对接。
- 支付、审核、候补、核销、排队叫号。
- 短信、微信订阅消息和管理员通知。
- 重复预约限制、身份证去重、黑白名单和爽约限制。
- 管理员代客新增预约。
- 独立数据统计页、访问明细和转化分析。
- 活动暂停、恢复、结束和草稿状态。

## 三、后台入口与信息架构

工作台新增“活动/场次预约管理”功能分组，第一期包含：

- 活动管理：创建和管理预约活动。
- 特殊提示日期管理：按日期维护是否触发特殊提示。入口已确定，内页待业务进一步确认。

活动管理内包含：

- 预约活动列表。
- 活动编辑配置。
- 活动管理首页。
- 预约订单。
- 日期/场次名单。
- 数据导出。

## 四、预约活动管理

### 4.1 活动状态

预约活动只有两种状态：

- 已发布：活动对游客生效，具体日期和场次继续按照开放、截止及库存计算。
- 已下架：停止接受新预约；新建活动首次发布前也按已下架管理。

不设置草稿、暂停、恢复和结束状态。配置由管理员主动保存；已发布活动保存后立即更新游客端，历史预约继续使用提交时保存的配置快照。

### 4.2 活动列表

- 支持一个景区同时维护多套活动。
- 支持按活动名称搜索。
- 使用“已发布”“已下架”两个标签，标签文字后不展示数量；标签下方展示当前状态的活动总数。
- 默认进入“已发布”，并按最后更新时间倒序排列。
- 卡片展示活动图片、名称、状态、最后更新时间、最后更新人、总参与人数和今日预约人数。
- 未上传活动图片时，列表使用主题色浅底占位图并显示活动名称首字。
- 卡片通过“信息”入口展开查看创建时间和创建人。
- 点击卡片主体直接进入编辑配置。
- 卡片业务操作只保留“海报”；海报内容、图片来源、二维码或小程序码、保存分享方式及无图处理待后续确认。
- 卡片底部左侧将总参与人数和今日预约人数分为上下两行展示，并支持四位数及以上人数；右侧展示“海报”和“信息”入口。

总参与人数按有效预约的实际参与人数统计：单人预约计 1 人，多人预约按填写人数统计。今日预约人数统计当日新提交且当前仍有效的实际参与人数。

### 4.3 删除

- 已发布活动必须先下架才能删除。
- 已下架活动即使已有预约数据也允许删除。
- 删除前展示预约记录数和实际参与人数。
- 明确提示删除将清空全部配置和预约数据且无法恢复。

### 4.4 发布校验

发布前至少满足：

- 已填写活动名称。
- 至少存在一个未来可预约日期，每个开放日期至少存在一个场次。
- 姓名和手机号字段已经添加并设为必填。
- 限制人数的场次和项目均已配置有效名额。
- 配置项目时已经填写项目主题，且至少存在一个可展示项目。
- 启用项目分类时，至少存在一个包含可展示项目的分类。
- 启用必读须知时，标题、内容和阅读时长完整。

校验失败时列出问题，并可进入对应配置页处理。

## 五、活动基础配置

### 5.1 基础信息

- 活动名称：必填。
- 活动图片：选填，列表及游客端共用；未上传时，列表使用主题色浅底占位图并显示活动名称首字，游客端详情及海报中的缺省样式另行确认。
- 详情介绍：选填，支持基础图文编辑。
- 联系人、联系电话：选填。
- 创建人、创建时间、更新时间：系统记录，不允许人工修改。

### 5.2 必读须知

一个活动配置一份须知：

- 展示必读须知：是或否。
- 选择“是”后设置展示方式：全局展示或按特殊提示设置展示。
- 全局展示：游客选择任一可预约日期均弹出。
- 按特殊提示设置展示：仅命中特殊提示日期时弹出，并在日期上显示“特殊提示”。
- 配置弹窗标题、图文内容和强制阅读秒数。
- 确认文案固定为“已读并确认以上内容”；倒计时未结束前不可点击。
- 点击关闭、返回或遮罩可关闭，但不会选中该日期。
- 同一次进入预约页面，同一日期确认一次；退出后重新进入需再次确认。
- 预约提交时保存游客确认的须知内容和确认时间。

## 六、日期、场次与开放规则

### 6.1 日期模式

支持两种方式：

- 自选可约日期：逐日选择不连续日期，或通过开始日期和截止日期批量选择连续日期。
- 每周规律循环：设置生效范围及开放星期，并可增加特殊开放日和特殊关闭日。

未产生预约的未来日期允许移除；已有预约的日期必须先取消该日全部预约后才能移除。过去日期保留查看，不再修改基础配置。

### 6.2 场次配置

- 开始时间必填，结束时间和场次名称选填。
- 未配置结束时间时，游客端只显示开始时间。
- 同一天允许存在时间重叠的多个场次，各自独立计算库存。
- 场次支持不限名额或限制人数。
- 已有预约后，不允许修改场次时间或删除场次。
- 名额可增加；可减少但不能低于当前已预约实际参与人数。
- 管理端按日期汇总总名额、已预约人数和剩余名额。

### 6.3 场次复制与模板

- 可复制到单个日期、连续日期范围或全部未来开放日期。
- 可选择仅填充空日期或替换目标日期原有场次。
- 有预约数据的目标日期禁止替换并自动跳过。
- 可保存场次模板并应用到指定范围。
- 只复制场次名称、时间和名额设置，不复制预约数据、特殊提示和项目隐藏关系。

### 6.4 开放与截止

开放规则：

- 立即开放。
- 滚动开放：每天固定时刻开放未来第 N 天。

截止规则：

- 到场次开始时间截止，作为默认值。
- 场次开始前 N 分钟或 N 小时截止。

### 6.5 游客端场次展示

- 日期采用横向日期列表，可打开月历选择；月历范围为当天至一个月后。
- 场次采用分页视图，展示场次名称、开始和结束时间。
- 剩余名额展示可配置；关闭后不展示具体剩余数。
- 满员场次始终继续展示“已满员”，不可选择。
- 已截止场次是否隐藏由开关控制；隐藏后，当天全部场次均截止时日期也隐藏。
- 未配置、隐藏或尚未达到展示条件的场次不向游客端展示；不设置“未开放”场次状态。

## 七、项目与分类

### 7.1 项目启用

- 未添加项目时，游客流程中不展示项目模块，只校验场次库存。
- 添加第一个项目后自动启用；项目主题必填，例如“游览线路”。
- 一笔预约只能选择一个项目；启用项目后项目必选。
- 项目名称必填，图片和简介选填。
- 游客端支持有图和无图两种项目卡片。

### 7.2 项目分类

- 分类能力默认关闭。
- 关闭时直接展示项目；开启时按照分类再选项目。
- 开启分类后，未归类项目不向游客展示。
- 分类使用横向标签，默认选中第一个存在可预约项目的分类。
- 分类下没有可预约项目时不展示该分类。

### 7.3 项目库存

项目支持三种库存范围：

- 每时段：每个日期、场次独立名额。
- 每日：同一日期下所有场次共享名额。
- 全局：活动全部日期和场次共享项目总名额。

每种模式均可不限名额或限制人数。提交时同时校验场次库存与项目库存，最大可预约人数取两者剩余量的较小值。

已有预约后不能切换项目库存模式。名额可增加；可减少但不能低于相应范围内已预约实际人数。

### 7.4 项目隐藏

- 项目可完全隐藏，也可按指定日期或场次隐藏。
- 被隐藏项目在当前组合下视为不存在：不展示、不可选择，不参与新预约项目库存核算。
- 已产生预约的项目可隐藏但不可删除。
- 隐藏只影响后续预约；历史预约继续有效并占用原名额。
- 项目满员后继续展示“已满员”，不可选择。

## 八、游客填写字段

### 8.1 字段管理

- 支持添加、编辑、复制、排序和停用字段。
- 已产生预约数据的字段不得物理删除，只能停用。
- 每张预约保存提交时的表单结构和数据快照。
- 第一期所有字段均不提供“填写提示”。

### 8.2 常用字段

| 字段 | 主要规则 |
|---|---|
| 姓名 | 名称可改、类型固定；必填默认开启；自动填充上次预约姓名默认开启；不做去重和名单。 |
| 手机号 | 名称可改、类型固定；必填默认开启；固定格式校验；游客可微信授权加载并继续修改；不读取历史预约手机号。 |
| 身份证号 | 名称可改、类型固定；必填默认关闭；校验大陆居民身份证位数、出生日期和校验码；不做实名、年龄、号段、去重和名单。 |

### 8.3 自定义字段

| 字段 | 主要规则 |
|---|---|
| 单行文本 | 必填默认关闭；最大 50 字；无自动填充。 |
| 多行文本 | 必填默认关闭；最大 200 字；需要备注时使用该类型。 |
| 数字 | 只允许非负整数；必填默认关闭；默认最多 15 位。 |
| 单选 | 游客端固定下拉框；纯文字；至少 2 项；支持逐项增删改和排序；不做“其他”和批量添加。 |
| 多选 | 纯文字；至少 2 项；非必填时最少 0 项；开启必填后最少默认 2 项；最大可选默认全部。 |
| 日期 | 固定选择年月日；必填默认关闭；不支持具体时间、默认日期和日期范围。 |

### 8.4 多人/团体

- 一个活动最多添加一个多人/团体字段。
- 名称由管理员自定义，字段固定必填。
- 最少人数固定为 1 人，默认人数为 1 人；最多人数由管理员配置。
- 添加“多人/团体”字段表示游客需要填写本单实际参与人数，并不代表一单必须至少两人；一人参与时填写 1 人。
- 游客填写人数即实际参与人数，联系人不额外计入。
- 按实际参与人数扣减场次与项目库存。
- 不自动填充历史人数，不采集每位同行人的明细资料。
- 未添加该字段时为单人统计模式：填写一位预约人的资料，一张有效预约固定统计并扣减 1 人，游客端不显示人数加减控件。
- 添加该字段时为多人/团队统计模式：显示管理员自定义名称的人数控件，游客填写几人即统计并扣减几人。

## 九、游客预约流程

预约主链路：

`预约首页/详情 → 日期 → 场次 → 分类（启用时）→ 项目（配置时）→ 游客资料 → 确认预约 → 预约成功`

核心规则：

- 切换日期后清空场次、分类和项目选择。
- 项目隐藏、满员或不可预约时实时过滤。
- 游客填写页展示预约摘要，日期、场次和项目不可在本页修改。
- 提交前由服务端重新校验活动、开放截止状态、场次库存、项目库存和表单数据。
- 填写过程中不提前锁定名额；多个游客同时提交，以服务端实际扣减成功顺序为准。
- 预约创建、场次扣减和项目扣减作为一个完整事务处理。
- 防止连续点击和网络重试重复创建预约。
- 库存不足时保留填写资料；多人模式有部分余量时可减少人数后再次提交。

预约成功页展示活动、日期、场次、项目、多人模式人数及游客预约号。

## 十、游客预约记录

### 10.1 我的预约

- 按当前微信小程序用户查询当前景区下的全部预约活动记录。
- 标签为全部、已约/报名、已取消。
- 卡片展示状态、活动、日期、场次、项目、人数、预约号和提交时间。

### 10.2 游客预约号

- 系统内部另有全局唯一 ID，不向游客展示。
- 游客预约号按照“活动＋预约游玩日期”独立递增，每日从 `001` 开始。
- 同一日期不同场次共用序列；次日重新从 `001` 开始。
- 取消后不回收号码；修改资料或人数不改变号码。
- 管理端查询时结合活动和预约日期定位重复号码。

### 10.3 修改

- 游客和管理员均可修改普通填写资料及多人模式下的实际人数。
- 日期、场次、分类和项目不能修改，选择错误需取消后重新预约。
- 修改不设置截止时间，场次开始前后均允许。
- 人数减少时返还差额库存；增加时校验并追加扣减。
- 保存修改和库存变化作为完整事务处理，失败则保持原数据不变。

### 10.4 取消

- 管理端可配置是否允许游客取消，默认开启。
- 游客取消截止支持场次开始前 N 分钟/小时，或到场次开始时间截止。
- 游客取消原因选填；管理员取消原因必填。
- 管理员可单笔取消，也可批量取消某日期或场次全部预约。
- 取消状态更新和库存返还作为完整事务处理，同一预约只能成功取消一次。
- 取消不可撤销；需要参与时重新预约。
- 活动下架后，历史预约仍可查看、修改和取消。

## 十一、管理端运营

### 11.1 活动管理首页

- 概览有效预约单数、有效实际参与人数、今日新增预约单和人数、已取消预约单、总访问人数及今日访问人数。
- 快捷入口：预约订单、日期/场次名单、编辑配置、数据导出。
- 下架后仍可查看数据、处理历史预约、编辑并重新发布。

### 11.2 预约订单

- 标签：已预约、已取消。
- 搜索：游客预约号、姓名、手机号。
- 筛选：预约日期、场次、提交时间；有分类和项目时动态增加对应筛选。
- 支持简要列表和详情卡片。
- 详情卡片可从填写项中选择最多 5 项直接展示。
- 点击进入预约详情后执行修改或取消。

### 11.3 日期/场次名单

- 按预约日期和场次汇总开放状态、名额、已预约人数和剩余名额。
- 无预约场次继续展示“暂无人选择”，不显示名单详情链接。
- 有预约时可进入场次名单详情。
- 名单支持按预约号、姓名和手机号搜索，支持简要列表和详情卡片。
- 单笔操作包含详情和取消。

### 11.4 数据导出

第一期提供：

- 场次名单：一个文件包含场次汇总和有效预约明细两个工作表。
- 预约记录：每张预约一行，可导出全部、已预约或已取消。

导出时间范围按预约游玩日期选择。动态填写字段按照预约提交时的字段快照展开。

## 十二、状态、库存与数据一致性

- 有效预约状态只有预约成功；另有已取消状态。
- 已取消预约不计入有效预约人数和场次名单。
- 场次和项目库存始终按照实际参与人数处理。
- 预约提交、人数修改、取消返还均使用服务端事务。
- 同一请求使用唯一请求标识，防止重复创建、重复扣减或重复返还。
- 项目隐藏、字段停用和配置修改不改变历史预约快照。
- 已满员场次和项目继续展示“已满员”，不隐藏且不可选择。
- 已截止场次是否隐藏按活动配置执行。

## 十三、待业务补充与后续迭代

### 13.1 待业务补充

特殊提示日期管理内页尚需确认：

- 适用活动范围。
- 日期选择和批量设置方式。
- 可操作角色与权限。
- 历史日期和已有预约日期的处理规则。

### 13.2 后续迭代

- 官网小程序购票完成后直接预约。
- 购票与预约同一流程完成。
- 携程、美团等 OTA 订单及场次接口对接。
- 短信和微信通知。
- 管理员代客预约、重复预约限制、黑白名单、审核、候补、核销和高级统计。
