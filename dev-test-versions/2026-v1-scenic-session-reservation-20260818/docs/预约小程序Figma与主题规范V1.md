# 预约小程序 Figma 与主题规范 V1

> 本文件是[《场景活动预约管理功能 PRD》](./场景活动预约管理功能PRD.md)的全局视觉与主题配套规范，只定义跨页面复用的 Token、组件和适配底线。每个页面的业务、模块顺序、页面特有样式、状态和交互以 PRD 对应页面章节为准；本文件不能脱离 PRD 单独作为开发需求。
>
> 页面编号和 HTML 原型覆盖范围参见[《HTML 原型页面清单 V1》](./HTML原型页面清单V1.md)。如本规范、HTML 原型与 PRD 冲突，以最新逐页确认并同步后的 PRD 为准。

> 适用范围：游客端预约活动、日期/场次/分类/项目选择、填写资料、预约成功、预约记录、预约详情及相关弹窗，以及管理小程序的活动列表和 C01—C07 配置页。  
> 设计基线：继承现有景区小程序的交易与服务页面风格，并支持同一套预约功能在不同景区中替换品牌主题色。  
> 设计稿基准：Figma 使用 750px 宽画板；开发尺寸按 375px 逻辑宽度理解，最终以微信开发者工具和真机预览校准。

## 微信平台适配补充

根据微信官方当前文档，本项目采用以下规则：

- 现有 Figma 继续使用 750px 双倍稿，对应 375px 逻辑宽度；同时按响应式页面处理 390px 和其他手机宽度，不能只做整页等比缩放。
- 微信官方当前优先推荐标准 `vw`，`rpx` 仍可使用但可能产生取整误差；页面不滥用基于屏宽同比例缩放的单位，配合 Flex/Grid、最大最小宽度和 Media Query。
- 原型与开发至少检查 320、360、375、390、414px 五档手机宽度。
- 右上角必须为微信官方菜单/胶囊预留区域；底部固定按钮必须兼容安全区和 Home Indicator。
- 使用 `wx.getWindowInfo()` 获取窗口与安全区信息；部分机型可能不返回 `safeArea`，开发需有兜底。
- 主要按钮、输入框、日期块和图标热区不低于 44×44px 逻辑尺寸。该数值是根据微信官方建议的 7—9mm 物理触控区域形成的项目执行标准。
- 一期按手机竖屏设计，不主动开启旋转；若宿主小程序未来启用 iPad/大屏模式，再通过 Media Query、`resizable` 和最大内容宽度适配。
- 表单需要专项检查键盘弹出、错误定位和固定底栏遮挡问题。

官方依据：

- [微信小程序设计指南](https://developers.weixin.qq.com/miniprogram/design/)
- [WXSS](https://developers.weixin.qq.com/miniprogram/dev/framework/view/wxss.html)
- [响应显示区域变化](https://developers.weixin.qq.com/miniprogram/dev/framework/view/resizable.html)
- [`wx.getWindowInfo`](https://developers.weixin.qq.com/miniprogram/dev/api/base/system/wx.getWindowInfo.html)

## 一、设计原则

1. 预约功能属于景区小程序的一部分，不建立独立品牌风格。
2. 快预约竞品用于业务流程、状态和交互参考，不直接继承其视觉样式。
3. 页面结构、间距、字号、圆角和状态语义在所有景区保持一致。
4. 景区差异主要通过主题色、活动图片和项目图片体现，不允许每个景区重新修改组件样式。
5. 交易和填写页面以清晰、稳定、易操作为先，不套用首页节庆营销皮肤。
6. 所有颜色都从 Figma 变量和开发主题变量引用，组件内部不得写死景区品牌色。

## 二、多景区主题机制

### 2.1 主题归属

主题配置归属于景区，不归属于预约活动。

同一个预约活动可以匹配多个景区。游客从哪个景区的小程序入口、页面入口或有效分享链接进入，就使用哪个景区的主题配置；活动内容、日期场次、项目和库存仍使用同一份活动数据。

主题解析顺序：

1. 当前小程序或页面上下文中的景区主题。
2. 分享链接携带的景区标识所对应的主题。
3. 活动配置的默认展示景区主题。
4. SaaS 系统默认主题。

直接分享活动时必须携带景区标识；无法确定景区时才进入后两级兜底，避免同一活动在不同入口中出现错误品牌色。

### 2.2 第一期景区主题配置

每个景区至少配置：

- 主题色 `brand-primary`，必填。
- 主题色上的文字颜色 `on-brand-primary`，系统自动计算为白色或深色。
- 可选品牌标识或景区名称，由现有小程序公共框架处理，预约模块不重复配置。

管理员只选择一个主题色。系统保存时自动生成浅色背景、描边色、按压色等衍生色，避免管理员逐个配置导致颜色失控。

### 2.3 主题色使用范围

使用景区主题色：

- 小程序页面导航栏背景或导航标题强调。
- 主按钮、文字按钮和可操作链接。
- 日期、场次、分类、项目的选中状态。
- 日历选中日期和当前步骤。
- 输入框聚焦态、单选、多选和开关激活态。
- 轻量品牌标签、统计强调和加载动画。

不使用景区主题色：

- 错误、取消失败、删除等危险状态。
- 警告、名额紧张、特殊提示等提醒状态。
- 已满员、已截止、不可选、已取消等中性状态。
- 正文、辅助文字、分割线和页面背景。

### 2.4 业务语义色与品牌色分离

即使某个景区主题色是红色、黄色或蓝色，业务状态仍使用固定语义：

- 成功 `status-success`：绿色。
- 警告 `status-warning`：橙色。
- 危险 `status-danger`：红色。
- 信息 `status-info`：蓝色。
- 禁用 `status-disabled`：灰色。

呀诺达主题恰好以绿色为品牌色时，品牌色和成功色仍使用不同变量，不能在 Figma 或代码中合并。

### 2.5 主题色安全校验

- 主按钮文字与按钮底色的对比度不低于 4.5:1。
- 关键控件边界与相邻背景的对比度不低于 3:1。
- 系统根据主题色明度自动选择白色或深色按钮文字。
- 主题色过浅、过灰或无法生成合格衍生色时，管理端不允许直接保存，并提示更换颜色。
- 选中状态同时使用背景、边框、文字或勾选图标表达，不能只依赖颜色。

## 三、Figma 变量

### 3.1 品牌变量

| Figma 变量 | 用途 | 呀诺达主题示例 |
|---|---|---|
| `brand/primary` | 主按钮、选中态、导航强调 | 以正式组件取色为准 |
| `brand/on-primary` | 主色背景上的文字和图标 | 自动计算 |
| `brand/primary-pressed` | 主按钮按压态 | 由主色生成 |
| `brand/primary-soft` | 选中浅底、轻标签 | 由主色生成 |
| `brand/primary-border` | 选中描边、次按钮描边 | 由主色生成 |
| `brand/primary-disabled` | 品牌控件禁用底色 | 由主色与中性色混合生成 |

Figma 建立一个 `Scenic Theme` 变量集合。默认 Mode 为“呀诺达”，其他景区新增 Mode；组件只绑定变量，不复制组件。

### 3.2 中性色

| 变量 | 建议值 | 用途 |
|---|---:|---|
| `neutral/page` | `#F5F6FB` | 预约流程页面底色 |
| `neutral/card` | `#FFFFFF` | 卡片、弹层、底部操作栏 |
| `neutral/text-primary` | `#1F2329` | 标题、主要字段值 |
| `neutral/text-secondary` | `#646A73` | 正文和次级信息 |
| `neutral/text-tertiary` | `#8F959E` | 辅助说明、占位文字 |
| `neutral/text-disabled` | `#B8BDC5` | 禁用文字 |
| `neutral/border` | `#E5E7EB` | 分割线、普通描边 |
| `neutral/mask` | `rgba(0,0,0,.55)` | 弹窗遮罩 |

### 3.3 语义色

| 变量 | 建议值 | 用途 |
|---|---:|---|
| `status/success` | `#16B364` | 预约成功、操作成功 |
| `status/warning` | `#F79009` | 特殊提示、名额紧张 |
| `status/danger` | `#F04438` | 删除、错误、危险操作 |
| `status/info` | `#2E90FA` | 普通信息提示 |
| `status/disabled` | `#C9CDD4` | 不可选和失效状态 |

以上数值作为原型初始值；正式进入视觉定稿时可微调，但语义关系不得改变。

## 四、尺寸与排版

### 4.1 画板与安全区

- Figma 游客端画板宽 750px。
- 页面内容左右边距 24px 设计稿尺寸，对应约 12px 逻辑尺寸。
- 固定底栏必须包含 iPhone Home Indicator 和微信小程序底部安全区。
- 导航栏遵循微信小程序胶囊区域，不把关键操作放入胶囊遮挡区。

### 4.2 间距系统

使用 4 的倍数建立间距变量，Figma 中以 2 倍稿标注：

| 变量 | Figma | 逻辑尺寸 | 使用场景 |
|---|---:|---:|---|
| `space/1` | 8px | 4px | 图标与文字微间距 |
| `space/2` | 16px | 8px | 紧凑行内间距 |
| `space/3` | 24px | 12px | 页面边距、卡片间距 |
| `space/4` | 32px | 16px | 卡片内边距 |
| `space/5` | 40px | 20px | 模块标题与内容 |
| `space/6` | 48px | 24px | 大模块分组 |

同一页面优先使用 24px、32px、48px 三档 Figma 间距，避免出现大量无规则数值。

### 4.3 圆角

沿用现有设计规范：

| 变量 | 圆角 | 使用场景 |
|---|---:|---|
| `radius/s` | 4px | 小标签、微型状态块 |
| `radius/m` | 8px | 输入框、日期块、小按钮 |
| `radius/l` | 12px | 场次卡、项目卡、信息卡 |
| `radius/xl` | 16px | 大卡片、底部弹层、重要弹窗 |
| `radius/full` | 999px | 胶囊按钮、圆形状态 |

### 4.4 字体

- 中文字体：PingFang SC；无法使用时回退至系统无衬线字体。
- 页面标题：20px / Semibold。
- 模块标题：17px / Semibold。
- 卡片标题：16px / Medium 或 Semibold。
- 正文和表单值：14px / Regular。
- 辅助说明：12px / Regular。
- 按钮文字：16px / Medium。
- 数字、日期和时间使用等宽数字特性，避免库存变化时跳动。

Figma 750px 稿中的字号按上述逻辑字号乘 2 标注，例如页面标题使用 40px。

### 4.5 管理小程序列表与配置页字号

- A02 活动名称：15px，最多两行；活动状态和更新时间等辅助信息不挤压名称。
- 配置页页面标题：18px；配置卡片标题：16px。
- 字段名称、输入值和主要选项名称：14px。
- 顶部步骤、游客端效果、轻量操作按钮：13px。
- 字段选填/必填、尺寸建议、解释文字、日期场次摘要等次级信息：12px。
- 底部主要按钮：14px。
- C01—C07 必须使用同一字号层级；低于 12px 的文字只能用于非核心装饰标识，不能承载日期、状态、操作说明或业务结果。

### 4.6 暂停预约状态

- “暂停预约”是业务警告状态，使用固定橙色警告语义，不跟随景区品牌主题色变化。
- 后台日期摘要显示“已暂停”，游客端日期和该日场次显示“暂停预约”。
- 暂停状态仍保留日期、场次及历史预约可见性，但控件不可选择；不能仅依靠降低透明度表达，应同时使用文字、浅橙底和警告色。
- 尚未开放的配置能力使用完整灰色禁用卡片，并在标题中明确标注“敬请期待”；禁用项不得出现选中边框、主题色底或可点击反馈。
- “已截止”使用中性灰色表达时间失效，“已满额”使用独立的满员语义样式表达库存耗尽；两种状态文案和颜色不可混用。

## 五、基础页面结构

### 5.1 导航区

- 首选主题色导航栏，标题使用 `brand/on-primary`。
- 如宿主景区小程序统一使用白色导航栏，则预约模块跟随宿主，不单独强制主题色导航。
- 返回、更多和微信胶囊区域遵循小程序原生规范。
- 管理端 C01—C07 步骤标签使用单行横向滚动栏，不折行；手机端原生手指滑动，HTML 原型支持鼠标拖拽、触控板和滚轮横移。鼠标短按与拖拽必须按位移阈值区分，短按标签时高亮和下方页面内容必须同步切换。

### 5.2 页面背景与卡片

- 页面背景统一使用 `neutral/page`。
- 主要内容使用白色卡片；重要模块之间留出 12px 逻辑间距。
- 卡片不使用重阴影，以轻描边、极弱阴影或留白区分。
- 详情页采用“左侧字段名、右侧字段值”的稳定行式结构。

### 5.3 底部操作栏

- 白色固定底栏，顶部可有轻分割线。
- 主按钮占主要宽度，使用 `brand/primary`。
- 单主操作时不并列放置低频入口。
- 主按钮禁用时使用中性禁用样式，不仅降低透明度。

## 六、核心预约组件

### 6.1 活动头图区

- 活动图片使用真实景区或项目图片，避免把关键文字直接做进图片。
- 活动名称和详情介绍使用真实文本，保证多景区和多语言扩展能力。
- 头图只承担氛围表达，不决定页面主题色。

### 6.2 横向日期条

- 默认展示当天至一个月后的可预约日期。
- 日期卡展示星期、月日和必要状态。
- 选中态使用 `brand/primary-soft` 背景、`brand/primary-border` 描边和 `brand/primary` 文字。
- 特殊提示日期增加固定警告标识，使用 `status/warning`，不随主题变化。
- 已满员和已截止使用独立中性状态；暂停预约使用固定警告状态。未配置或隐藏的日期不进入游客端。
- 日期条右侧保留月历入口。
- 开放日期允许不连续，日期条下方不额外展示“今天至某日”或“当前共 X 个可预约日期”等范围、数量说明。

### 6.3 月历弹窗

- 使用白色圆角弹层和半透明遮罩，允许点击遮罩关闭。
- 选中日期使用 `brand/primary` 实心底和 `brand/on-primary` 文字。
- 今天可用描边或小圆点辅助表达，不能与选中状态混淆。
- 特殊提示日期保留警告标识。

### 6.4 场次卡片

- 展示开始时间；配置结束时间时展示时间范围；配置场次名时同时展示名称。
- 名额可见时展示“剩余 X 名”；无剩余显示“已满员”；超过截止时间显示“已截止”。
- 选中态使用主题浅底、主题描边和明确勾选图标。
- 已满员继续展示但不可选；已过期场次按活动配置决定是否隐藏。

### 6.5 分类

- 使用横向标签或短标签栏。
- 选中分类使用主题色文字和主题色指示线/浅色胶囊。
- 分类过多时横向滚动，不折成多行造成页面跳动。
- 分类标签点击热区不低于 44px；滑动和点击采用明确阈值区分，滚动后的第一次点击必须生效，切换后保留当前横向位置并确保选中标签可见。
- 未配置分类时不显示此模块，项目直接展示。

### 6.6 项目/线路卡片

- 有图项目使用左图右文卡片；无图项目使用紧凑文字卡片。
- 图片使用实景项目图，不在图片中写库存、状态或按钮文字。
- 项目名称最多两行；说明和名额状态保持信息层级。
- 选中态统一使用主题色体系；满员与截止状态使用中性灰或固定语义色。
- 项目不展示票价、退改、购票标签等本期无票预约信息。

### 6.7 表单控件

- 输入框、下拉框、日期控件、图片上传、单选和多选使用统一字段标题、辅助说明、圆角和聚焦态；同一页面不得混用裸文件框、文字链接和不同高度的选择控件。
- 单行输入、下拉选择和图片选择入口的操作高度统一为 44px；多行文本使用相同边框和圆角，最小高度 92px。
- 下拉选择使用整行可点击区域和右侧选择提示；图片上传使用“选择图片”入口并显示格式说明，已上传状态显示缩略图及移除操作。
- 活动 LOGO 与项目 LOGO 使用同一上传组件：正方形预览、建议尺寸说明、更换和删除操作；没有图片时使用主题色底＋名称首字作为管理端占位。
- 移动端优先使用选择控件替代手工输入；可排序列表使用三横线拖动手柄，并同时支持触摸与鼠标拖动。
- 必填标识使用 `status/danger`，错误说明紧邻对应字段。
- 姓名、手机号和身份证号为默认常用字段；自定义字段沿用同一表单框架。
- 多人模式控件属于业务组件，不因景区主题变化改变结构。

### 6.8 必读须知与特殊提示

- 白色圆角弹窗，标题居中，内容区域支持滚动。
- 倒计时确认按钮在主题色上显示倒计时文本。
- 水位限高等信息使用警告色和警告图标，不使用景区主题色冒充风险等级。

### 6.9 预约成功

- 成功图标使用 `status/success`，不使用景区主题色变量。
- 主按钮使用景区主题色；次按钮使用主题描边。
- 结果文字简短明确，预约编号需要突出但不夸大。

### 6.10 预约记录与详情

- 记录按日期或预约单分白色卡片展示，状态放在卡片右上角。
- “已约/报名”使用成功或主题强调，“已取消”使用中性灰。
- 修改使用主题浅色按钮；取消使用危险文字或中性次按钮，避免两个操作同等强调。
- 详情页使用信息分组卡片，底部放修改和取消操作。

### 7.1 页面

1. `00-封面与说明`
2. `01-设计变量`
3. `02-基础组件`

### 7.2 组件命名

使用“类别/组件/变体”命名，例如：

- `Button/Primary/Default`
- `Button/Primary/Disabled`
- `DateCell/Available/Selected`
- `SessionCard/Available/Default`
- `SessionCard/Full/Disabled`
- `ProjectCard/Image/Selected`
- `Form/Input/Error`
- `Dialog/Notice/Countdown`

### 7.3 组件变体属性

统一使用：

- `State`: Default / Selected / Disabled / Full / Closed / Error。
- `Size`: Small / Medium / Large。
- `Image`: On / Off。
- `Quota`: Visible / Hidden。
- `Theme`: 不作为组件变体；通过 Figma Variable Mode 切换。

### 7.4 必做主题检查画板

同一张“日期＋场次＋分类＋项目＋底部按钮”核心页面至少同时展示：

- 呀诺达绿色主题。
- 一套蓝色景区主题。
- 一套偏暖色景区主题。

三套画板共用同一批组件实例，只切换 Variable Mode，用于检查是否存在写死绿色、对比度不足或警告色混淆。

## 八、开发主题变量

开发侧建议由景区主题配置生成以下变量，页面和组件只使用变量：

```css
page {
  --brand-primary: #00B578;
  --brand-on-primary: #FFFFFF;
  --brand-primary-pressed: #009A66;
  --brand-primary-soft: #E8F8F2;
  --brand-primary-border: #80DABD;
  --brand-primary-disabled: #B7DDD0;

  --page-bg: #F5F6FB;

  --text-primary: #1F2329;
  --text-secondary: #646A73;
  --text-tertiary: #8F959E;
  --border-color: #E5E7EB;

  --status-success: #16B364;
  --status-warning: #F79009;
  --status-danger: #F04438;
  --status-info: #2E90FA;

```

代码中的 `#00B578` 仅作为可运行的初始示例，不代表已经确认的呀诺达正式主色。正式值从现有小程序的主按钮组件取色后替换。

主题配置应在进入预约模块时一次性注入页面根节点，不允许各页面分别请求或各自计算。分享链接切换景区上下文时，需要重新解析并注入对应景区主题。

## 九、图片与交付

- 金刚区图标参考现有规范：88×88px、PNG、小于 1KB；预约模块如使用公共功能图标，优先使用矢量组件而不是位图。
- 大图参考：750px 宽、高度自适应、PNG/WebP，目标小于 100KB。
- 功能图标优先 SVG 或字体/组件图标；实景和项目图片使用 WebP/PNG/JPEG。
- 不导出按钮、文字、状态标签等可由代码实现的位图。
- 每个页面交付默认态、选中态、禁用态、满员/截止态和错误态，不只交付一张正常截图。

## 十、第一版原型定稿顺序

1. 先完成“预约首页＋日期/场次/分类/项目选择”核心页。
2. 用绿色、蓝色、暖色三套主题验证换肤。
3. 校准字号、圆角、卡片密度、日期和场次状态。
4. 定稿后沉淀为 Figma 变量、组件和开发主题变量。
5. 再批量制作填写资料、须知、成功、记录和详情页面。
