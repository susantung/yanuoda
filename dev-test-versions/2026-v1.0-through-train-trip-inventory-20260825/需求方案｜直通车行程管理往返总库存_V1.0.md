# 直通车-行程管理增加往返总库存显示

版本：V1.0  
日期：2026-08-25  
适用端：全域后台  
功能位置：乘车预约管理 → 路线管理 → 对应线路 → 行程管理

## 1. 背景与问题

现有“库存配置”在新增和编辑时都展示“前往库存、返程库存”，但业务人员实际需要配置的是车辆总座位数。已有预约后，如果仍按剩余库存调整车辆，业务人员必须先查询已预约人数，再手工用车辆座位数减去已预约人数后填写，容易计算错误，也无法在后台直接判断当前车辆总座位数和已预约数。

本次将配置口径统一为“总库存”，后台自动根据小程序实际预约数计算剩余实际库存。

## 2. 页面范围

仅修改全域后台行程管理现有页面和现有“库存配置”弹窗：

1. 行程管理月历增加往返总库存显示。
2. 批量设置（新增）弹窗调整库存字段口径与名称。
3. 点击某日（编辑）弹窗展示总库存、已预约数和剩余实际库存。
4. 不改变司机姓名、司机电话、可预定日期、永久销售、删除选中日期及页面保存等现有功能。
5. 小程序端仍不展示总库存。

## 3. 核心口径

| 数据 | 定义 | 是否可编辑 |
| --- | --- | --- |
| 总前往库存 | 当日前往车辆可承载的总人数 | 新增、编辑可填写 |
| 前往已预约数 | 小程序端该日期前往方向的实际有效预约人数 | 否 |
| 前往剩余实际库存 | `总前往库存 - 前往已预约数` | 否，系统计算 |
| 总返程库存 | 当日返程车辆可承载的总人数 | 新增、编辑可填写 |
| 返程已预约数 | 小程序端该日期返程方向的实际有效预约人数 | 否 |
| 返程剩余实际库存 | `总返程库存 - 返程已预约数` | 否，系统计算 |

“已预约数”取小程序当前有效预约数据；取消、退款等是否释放库存，继续沿用现有预约库存规则，本次不改变。

## 4. 批量设置（新增）

1. 原“前往库存”改名为“总前往库存”。
2. 原“返程库存”改名为“总返程库存”。
3. 新增弹窗仅调整上述两个字段名称，不增加库存规则说明文字；原输入框提示保持不变。
4. 两个字段均必填，允许填写 `-1` 或 `0～999999` 的整数。
5. 新增时尚无预约：
   - 前往剩余实际库存 = 总前往库存。
   - 返程剩余实际库存 = 总返程库存。
6. 填写 `-1` 表示无限库存；保存时总库存按 `999999` 记录，后续编辑显示 `999999`。
7. 日期范围、永久销售、司机姓名、司机电话沿用现逻辑。

## 5. 单日编辑

点击月历中的已配置日期，打开现有“库存配置”弹窗：

1. 可预定日期只读，沿用现状。
2. “总前往库存”可编辑；其后展示“前往已预约数”和“前往剩余实际库存”，两者只读。
3. “总返程库存”可编辑；其后展示“返程已预约数”和“返程剩余实际库存”，两者只读。
4. 总库存调大或调小时，页面立即按当前已预约数预计算剩余实际库存。
5. 总库存不能小于对应方向的已预约数；否则字段下方提示并禁止确定。
6. 原数据为无限库存时，编辑弹窗总库存显示 `999999`，不再回显 `-1`。

示例：前往已预约 33 人，总前往库存由 40 调整为 20 时不可保存；调整为 35 时可保存，前往剩余实际库存为 2。

## 6. 行程管理月历

每个已配置日期保持现有信息结构，仅将两行库存文案调整为：

- `前往库存：当前实际剩余库存张/总前往库存张`，示例：`前往库存：4张/46张`。
- `返程库存：当前实际剩余库存张/总返程库存张`，示例：`返程库存：4张/46张`。
- 导游信息等现有内容和日历密度不变，不拆成四行展示。

无限库存按总库存 `999999` 展示。月历中的剩余库存仍为实时计算结果，不用于反向修改总库存。

## 7. 提交与并发校验

前端输入校验只能用于即时提示，最终以服务端提交校验为准：

1. 点击“确定”时，服务端重新查询该日期、该方向的最新有效预约数。
2. 校验 `新总库存 >= 最新已预约数`。
3. 前往、返程两个方向同时校验；任一方向不通过，整次提交不更新。
4. 校验和总库存更新需在同一事务/原子操作中完成，或使用版本号/CAS 防止校验后又产生新预约。
5. 并发导致失败时，返回最新已预约数；前端刷新只读数据并提示：`当前已预约数已更新，总库存不能小于已预约数，请调整后重试`。
6. 保存成功后：`剩余实际库存 = 新总库存 - 提交时最新已预约数`。

## 8. 数据兼容

1. 已有有限库存数据：继续读取原总库存字段；若历史页面未展示，则本次直接展示。
2. 已有无限库存数据：总库存统一按 `999999` 展示与参与计算。
3. 禁止通过“剩余库存 + 页面旧值”推算已预约数；已预约数必须取预约业务数据。
4. 前往和返程分别计算、分别展示，不能共用一个预约数或剩余数。

## 9. 验收标准

1. 批量新增填写总前往 40、总返程 40，保存后两方向总库存和剩余库存均为 40。
2. 批量新增填写 `-1`，保存后编辑回显总库存 `999999`。
3. 某日前往总库存 40、已预约 33，编辑显示剩余 7。
4. 上述日期将总前往库存改为 35，实时显示剩余 2，可保存。
5. 上述日期将总前往库存改为 32，提示不能小于已预约 33，不能保存。
6. 前往校验通过、返程校验失败时，前往和返程均不更新。
7. 编辑期间预约数从 33 增至 35，提交总库存 34 时，服务端拒绝并返回最新预约数 35。
8. 月历同一日期显示 `前往库存：剩余张数/总张数` 和 `返程库存：剩余张数/总张数`，不新增库存说明行。
9. 小程序端不恢复总库存展示。
