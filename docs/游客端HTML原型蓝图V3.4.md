# 游客端 HTML 原型蓝图 V3.4

> 原型目录：`outputs/product-preview/scenic-reservation/preview/`

## 一、页面范围与顺序

1. 活动详情与预约内容选择：活动、日期、场次、分类、项目。
2. 月历弹层、必读须知弹层。
3. 游客信息填写与提交。
4. 预约成功与提交异常。
5. 我的预约列表、预约详情。
6. 修改预约资料与实际参与人数、取消预约。

## 二、页面状态图

`活动详情 → 选择日期 →（命中特殊日期）必读须知 → 选择场次 → 选择分类 → 选择项目 → 填写资料 → 提交校验 → 预约成功 → 预约详情`

游客进入活动后默认选中当天，并立即展示当天全部场次；底部主操作统一使用“立即预约”。

补充分支：

- 日期：可选、特殊提示、无可预约场次、月历选择。
- 场次：可选、已满员、已截止、暂停预约。
- 项目：有图、无图、已满员、当前分类无可预约项目。
- 提交：处理中、库存变化、字段错误、结果不确定。
- 记录：全部、已约/报名、已取消、空状态。
- 详情：预约成功、已取消、活动已下架但历史记录可操作。
- 修改：资料正常保存、增加人数库存不足。
- 取消：允许取消、超过取消截止时间、二次确认、取消成功。

## 三、字段与操作白名单

### 预约选择

- 活动图片、活动名称、详情介绍、联系方式、我的预约。
- 日期、场次名称、开始/结束时间、剩余名额、场次状态。
- 分类名称、项目图片、项目名称、项目说明、项目剩余名额。
- 操作：查看月历、选择日期/场次/分类/项目、下一步。

### 游客资料

- 姓名、手机号、身份证号，以及用于示例的动态自定义填写项。
- 配置“多人/团体”字段时显示管理员自定义名称的人数控件；示例名为“实际参与人数”。最少和默认人数均为 1 人，表示启用本单实际参与人数填写，不强制一单至少两人。
- 原型提供单人统计/多人团队统计切换：单人统计不显示人数加减控件，一单固定 1 人；多人团队统计显示人数控件，按填写人数统计。
- 填写页预约摘要在配置项目时直接显示“分类”和“项目”。
- 操作：微信手机号加载、增减人数、确认预约。

### 预约记录

- 游客预约号、状态、活动、预约游玩日期、场次、项目、实际参与人数、提交时间。
- 操作：查看详情、修改资料和人数、取消预约。

## 四、样式契约

- 继承全域小程序：真实景区头图、白色圆角卡片、浅灰页面背景、轻描边和克制阴影。
- 逻辑基准宽 375px，覆盖 320/360/375/390/414px；使用 `rpx` 等比思路与安全区变量。
- 主体颜色全部来自主题变量；警告、错误、成功保持独立语义色。
- 绿色、蓝色、暖色三套主题仅替换品牌变量，不改变布局和业务状态色。
- 自定义导航避让微信胶囊；固定底栏计入 `safe-area-inset-bottom`。
- 不引入票价、购票校验、审核、候补、核销、通知等第一期外功能。

## 五、场次展示与后端逻辑衔接备注

- 场次按照开始时间升序展示。
- 当前时间之前或超过预约截止条件的场次显示“已截止”。
- 当前及后续已开放时段，根据真实库存显示“剩余 X 名”或“已满员”。
- 尚未达到展示条件的日期和场次不下发游客端，不显示“未开放”状态。
- 不单独设计“仅剩 X 名”的紧张状态，统一使用“剩余 X 名”。
- 上述状态最终由活动开放规则、预约截止规则和实时库存共同计算，页面不得通过固定序号判断。
- 排列样例：常规溪降为 10:00 首场，10:30—15:30 每小时一场；VIP 私家团每场上限 12 人，10:00—15:30 每 30 分钟一场。
- 场次库存支持限制人数和不限名额；不限名额时游客端显示“不限名额”，不显示虚构剩余数字。
- 项目三种库存范围均支持限制人数和不限名额；不限名额项目显示“不限名额”。
- 活动未添加项目时，游客端完全隐藏分类和项目模块，选择场次后即可进入游客资料填写，仅校验场次库存。
